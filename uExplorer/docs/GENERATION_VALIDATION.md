# Проверка генерации делегатов и new

## Правила восстановления

- `0x43` (`delegate_property`) — **вызов** делегата: ссылка на свойство,
  имя сигнатуры и аргументы до `EndFunctionParms`. Аргументы принадлежат узлу
  вызова, включая вложенные вызовы и вызовы через `Context`.
- `0x44` — имя обработчика либо `None`; `0x45` — присваивание делегата.
- Функция с флагом `0x100000` объявляется через `delegate`, а не `function`.
- Служебное свойство `__<имя>__Delegate` заменяется именем соответствующего
  делегата. Оно не печатается как отдельная `var`, только если подтверждены
  ссылка на delegate-функцию, общий владелец, точное имя и скалярная размерность.
  Нераспознанные DelegateProperty сохраняют диагностику `partial`.
- `new` содержит четыре выражения: Outer, имя, флаги, класс. Пропущенные
  аргументы (`Nothing`) отличаются от явного `None` и нуля. Вложенные выражения
  сохраняются; скобки защищают порядок вычислений. Не поддержанные компилятором
  пропуски внутри списка аргументов (например, `new(, "Name")`) сохраняют `partial`.
- Ошибка генерации не превращается в ошибку декодирования: для успешно
  прочитанной функции остаётся `decoded: true`, а `generated: false` сопровождается
  `stage: declaration/generate` и AST. Ошибки чтения имеют `stage: decode`.
  Замечания содержат `code`, `scope`, `message`.

## Автономные тесты

После сборки выполните `ctest --test-dir <build> -C Release --output-on-failure`.
Тест `generation` проверяет чтение аргументов, вложенные вызовы, PC, генерацию
делегата и `new`, отказ при некорректных метаданных и усечённых данных.
Профили декодера: 123/0, 123/37, 126/0, 133/40.

## Компилятор как независимый источник проверки

`tests/generation/*.uc` — собственные минимальные исходники, без клиентского кода.
`tests/compile_generation.py` копирует внешний комплект компилятора и launcher
в новый каталог **внутри uExplorer/local**, затем:

1. Компилирует исходные примеры.
2. Декомпилирует их новым ядром, требуя `recovered`.
3. Компилирует полученные исходники.
4. Сравнивает набор классов/функций, наследование, flags/native, размеры скриптов,
   PC и AST с символическими ссылками вместо индексов таблиц.

```powershell
python -B tests/compile_generation.py --compiler 'D:/compiler/System' `
  --launcher 'D:/toolchain/ucc64.exe' --library build-generation/Release/uexplorer_core.dll `
  --out local/generation/roundtrip
```

Используются правила из `int64/README.md` и изолированного запуска
`gameAddWebWithD3D9/tools/ue2/run_compile.py`: совместимый UCC/SDK, проверяемый
launcher, `-NoBind -Silent`, полный журнал и контроль кода завершения.
Их исходные каталоги не изменяются. У старого SDK не подтверждена поддержка
`var delegate<...>` и сравнения делегата с `None`; эти конструкции не выдаются
за проверенные компилятором. Проверка минимальных примеров не означает
совместимость этого SDK со всем кодом клиентов 133/40.

## Матрица внешних пакетов

`tests/audit_generation.py` обрабатывает Core, Engine, NWindow, Interface,
InterfaceClassic (если присутствует), в режимах auto и force-bytecode.
Зависимости разрешаются из каталога соответствующего пакета.

```powershell
python -B tests/audit_generation.py --library bin/uexplorer_core.dll `
  --profile 'ProfileA=D:/clients/profile-a/system' `
  --profile 'ProfileB=D:/clients/profile-b/system' `
  --profile 'ProfileC=D:/clients/profile-c/system' `
  --profile 'ProfileD=D:/clients/profile-d/system' `
  --profile 'ProfileE=D:/clients/profile-e/system' `
  --output local/generation/after.json --baseline local/generation/before.json
```

Снимок `before.json` получают старым ядром той же командой без `--baseline`.
Пути в примерах условные; замените их локальными каталогами. Метки ProfileA–E
обезличены: A–C используют формат 133/40, D–E — 123/37 для базовых пакетов
и 126/0 для Interface.u. Подробные отчёты и журналы остаются локальными.
Отчёт включает SHA-256 пакетов и DLL, structural audit, статусы классов,
функций и причины неполного восстановления. ScriptText проверяется по SHA-256
исходных байтов; отчёт не содержит полный клиентский исходный код.
Сравнение выявляет новые failed/partial, потери decoded/generated и изменения
ScriptText. Статус recovered сам по себе не доказывает семантическую эквивалентность.

## Результаты исходной проверки

Windows x64 Release, SHA-256 проверенного ядра:
`3ed15365e573518c1c4645a07c747eab4427aa2aafdad289467bfd305c51ff1d`.
Проверены 23 пакета в двух режимах старым и новым ядром. Структурных ошибок — 0,
регрессий статусов/decoded/generated/ScriptText — 0. Для 1347 классов старых
клиентов побайтовый ScriptText сохранён (сравнение SHA-256).

Результат принудительной декомпиляции интерфейсов:

|---|---|---:|---:|---:|
| ProfileA | Interface.u | 782 | 229 | 0 |
| ProfileA | InterfaceClassic.u | 817 | 252 | 0 |
| ProfileB | Interface.u | 794 | 224 | 0 |
| ProfileB | InterfaceClassic.u | 824 | 244 | 0 |
| ProfileC | Interface.u | 794 | 224 | 0 |
| ProfileC | InterfaceClassic.u | 824 | 244 | 0 |
| ProfileD | Interface.u | 244 | 1 | 0 |
| ProfileE | Interface.u | 257 | 2 | 0 |

Все классы этой таблицы имеют `recovered`, отказов экспорта нет. В auto-режиме
профили A–C дают тот же результат, D–E используют ScriptText.
В Core/Engine/NWindow остаются другие причины partial: Within, replication,
state/latent, iterator, PtrProperty, неизвестное преобразование и сложные defaults.
Их статусы не были скрыты или искусственно заменены на recovered.

Дополнительно прошли:

- CTest `package_tokens` и `generation`;
- компиляция → декомпиляция → компиляция восьми собственных функций, без ошибок
  и предупреждений; совпали flags/native, PC и AST с символическими ссылками;
  включая наследование, делегат с телом по умолчанию, enum/optional-параметры,
  вложенные вызовы, присваивание/сброс обработчика, варианты `new`;
- запуск настоящего portable `Start.cmd`, DLL/CLI/GUI, экспорт и локальные настройки.

Локальные подробные отчёты: `local/generation/before.json`, `after.json`,
`roundtrip-5/roundtrip.json` и журналы компиляции рядом. Клиентские пакеты
и результаты декомпиляции не включены в исходный состав проекта.
Полные интерфейсы современных клиентов не перекомпилировались и не проверялись
в игре: результат таблицы — проверка декодирования и генерации, не доказательство
семантической эквивалентности всех функций.
