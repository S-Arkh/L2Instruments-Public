# Руководство пользователя

## 1. Запуск

Основной запуск в подготовленном дереве: `uExplorer\run.cmd` относительно корня репозитория.
Python и PySide6 нужны даже при наличии готовой DLL. Подробности установки
отдельного Python: [сборка](BUILD_AND_TEST.md).

## 2. Просмотр пакета

1. Нажмите **Открыть каталог…** и выберите каталог с `.u`.
   Просматриваются файлы непосредственно этого каталога, без рекурсивного обхода.
2. В левой панели выберите пакет. В средней появятся его классы.
3. Выберите класс: справа появится текст, доступный только для чтения.
4. Поля над списками фильтруют файлы и классы без учёта регистра.
5. **Обновить пакет** перечитывает файл и зависимости после внешнего изменения.

Внизу находятся журнал и прогресс. Загрузка, предпросмотр и экспорт выполняются
в фоновом потоке. На время операции выбор пакета и класса заблокирован.
Предпросмотр и журнал используют светлый фон; подсветка рассчитана на него.
При ошибке журнал показывает пакет, выбранный класс и причину, затем traceback
для технической диагностики.

## 3. Зависимости

Для восстановления вызовов native-функций и типов нужны соответствующие этому
клиенту `Core.u`, `Engine.u`, `NWindow.u` и другие импортируемые пакеты.
Сначала программа ищет их рядом с выбранным `.u`, затем в каталогах,
добавленных кнопкой **Зависимости…**. При совпадении имени приоритет имеет
первый найденный каталог. Вложенные зависимости подгружаются автоматически.

Можно добавить несколько каталогов. Этот список действует в текущем сеансе;
после перезапуска его нужно задать снова. Сообщение `Missing dependency`
указывает, какого пакета не хватает. После добавления каталога выбранный пакет
перечитывается. Смешивание зависимостей разных клиентов может дать неверные типы
или конфликт native-индексов.

## 4. ScriptText и байткод

По умолчанию программа предпочитает сохранённый **ScriptText**, если в нём
найдена декларация нужного класса. Пустой/очищенный ScriptText заменяется
восстановлением из метаданных и байткода.

Флажок **Из байткода даже при наличии ScriptText** принудительно включает
декомпиляцию. Он действует и на предпросмотр, и на последующий экспорт.

Статусы:

| Статус | Значение |
|---|---|
| `source` | Извлечён сохранённый ScriptText |
| `recovered` | Код сгенерирован; генератор не сообщил неподдержанных конструкций |
| `partial` | Восстановление неполное; смотрите комментарии `INCOMPLETE` и отчёт |
| `failed` | Класс не удалось экспортировать; ошибка в отчёте |

`recovered` сам по себе не означает доказанную эквивалентность или успешную
компиляцию. Исходные комментарии, форматирование и прежняя структура циклов
при декомпиляции не восстанавливаются. Переходы могут быть представлены
`while (true)` / `switch (__RecoveredPC)` — это ожидаемый результат.

## 5. Экспорт

1. Нажмите **Каталог экспорта…**.
2. Для одного класса выберите его; для нескольких используйте Ctrl/Shift.
3. Нажмите **Экспорт выбранных** либо **Экспорт всего .u**.
   Экспорт всего пакета включает и классы, скрытые фильтром.
4. Если файлы уже существуют, подтвердите перезапись.
5. По окончании появятся количества `source/recovered/partial/failed` и путь
   к JSON-отчёту.

Структура назначения:

```text
<назначение>/
  Interface/
    Classes/
      LoginMenuWnd.uc
      <группа>/<класс>.uc
    export-report-<дата-время>.json
```

Каждая операция создаёт отдельный отчёт с SHA-256 пакета, ядра и выходных файлов,
режимом восстановления, диагностикой и результатами по классам. Храните его
вместе с экспортом: в нём находятся доступные AST/raw данные неполных функций.

**Отмена** срабатывает между классами. Уже записанные `.uc` остаются;
отчёт отмечает отмену. При закрытии окна во время работы программа просит
дождаться текущей операции, затем закрыть окно ещё раз.

## 6. Кодировки

- ScriptText сохраняется **побайтово**, включая его исходную кодировку.
- Переключатель `ANSI ScriptText` меняет только отображение ANSI-исходника:
  `cp1251`, `cp1252`, `latin1`, `cp949`.
- Сгенерированный код сохраняется в UTF-8. Исторические ANSI-байты строк
  байткода ядро представляет как Latin-1, поэтому не-ASCII текст может
  потребовать преобразования под кодовую страницу конкретного клиента.
- Старый UCC может требовать ANSI `.uc`. Для Gracia тест компиляции делает
  специальное преобразование UTF-8 → Latin-1 в отдельном тестовом каталоге;
  обычный экспорт этого не делает.

## 7. Решение проблем

| Сообщение/симптом | Действие |
|---|---|
| `C++ core not found` | Выполнить `build.ps1`; проверить `bin/uexplorer_core.dll` |
| Ошибка загрузки DLL / WinError 193 | Проверить одинаковую разрядность Python и DLL |
| `No module named PySide6` | Установить requirements в используемый Python |
| `Missing dependency` | Добавить каталог соответствующих `.u` |
| `Unknown/conflicting native` | Проверить зависимости и подробности отчёта |
| `Unsupported package version` / envelope | Этот профиль или оболочка не поддерживается |
| `partial` / `INCOMPLETE` | Использовать ScriptText, если доступен, либо доработать генератор по отчёту |
| Нечитаемый ANSI ScriptText | Переключить кодовую страницу предпросмотра |
| После изменения файла виден прежний код | Нажать «Обновить пакет» |

Каталог открытия и каталог экспорта запоминаются через QSettings.
Программа предназначена для классов/UnrealScript: экспорт текстур, звуков
и декомпиляция машинного кода DLL в эту реализацию не входят.
