# Просмотр ресурсов

Текущий этап разработки этого view-only просмотра завершён в границах preview
`.49`. Описанные ниже неподтверждённые формулы, состояния и эффекты остаются
ограничениями, а не обязательным продолжением текущего этапа. Структурное чтение
сохранённых ресурсов не требует воспроизводить итоговый игровой материал;
перенос или запекание его игрового вида — отдельная задача.

Portable-сборка переиспользует один каталог `local/portable` (параметр
`tools/package_windows.py --out`). Предыдущий результат заменяется при
пересборке; каталог распознаётся по `.uexplorer-package-output`.
Сохраняется только последняя portable-версия. Версия и ревизия остаются
в `BUILDINFO.json` и имени ZIP; отчёты проверок хранятся отдельно.

GUI открывает каталоги с `.u`, `.utx`, `.usx`, `.ukx`, `.uax` и `.unr`.
Над средней панелью находятся переключатели **Код, Текстуры, Звуки, Материалы,
Модели, Анимации, Прочее**. Недоступные для выбранного пакета режимы отключены.
Средняя панель содержит объекты выбранного типа; правая показывает результат
независимого C++ reader. Фильтр, выделение и прокрутка сохраняются для каждого
пакета и режима в пределах текущего запуска.

Ресурсные пакеты инвентаризируются без загрузки зависимостей. Для пакетов с кодом
сохраняется существующий просмотр и экспорт классов. Ошибка чтения классов
не скрывает доступную инвентаризацию ресурсов. Экспорт классов доступен только
в режиме «Код»; редактирование ресурсов не добавлено.

## Звуки

Требуется полный PySide6 6.8+ с QtMultimedia. В фиксированные входы будущей
portable-сборки добавлен PySide6-Addons 6.12.0.

- Воспроизведение / пауза, стоп с возвратом к началу, переход «Сначала».
- Шкала перемотки, текущее время / длительность, громкость, выключение звука,
  повтор выбранного звука.
- Обзор звуковой волны с переходом щелчком для поддерживаемых PCM WAV.
- Живой FFT-спектр (окно Hann, 1 024 отсчёта, −80…0 dBFS).
- Спектрограмма последних декодированных буферов; частота по вертикали,
  последовательность буферов по горизонтали. Это скользящая история, а не
  заранее вычисленная спектрограмма всего файла.

Анализируется первый канал, чтобы противофазные стереоканалы не гасили друг
друга. FFT доступен для декодированного Qt аудио, даже если обзор WAV недоступен.
Поддержка сжатых кодеков зависит от QtMultimedia/backend; ошибки отображаются
в плеере. При выборе звука воспроизведение не начинается автоматически.
Смена объекта, режима, каталога или закрытие окна освобождает звуковой буфер.

Аудиоданные передаются плееру в памяти: исходный пакет не изменяется, временный
звуковой файл не создаётся. Подготовка обзора выполняется в рабочем потоке.
Лимит предпросмотра — 64 МиБ на сериализованный объект и на аудиоданные.

## Текстуры

Графический просмотр поддерживает P8 с локальной палитрой, RGBA8 (BGRA в
хранилище), DXT1/3/5 и G16. Для G16 показывается старший байт как фиксированная
шкала серого без автоконтраста. Палитры UE2 читаются в порядке RGBA;
для `bMasked` индекс 0 отображается прозрачным, остальные alpha сохраняются.

- Масштабирование колесом и кнопками, перемещение мышью, 1:1 и «Вписать».
- Шахматный, чёрный и белый фон для проверки прозрачности.
- Выбор сериализованного mip-уровня и локальной грани Cubemap.
- Декодирование пикселей в рабочем потоке; QPixmap создаётся в GUI-потоке.

Лимит — 16 777 216 пикселей, сторона до 16 384 и 64 МиБ входных пиксельных
данных. Ошибка выбранного mip очищает изображение, сохраняя доступные
переключатели для выбора меньшего уровня или другой грани. Внешние ссылки на
палитры/грани и отсутствующие пиксельные данные показывают явную ошибку.
Процедурные текстуры не синтезируются. При переходе к другому объекту или
режиму изображение и данные освобождаются. Сохранения/редактирования нет.

Порядок каналов сверён с UEViewer `a0bfb468d42be831b126632fd8a0ae6b3614f981`
(`UnCore.h`, `UnTexture2.cpp`). Независимый Pillow 13.0.0 дал точное совпадение
RGBA для 43 реальных mip-изображений из пяти пакетов: DXT1 — 7, DXT3 — 20,
DXT5 — 12, RGBA8 — 4. Хеши исходных пакетов после проверки совпали.
Это проверка пиксельного декодирования, а не эквивалентности игрового рендеринга.

## Модели и анимации

Диагностический ортографический 3D-просмотр поддерживает StaticMesh, Polys,
поддерживаемый reader профиль Model и исходную геометрию SkeletalMesh.
Доступны вращение ЛКМ, перемещение ПКМ/средней кнопкой, масштаб колесом,
вписывание, виды спереди/сбоку/сверху, каркас и диагностическая заливка граней.
Для StaticMesh отдельно выбираются сериализованные треугольники коллизии;
для SkeletalMesh — опорная поза скелета.

Исходная геометрия показывается в координатах ресурса, без игровых
трансформаций объекта. Диагностическая заливка сортирует грани по
глубине в Qt QPainter, без z-buffer; пересечения и перекрытия могут
отображаться приблизительно. Каркас показывает все рёбра. Это средство
инспекции геометрии, а не замена игрового рендера или проверки коллизий.
Лимиты: 100 000 вершин, 50 000 граней, 150 000 рёбер. Невалидные индексы,
нечисловые координаты, пустые потоки и превышение лимитов дают явный отказ.

Для MeshAnimation добавлен **проигрыватель скелета**:

- последовательность, воспроизведение/пауза, стоп, перемотка и время;
- скорость 0,25× / 0,5× / 1× / 2×, повтор, вращение и масштаб;
- линейная интерполяция позиций и shortest-path SLERP вращений;
- шкала времени с учётом частоты кадров и MotionChunk.TrackTime.

### Просмотр Model

Для профиля `133/40` полный read-only запрос `model` читает сохранённую
структуру: BSP-данные, зоны, листья, секции, световые записи и буферы,
ссылки и конечные поля. Он возвращает `status: decoded` и
`reconstruction_supported: false`: это ограничение API просмотра, а не
утверждение об отдельном writer openUCC. GUI показывает геометрию без
материалов и предупреждает, что мировое размещение и игровая коллизия не
подтверждены. Неверные точки вне диапазонов узлов и неверные плоскости в hull,
на которые не ссылаются узлы, сохраняются и диагностируются; использование
этих записей игрой не установлено.

Для `127/39`, `128/39`, `130/40` и `132/40` тот же read-only запрос
принимает только наблюдавшийся вариант с пустыми дополнительными массивами и
пятью нулевыми конечными байтами. GUI указывает точный профиль и ограниченность
поддержки; ненаблюдавшиеся формы не принимаются.

Отдельный ограниченный `model_collision` возвращает начальную часть Model с BSP-точками,
узлами, поверхностями, списком вершин и hull-записями. Запрос требует пустых
неподтверждённых зон, листьев, источников света и render-массивов, а также ровно
пять нулевых байтов в конце. В этом частичном API они не читаются: ответ помечен
`status: partial`, `remaining_bytes: 5`, `reconstruction_supported: false`.
Ненулевой или отличающийся по длине
хвост, неверные индексы, используемые узлами, и другие неподдерживаемые данные
дают отказ. Неверные индексы точек в записях пула, которые не используются узлами,
перечисляются отдельно в `invalid_unused_vertices` (поле присутствует, когда
такие записи есть); это не доказывает их неиспользование игровым кодом.

GUI сначала использует полный reader; частичные операции остаются отдельными
ограниченными диагностическими запросами. Это локальные координаты ресурса, **не готовая
сцена**: преобразование владельца, полнота коллизий и игровое столкновение не
подтверждены.
Камера и показанные границы рассчитываются по точкам отображаемых граней
узлов, а не по всем сохранённым точкам и не по сохранённому Model box.
Остальные точки остаются в ответе API и исходном ресурсе; их возможное
использование игрой не установлено. Координаты всех сохранённых точек по-прежнему
проверяются на конечность, а неверные индексы отображаемых узлов отклоняются.
Если сохранённая ссылка ведёт на локальный `Polys`, кнопка **Открыть
сохранённые Polys** открывает его отдельно, только по нажатию. Это работает и
когда у Model нет отображаемых узлов. Polys не подменяет автоматически
геометрию Model и не подтверждает её совпадение или игровую коллизию.

Отдельный `model_level_geometry` читает ограниченный префикс Model уровня с
непустыми зонами, листьями и списком источников света. Он проверяет индексы,
используемые узлами, и отдельно сообщает неверные индексы в неиспользуемой
узлами части пула. Render-данные после объявленного числа секций **не читаются и не
проверяются**; ответ тоже частичный и не пригоден для реконструкции. Это не
проверка целостности всего объекта. В частичном ответе указывается размер
непрочитанной части и число неверных записей вне диапазонов узлов; это не
утверждение об их использовании игровым кодом.

На корейской карте `16_19` частичный reader и независимый полевой разбор
согласились на 160 brush-вариантах: 122 из них пустые, 38 содержат узлы. Для всех
десяти связанных с `BlockingVolume` Model 60 граней совпали по наборам
сохранённых вершин с соответствующими объектами Polys. Ответы Windows и Linux
совпали по хешу; входной пакет не изменён. Для крупного Model уровня отдельно
проверены 925 узлов и 4 244 используемых ссылок на вершины: все валидны, но
5 142 записи вне диапазонов узлов содержат неверный индекс. В том частичном
ответе 1 556 010 байтов render-данных не разобраны; полный API читает их отдельно.
Сопоставление используемых вершин с плоскостями
узлов дало максимальное отклонение 0,153; это не доказывает полное покрытие
выбранного участка или работу коллизий в игре.

В 62 ранее исследованных контейнерах полевой разбор и частичные ответы
Windows/Linux совпали для 1 457 Model. В 16 из них 64 неверных индекса
находятся только вне диапазонов узлов; ранее эти объекты отклонялись целиком.
В прежнем реальном окне один из таких Model показал 22 грани и предупреждение о двух
неиспользуемых узлами индексах. Этот частичный тест сам по себе не подтверждает
реконструкцию.
Для 301 сохранённой Model уровня на обеих платформах частичный C++ API согласовался
с отдельной диагностикой индексов: 1 475 649 различных записей используются
узлами, ещё 1 291 114 неверных записей лежат вне диапазонов узлов. В сумме
520 360 487 render-байтов API не читает. Это не полная проверка Model.
Отдельное сравнение сохранённых Model box на 19 579 связях с BlockingVolume
показало численное совпадение с пределами точек узлов у 19 566 Model; у двух
нет точек узлов, а у 11 некоторые такие точки находятся за сохранённой
границей. Все 11 входят в 71 различие Model/Polys, максимальное отклонение по
оси равно ровно 1/4096. Допуск и исправление границ не применялись; равенство
сохранённых чисел не доказывает мировое размещение или игровую коллизию.

### Сохранённые свойства BlockingVolume

В режиме **Прочее** для поддерживаемого `Engine.BlockingVolume` профиля `133/40`
показываются только сохранённый стек и распознанные tagged-свойства. Неизвестные
свойства явно помечены, их содержимое не копируется. Кнопка открывает связанную
локальную `Model` в режиме **Модели**; её геометрический просмотр остаётся в
координатах ресурса. Явно сохранённые `bDeleteMe=True` или
`bPendingDelete=True` показываются дополнительным предупреждением, которое не
утверждает текущее игровое состояние. Наследуемые defaults, мировое
преобразование, события и игровая коллизия этим не устанавливаются. Снимок не
засчитывается сравнением как полная реконструкция.
На 301 карте проверены 19 579 сохранённых связей с Model и Polys: у 19 508
совпали неупорядоченные наборы битов вершин непустых записей узлов и полигонов,
у 71 они различаются. Ещё три акторных экспорта строго отклонены по границам
PointRegion и не входят в сравнение. Совпадение наборов не проверяет обход или
вырожденность граней, размещение в мире и игровую коллизию.

На десяти объёмах карты `16_19` сохранённые поля проверены независимым разбором
и совпали между Windows и Linux. У `BlockingVolume43` явно сохранено
`bWorldGeometry=False`; в реальном окне проверены это значение и переход к
связанной `Model64` с шестью гранями. Исходный пакет не изменялся.

Поддерживаются полная упорядоченная иерархия до 512 костей, до миллиона
ключей, пустая либо единичная карта индексов и полные треки позиции/вращения.
Частичные иерархии, отсутствующие ключи, требующие опорной позы другого
ресурса, неверные времена и нулевые/вырожденные кватернионы явно отклоняются.
Небольшие отклонения длины кватерниона нормализуются для просмотра.
Камера использует постоянные консервативные границы выбранной последовательности.
Отдельный RootTrack, игровые события и скрипты не исполняются.
Автозапуска нет; смена объекта/режима/пакета останавливает таймер и освобождает
данные. Ошибка одной последовательности оставляет выбор остальных доступным.

Математика времени и соглашение осей сверены с закреплённым UEViewer.
На копиях пакетов PSA-экспорт независимо подтвердил 120 последовательностей,
140 355 отсчётов костей: максимум ошибки позиции 0,0001221, минимум абсолютного
скалярного произведения нормализованных вращений > 0,99999999999999.
Ещё 18 последовательностей отклонены из-за нулевого корневого кватерниона.
Геометрия 3 426 треугольников двух моделей совпала с ActorX-экспортом при
округлении координат до 0,0001 без учёта порядка вершин треугольника.
Эти проверки не доказывают skinning, игровые события или runtime-эквивалентность.
Реальный GUI проверен на статической и скелетной геометрии, опорном скелете,
воспроизведении анимации и восстановлении после отказа. Хеши исходников сохранены.

## VertMesh

В режиме **Модели** VertMesh открывает проигрыватель каркасной геометрии:
выбор последовательности, play/pause/stop, перемотка, скорость и повтор.
Кадры линейно интерполируются, границы камеры постоянны для последовательности.
Поддерживаются знаковые упакованные координаты 11/11/10 бит и float-координаты
с единичным преобразованием ресурса. Неединичные transforms пока явно
отклоняются. Материалы и события не исполняются; автозапуска нет.
Лимиты: 20 000 вершин, 50 000 треугольников, миллион вершинных отсчётов
выбранной последовательности. Подготовка выполняется в рабочем потоке.

Внешний экспорт UEViewer двух реальных моделей подтвердил 121 хранимый кадр,
15 878 wedge-отсчётов и 512 треугольников. Их выбранные последовательности
используют 120 кадров: все 15 660 отсчётов нового просмотрщика совпали с
внешними координатами. Один оставшийся кадр не входит в диапазон первой
последовательности и не добавляется автоматически. Проверен реальный Windows
GUI: геометрия, перемотка, запуск таймера и освобождение при очистке.

Для отдельной float-модели проверены 26 кадров / 62 036 отсчётов. UEViewer
при экспорте в `.3d` теряет дробную часть и упаковывает координаты в 11/11/10:
такое преобразование совпало для всех отсчётов. Новый просмотрщик сохраняет
исходные float-координаты; их восстановление из нормализованной геометрии
проверено отдельно. Это различие уровней проверки не скрывается за утверждением
точного совпадения float-геометрии с потерявшим точность внешним экспортом.
Windows GUI на этой модели также проверен.

Проверка корпуса: 407 VertMesh в шести пакетах (405 float, 2 packed), все с
единичным преобразованием. Подготовка и выборка начала, интерполяции, конца
и повтора прошли для 405/407 последовательностей. Один отказ связан с 10 584
вершинами при лимите 10 000; второй — с объявленными 106 кадрами при 96
хранимых. Диапазон не обрезается автоматически. Это проверка работоспособности
подготовки/выборки, а не независимое сравнение всех кадров корпуса.
Хеши шести исходных пакетов сохранены.

После этой проверки лимит вершин поднят до 20 000. Модель с 10 584 вершинами
проверена в Windows: подготовка около 2,53 с, перемотка с перерисовкой около
0,104 с на кадр на проверенной машине; координаты занимают 5 588 352 байта.
Отказ по лимиту для неё снят. Результат 405/407 выше относится к прежнему лимиту.

Несоответствие 106/96 независимо подтверждено экспортом UEViewer: `.uc`
содержит `NUMFRAMES=106`, а `.3d` хранит 96 кадров. Десять отсутствующих кадров
не восстанавливаются из воздуха. Исходная последовательность остаётся ошибочной,
но пункт **«Сохранённые кадры (диагностика, 30 кадров/с)»** позволяет просмотреть
все 96 реально сохранённых кадров. Диагностическая частота — настройка просмотра,
не исправление метаданных или файлов.

## Материалы и текстурированный 3D

Режим **Материалы** показывает граф ресурсов, декодированные параметры и исходные
поля, ошибки разрешения и ссылки. Двойной щелчок по ссылке выбирает узел графа;
**«Открыть выбранный ресурс»** переходит к объекту и соответствующему режиму,
в том числе в другом пакете. Текстурные узлы имеют миниатюры. Циклы не обходятся
бесконечно: лимиты графа — 128 узлов и 64 МиБ сериализованных данных.
Поиск импортов использует каталог пакета, заданные зависимости и соседние
ресурсные каталоги клиента; неоднозначные совпадения не выбираются автоматически.

У StaticMesh и SkeletalMesh в списке источников доступен пункт
**«Материалы и текстуры (диагностика)»**. Используются индексы материалов, UV и
разрешённые ссылки. OpenGL рисует ортографическую геометрию с depth buffer,
повторением UV и прозрачностью; при недоступном контексте явно включается Qt
raster с сортировкой граней без z-buffer. Сложные пересекающиеся прозрачные
поверхности всё ещё зависят от порядка отрисовки.

Это диагностический просмотр, не реализация всех игровых шейдеров: Texture и
ConstantColor отображаются непосредственно; у Shader показывается Diffuse,
у обёрток — связанный Material. Невоспроизведённые эффекты отмечаются в панели,
неразрешённые материалы остаются нейтральными гранями с пояснением.
Лимит декодированных текстур — 64 МиБ, выбранные mip не крупнее 512 при наличии.

### Смешивание и прозрачность — следующий этап после preview .6

OpenGL применяет семь подтверждённых режимов FinalBlend: overwrite, modulate
(`2·src·dst`), alpha, translucent, darken, brighten и invisible; Shader использует
соответствующие OutputBlending. Наружный FinalBlend переопределяет состояние
внутреннего Shader. Применяются AlphaTest/AlphaRef, ZWrite/ZTest, TwoSided и
текстурные UClampMode/VClampMode. Неподтверждённые режимы, включая
AlphaModulate и специальные L2-варианты, отклоняются с пояснением.
Непрозрачные грани рисуются перед прозрачными; взаимопересекающаяся
прозрачность всё ещё ограничена сортировкой по средней глубине.

Shader.Opacity использует **alpha**, а не яркость отдельной карты. Поддержаны
общий подтверждённый UV-поток, одинаковые размеры выбранных mip и адресация; константа
1×1 распространяется на вторую карту. Разные размеры, неподдержанные UV-обёртки
или адресация отклоняются, без скрытого пересэмплирования. Обход ограничен
64 узлами с обнаружением циклов; общая текстура двух ветвей не считается циклом.

Формулы framebuffer и порядок enum сопоставлены с публичными
`UnRenderer.cpp`
и `UnMaterial2.h`.
Это совместимость с проверенным диагностическим путём, не доказательство
полной семантики рендера клиента. В частности, пороги обычных Texture
с bMasked/bAlphaTexture соответствуют этому пути UEViewer.

Независимый GPU smoke `tests/material_gpu_smoke.py` проверяет итоговые RGB
по формулам, alpha-порог, culling, ZWrite/ZTest и clamp/repeat.
Проверен на Windows OpenGL 4.6; 77 GUI/декодерных тестов прошли.
На двух реальных пакетах подготовлены 9 из 11 Shader: один отказ связан с
отсутствующим внешним пакетом, другой — с неподдержанной UV-обёрткой Opacity.
MainWindow-проверка с реальным текстурированным mesh/skinning прошла.

Qt raster явно помечен как fallback **без framebuffer-эффектов, culling,
clamp и depth buffer**. Для GPU используется непрозрачный framebuffer с
сохранением alpha=1: alpha текстуры участвует в смешивании, а Qt не
переинтерпретирует straight RGB как premultiplied.

### UV-модификатор над Shader: только Diffuse

Для ограниченных форм `TexPanner`, `TexOscillator` и `TexRotator → Shader`
доступен помеченный частичный просмотр прямой Diffuse Texture на UV0. Проверяются
сохранённый shader, связь и фактическая идентичность Diffuse и её sampler;
короткое имя sampler допускается только при уникальности объекта в пакете.
`Opacity` допускается лишь при ссылке на ту же Texture. Прочие карты и игровое
освещение не вычисляются; это не воспроизведение полного Shader. Для одного
распознанного многопроходного варианта проверяется только первый diffuse-проход:
другие проходы и их sampler не вычисляются, их состояния не подтверждены.
Environment mapping также не вычисляется, даже если он указан в пропущенной карте.

Время Panner и Oscillator диагностическое, а не игровые часы. Неоднозначные
Roll и stretch-repeat дополнительно помечаются как приблизительные модели.
При неизвестных размерах pivot или случайном состоянии Oscillator, а также
для Rotator используется только полная сохранённая planar UV-матрица:
события, случайное состояние и анимация не восстанавливаются. Все эти
частичные поверхности и снимки запрещены как точные входы композиции материалов.

Для ограниченного `TexRotator → Shader → TexPanner → Texture` также доступен
статический diffuse-only снимок. Проверяются реальные ссылки, первый sampler,
его сохранённый порядок и shader; затем две полные planar-матрицы умножаются
в этом порядке с округлением результата до float32. Остальные карты не
вычисляются. Матрицы могли быть сохранены в разные моменты; синхронность и
анимация не восстанавливаются, точная композиция материалов запрещена.
Для одного реального материала две клиентские копии имеют один и тот же хеш
пакета; независимый Windows/Linux расчёт и MainWindow/GPU совпали на 554 гранях.

Для одного сложного вложенного `Shader → Combiner` с состоянием triggered
можно отдельно показать **только sampler 0** и композицию трёх его сохранённых
planar UV-матриц. Это не итоговый Diffuse и не результат материала: другие
ветви, Shader/Combiner, отдельная opacity и последовательность кадров Texture
не воспроизводятся, используется состояние исходной Texture вместо Shader.
Матрицы не доказаны одновременными, игровые события и время не восстанавливаются;
использовать этот снимок как точный вход композиции запрещено. В четырёх
клиентских деревьях независимый Windows/Linux расчёт совпал на 554 гранях;
это две пары хешей основного пакета и зависимости, а не четыре независимых графа.

В заранее подготовленной выборке четырёх клиентских деревьев Windows и Linux
одинаково подготовили 77 из 81 наблюдения как частичный Diffuse: это 40
различных пар «хеш пакета, экспорт», включая 14 наблюдений со статическими
снимками. Для остальных четырёх наблюдений доступны только описанные выше
изолированные sampler 0; результат их Diffuse и всего материала остаётся
неподдержанным. Хеши 43 прочитанных пакетов не изменились.
В MainWindow/GPU с реальной моделью на 554 грани проверены 15 наблюдений,
включая сохранённые снимки, отдельное предупреждение
о пропущенном EnvTex и два дерева с многопроходным примером одного хеша пакета.
Это не проверка игровых часов, состояний проходов или runtime-эквивалентности.

### Противоречие UV2 и сохранённого shader

Некоторые прямые `TexCoordSource → Texture` записывают `SourceChannel=2` и
`TexCoordSource=2`, но их сохранённый shader выбирает `tex0`. Для строго
распознанных односамплерных shader и проверенной ссылки на Texture GUI показывает
**диагностический UV0** и предупреждает о противоречии. Это не утверждение,
какой поток выбрала бы игра: сохранённый shader может не отражать runtime.
Непроецируемые координаты, sampler и фактически разрешённая Texture проверяются;
если UV0 у модели отсутствует или повреждён, материал не отображается.
Приближённый fallback нельзя использовать как точный вход композиции материалов.
Поддержан также один ограниченный двухсамплерный Combiner, описанный ниже;
другие вложенные Combiner и нераспознанные конфликты остаются неподдержанными.

На Windows и Linux одинаково подготовлены 86 наблюдений в трёх клиентских
деревьях: 32, 32 и 22; это 54 различных сочетания хеша пакета и экспорта, а
не 86 независимых материалов. Исходные файлы не изменились. В настоящем
MainWindow на двух версиях и модели с 554 гранями проверены выбранный UV0,
видимое предупреждение и GPU. Это не проверка игрового выбора.

### Сохранённые цвета StaticMesh

Для наблюдавшегося пустого `VertexColor` доступен отдельный **диагностический**
просмотр сохранённого цветового потока StaticMesh. UE2 `FRawColorStream`
содержит `FColor`, записанный в порядке RGBA: это описано в
`UnMesh2.h`
и `UnCore.h`.
GPU интерполирует сохранённые цвета; Qt raster показывает средний цвет грани.
Это не восстановление игрового vertex diffuse или освещения, отдельный
сохранённый alpha-поток не применяется, композиция материалов отключена.
UV-поток для этого просмотра не нужен; отсутствующие/повреждённые цвета
отключают только соответствующий материал. SkeletalMesh не подменяется
цветами из другого источника.

Один реальный `VertexColor` и сохранённые цвета mesh с 998 вершинами и
554 гранями проверены независимо на Windows и Linux. Настоящий MainWindow/GPU
показал те же цвета и предупреждение; исходные пакеты не изменились. Это не
подтверждение игрового освещения.

### Два sampler с независимыми UV-преобразованиями

Для строго распознанного сохранённого shader `Combiner` с умножением двух
текстур и alpha из первой ветви GPU отдельно применяет каждую сохранённую
цепочку UV-модификаторов и фильтрует её текстуру перед умножением. Допускаются
подтверждённые `TexPanner`, `TexScaler`, `TexOscillator` и `TexRotator` до
прямой Texture, с проверкой полного порядка, каждого sampler suffix, shader
и реальных идентичностей пакета и объекта. Неподтверждённые UV-снимки и
приближённые ветви не допускаются.

В StaticMesh ветви могут использовать разные потоки UV0–UV7, если сохранённые
shader и `TexCoordSource` каждого звена согласованы. Для каждого sampler
проверяются индекс и используемые координаты своего потока; отсутствующий или
повреждённый поток отключает этот материал, без подстановки UV0. В SkeletalMesh
доступен только UV0. Управление временем диагностическое, не игровые часы.
Для skinning можно связать его с временем клипа; Qt raster показывает только
первую ветвь. Игровое освещение, `mFactor` и полная эквивалентность рендера
не подтверждены.

Одна реальная цепочка с `TexPanner` и `TexOscillator → TexPanner`, включая
внешний конфликт UV2/UV0, проверена в трёх клиентских деревьях: два различных
хеша пакета. Независимый расчёт обеих ветвей совпал на Windows и Linux в пяти
диагностических моментах. На двух версиях в MainWindow/GPU сверены координаты
554 граней, предупреждение и перемотка; исходные пакеты не изменились.
Разные каналы UV0/UV1 дополнительно проверены в MainWindow/GPU на реальном
mesh с 554 гранями, но с **синтетическим материалом**; UV7 и повреждённые
потоки проверены синтетически. Реальный материал с разными каналами в этом
тесте не подтверждён.

Для одного проверенного варианта `TexRotator → Combiner` с прямой Texture
и ConstantColor доступен **статический снимок сохранённой UV-матрицы** над
уже вычисленной mip-сеткой. Shader, sampler, порядок и идентичности обоих
операндов проверяются; размер pivot и игровое время не угадываются. Снимок
нельзя использовать как точный вход композиции. Windows/Linux согласились
на двух наблюдениях с одним и тем же хешем пакета; реальный MainWindow/GPU
проверен на 554 гранях с видимым предупреждением.

### Panner над двухтекстурным Combiner

Для трёх строго распознанных вариантов `TexPanner → Combiner` с двумя прямыми
Texture проверяются сохранённые shader, ссылки и порядок sampler. GPU
фильтрует выбранный сохранённый mip каждой Texture отдельно и смешивает
полученные значения RGB и alpha; текстуры могут иметь разные размеры и режимы
адресации. К обеим применяется общий диагностический UV0 и время просмотра,
которое не является игровыми часами. Qt raster показывает только Material1.
Игровая анимация кадров Texture, освещение и `mFactor` не воспроизводятся;
точная игровая картинка и runtime-эквивалентность не утверждаются. Весь этот
preview помечен приблизительным и не допускается как точный вход композиции.

В подготовленной выборке четырёх клиентских деревьев Windows и Linux одинаково
подготовили 8 из 15 наблюдений как описанное GPU-смешивание: это 5 различных
пар «хеш пакета, экспорт». Хеши 17 прочитанных пакетов совпали до и после проверок и
между системами. На четырёх реальных случаях независимый расчёт отдельно
фильтрованных GPU-пикселей совпал в двух режимах framebuffer. В MainWindow/GPU
сверены координаты 554 граней для пяти наблюдений, предупреждения и перемотка.
Это проверка диагностического просмотра, не игровых состояний.

Для остальных семи наблюдений вложенного Combiner теперь доступен только
**изолированный sampler 0**: один выбранный сохранённый mip и произведение
трёх сохранённых planar UV-матриц. Ссылки, путь первого sampler, порядок и его
сохранённый shader проверяются; другие ветви и их alpha не вычисляются, вместо
состояния Combiner используется состояние Texture. Это не результат diffuse
или всего материала. Матрицы не доказаны одновременными, события triggered,
анимация кадров Texture и игровое время не восстанавливаются; снимок нельзя
использовать как точный вход композиции. Семь наблюдений представляют четыре
различные пары хешей основного пакета и зависимости. Независимый Windows/Linux
расчёт и MainWindow/GPU совпали для 554 граней каждого наблюдения; восемь
прочитанных источников не изменились.

### Изолированный sampler Rotator над вложенными Combiner

Для одного строго распознанного графа `TexRotator → Combiner` доступен
**только отдельный sampler 0**: проверяются сохранённый путь через три
Combiner, идентичность Texture, suffix первого sampler, его shader-префикс
и четыре полные planar-матрицы на пути `TexRotator → TexRotator →
TexOscillator → TexScaler`. Показан один сохранённый mip с произведением
этих матриц в проверенном диагностическом порядке и состоянием Texture вместо
Combiner. Остальные ветви, их alpha и итоговый Diffuse или материал не
вычисляются. Матрицы могут относиться к разным моментам; игровые события,
анимация и синхронизация не подтверждены. Приблизительный снимок не допускается
как точный вход композиции.

Windows/Linux сверили четыре наблюдения из двух различных пар «хеш пакета,
экспорт»: независимый расчёт матриц и BC3 совпал, как и UV 554 граней каждого
наблюдения; три прочитанных источника не изменились. Независимые BC3/bilinear
GPU-пиксели совпали в 24 случаях двух framebuffer-режимов; MainWindow/GPU
проверен на всех четырёх наблюдениях. У их Texture сохранённой `AnimNext`
ссылки не найдено. Переключение сохранённого кадра для этого вида снимка
дополнительно проверено **синтетической цепочкой**, не игровой анимацией.

### Сохранённые кадры Texture в сложных материалах

В текстурном просмотре модели для описанных выше изолированных sampler
`Shader/Combiner` и `TexRotator → Combiner`, проверенного двухтекстурного
`TexPanner → Combiner` и описанного ниже alpha-modulate Combiner можно вручную
выбрать **один sampler одного слота** и перейти по сохранённым ссылкам
`Texture.AnimNext`. Остальные sampler и слоты остаются на исходных кадрах.
Допускается шаг 0–31; проверяются класс и разрешённая идентичность каждого
объекта, отсутствие цикла, а также одинаковый исходный размер и однозначный
сохранённый mip выбранного размера. Бюджет чтения цепочки ограничен 64 МиБ.
При конце цепочки, цикле, неподдерживаемом кадре или ошибке перехода просмотр
останавливается, а GUI оставляет предыдущий кадр и показывает предупреждение.
Ни повтор, ни недостающий кадр не выдумываются.

Кадры можно переключать вручную или проигрывать с пользовательской
диагностической частотой 0,5–12 кадров/с (по умолчанию 4). Ожидание чтения
может замедлять воспроизведение; оно не повторяется автоматически. Значения
игровых FPS, `AnimCurrent`, события и синхронизация с UV не восстанавливаются.
При загрузке кадра UV-время приостанавливается и сохраняет выбранное значение.
Адресация и render-state текущего preview сохраняются, декодирование использует
свойства выбранной Texture. Это не подтверждение итогового материала или
игрового поведения; приблизительный результат по-прежнему не допускается как
точный вход композиции.

Независимые Windows/Linux проверки охватили пять наблюдений — пять различных
пар «хеш пакета, экспорт» — и 16 выбранных кадров, включая межпакетные ссылки
и отказ после конца цепочки. Выборки пикселей BC1/BC3 совпали с отдельным
блочным декодером; семь прочитанных пакетов не изменились. Настоящий
MainWindow/GPU проверен на трёх реальных вариантах и 554 гранях, включая
сохранение UV-времени, видимые предупреждения и остановку проигрывания.

### Ограниченный Combiner с alpha-modulate

Для одной распознанной формы сохранённого shader операции 7 разрешены две
различные прямые Texture, если `Mask` фактически указывает на `Material1`,
а сохранённые sampler и полное выражение совпадают с проверенным профилем.
GPU отдельно фильтрует оба выбранных сохранённых mip и показывает
`Material2.rgb × Material1.alpha`, с alpha из `Material1`. Это **приблизительный
диагностический результат**, не итоговый игровой материал: сохранённый shader
также содержит `mFactor` и vertex diffuse, которые не вычисляются. Qt raster
показывает только Material1. Другие варианты операции 7, масок, alpha и shader
не угадываются; приблизительную поверхность нельзя использовать как точный
вход композиции. Доступный `AnimNext` второго sampler можно просматривать
описанным выше способом, без утверждений об игровых часах.

На двух клиентских версиях с различными хешами пакета независимый Windows/Linux
разбор сверил входы, сохранённый следующий кадр, выборки BC1/BC2 и UV 554
граней. Отдельный GPU-пиксельный расчёт совпал для 24 случаев двух кадров и
двух режимов framebuffer; в реальном MainWindow/GPU проверены обе версии и
смена кадра. Пять прочитанных источников не изменились. Это не проверка
`mFactor`, освещения или игровой эквивалентности.

### Сохранённые UV-цепочки

Для цепочки из 2–32 плоских UV-модификаторов с `TexPannerTriggered`,
`TexOscillatorTriggered` или jitter у `TexOscillator` доступен статический
диагностический просмотр композиции сохранённых матриц. Требуются прямой
Texture, UV0, распознанный shader каждого звена, проверенные связи и порядок
каждого sampler suffix, а также полная ограниченная planar-матрица каждого
матричного звена. Проверка shader не означает его исполнения.

Матрицы перемножаются в сохранённом порядке с округлением результата каждого
шага до float32. Они не обязательно относятся к одному игровому моменту.
Предупреждение видно в GUI, UV-анимация и использование такого снимка как
точного входа композиции материалов отключены. Если цепочку подтвердить нельзя,
сохраняется доступный помеченный fallback или показывается отказ.

Для одной цепочки `TexOscillatorTriggered → TexRotator → Texture` независимое
перемножение сохранённых полей совпало на Windows и Linux в четырёх клиентских
деревьях; это два различных хеша пакета, а не четыре независимых материала.
В настоящем MainWindow на двух версиях и модели с 554 гранями проверены все
координаты, видимое предупреждение, отсутствие UV-контролов и GPU. Исходные
файлы не изменялись. Время, события и игровое состояние этим не подтверждены.

### Preview .27: диагностические UV-модели и сохранённое состояние

Для движущегося `TexOscillator` stretch-repeat, неоднозначного Roll у
`TexPanner` и части неподтверждённых вариантов точности и времени у
`TexRotator` добавлены **приблизительные диагностические модели**. При
просмотре показывается предупреждение; игровое время и точная траектория не
утверждаются. Приблизительные поверхности, в том числе во вложенных
UV-цепочках и на UV1, не допускаются к композиции материалов как поверхность
с подтверждёнными координатами. Для остальных случаев прежние проверки
сохранены.

Для прямых `TexOscillator` с jitter, `TexOscillatorTriggered` и
`TexPannerTriggered` доступен статический просмотр сохранённой матрицы, если
подтверждены UV0, shader, единственный sampler, его связь с Texture и полная
ограниченная planar-матрица. Короткое имя sampler допускается только при
уникальности Texture в пакете. Время сохранённого состояния неизвестно;
случайные переходы, события и игровое воспроизведение не моделируются.
Анимационные UV-контролы для такого снимка не включаются, композиция с точными
UV запрещена. Неподтверждённые цепочки и повреждённые матрицы не становятся
снимками; прежний явно помеченный fallback или отказ сохраняется.

Проверка сохранённых данных не равна проверке игрового поведения:

- Для stretch-repeat четыре отдельно проверенные компоненты согласуются с
  моделью при трёх выведенных временах и 6 или 29 panner-контролях. Две полные
  матрицы прямых Texture совпали на разных версиях корейского и японского
  пакетов. Другая точность угла даёт отличия на иных временах; у одного
  дополнительного образца проверен только масштаб, не pivot.
- Для приблизительного Roll два проверенных сохранённых состояния совпали,
  два не совпали. Все четыре остаются приблизительным просмотром; несовпадения
  не засчитываются как подтверждения.
- Для неоднозначных Rotator совпали восемь сохранённых матриц в четырёх
  клиентских деревьях, но использованы только два различных хеша пакета.
  При других временах возможные правила округления расходятся.
- У 11 записей jitter/triggered из четырёх клиентов координатные компоненты
  снимка совпали с независимым разбором сохранённых полей. Один пакет с
  PannerTriggered отсутствовал в дереве Gracia и не засчитан.
- В настоящем MainWindow на модели с 554 гранями проверены реальные repeat,
  Roll и Rotator с перемоткой, а также три вида статического снимка; GPU
  использовался, исходные хеши не изменились. Это не измеренные игровые часы.

### Preview .26: источники UV и стационарные граничные случаи

`TexCoordSource` выбирает поток UV0–UV7 при согласованных `SourceChannel`,
`TexCoordSource` и строго распознанном сохранённом shader. Отсутствующий
`SourceChannel` допускается только для подтверждённого shader потока UV0.
Поддержан один sampler с выражением `texN` или `mul(m0,float3(texN.xy,1.f))`;
сохранённый shader не исполняется. Короткое имя Texture допускается лишь при
однозначности в таблице пакета. Поддержана и цепочка до прямой Texture с одним
источником координат, если порядок и каждый sampler suffix подтверждены.
Источник координат в наблюдаемых suffix не является матричным модификатором;
для остальных звеньев ненулевого канала требуется `TCS_NoChange`.
У сохранённого дочернего shader ниже источника проверяется собственный UV0,
тогда как внешний shader подтверждает итоговый выбранный канал.
В .26 несогласованные, проецированные, многократные и неизвестные источники
отклонялись; текущий ограниченный конфликт UV2/UV0 описан выше.
В найденных материалах High Five `SourceChannel=2` сочетается с сохранённым
shader `tex0`; эти случаи не приравниваются к проверенному UV2.
В StaticMesh проверяются индекс потока и координаты каждой используемой вершины;
отсутствующий, неполный или повреждённый поток отключает только соответствующий
материал, без подстановки UV0. Повреждённый UV0 не отключает материал с
исправным UV1; грани без доступного материала остаются нейтральными.
Для SkeletalMesh пока доступен только UV0.
Композиция на сетке mip разрешена лишь для одинаковых источников и преобразований;
ограниченное GPU-смешивание разных потоков описано выше.

Связь `SourceChannel` с индексом потока подтверждена публичным описанием UE2 и
статическим чтением `PostEditChange` доступного High Five Engine; DLL не
запускалась. Две реальные StaticMesh с 554 и 525 гранями проверены на обоих
потоках: все координаты углов совпали с соответствующими сериализованными
данными, причём у первой модели UV0 и UV1 отличаются у всех 998 вершин.
Обёртка `TexCoordSource` в этой проверке **синтетическая**. GPU-проверка на
синтетических данных различает выбор UV0/UV1 и проверяет анимацию и перемотку
вложенной цепочки; отдельный синтетический тест проверяет отказ при отсутствии
UV2. Дополнительно подготовлены семь реальных записей из четырёх пакетов Кореи,
High Five и Gracia, включая `TexRotator → TexCoordSource` и обратный порядок
`TexCoordSource → TexScaler`; матрица последнего совпала с сохранённой.
В настоящем MainWindow на
реальной модели и реальных материалах переключение UV0/UV1 дало разные
GPU-снимки, вращение и перемотка прошли; хеши источников сохранены. Время
вращения диагностическое, не измеренные игровые часы. Эти проверки не доказывают
игровой runtime или покрытие всех реальных материалов.

При проверке .26 14 ранее неразрешённых записей Rotator как **полных
материалов** четыре подготовлены: два объекта в Корее и их дубликаты в Японии.
Тогда остальные десять отклонены из-за цепочек через Shader/Combiner или
неподтверждённого листа; текущие частичные preview описаны выше.
Это проверка подготовки поверхностей, а не пересчёт прежней классификации
компонентов и не доказательство игровых часов.
В одном из них сохранённый shader `Rotator → Combiner(Texture, ConstantColor)`
отличается от дочернего только координатами sampler; исходная Texture имеет
1024×1024, выбранный mip — 512×512. Собственные размеры Combiner и ConstantColor
для pivot не подтверждены, поэтому полная анимация не включена; статический
снимок сохранённой матрицы описан выше.

Для единственного ранее непрочитанного пакета Gracia профиля `118/11` отдельно
сравнены таблицы независимым Python-разбором и reader на временной копии с
синтетически изменённым только полем профиля на `118/0`. Все 11 записей
совпали: семь Texture, три Palette и один Package; целевых UV-модификаторов в
таблице нет. Оригинал и reader сохранили хеши. Тела объектов не проверялись,
производственный reader исходный профиль по-прежнему не поддерживает.

Ненулевой Roll также допускается при строго нулевой скорости Panner: смещение
не зависит от разницы таблиц направлений. Stretch-repeat с ненулевой амплитудой
допускается дополнительно только при одновременно нулевых скорости и фазе:
обе рассматриваемые формулы дают неизменный единичный масштаб. Проверены
синтетические граничные значения, включая субнормальные ненулевые параметры;
такие стационарные случаи не были найдены в прежней четырёхклиентской выборке.
Движущийся stretch-repeat, jitter, triggered и остальные неоднозначные варианты
Roll/Rotator по-прежнему не объявлены точными. Нулевой амплитуды jitter
недостаточно: в реальном объекте при нулевой амплитуде сохранено ненулевое
`CurrentUJitter`, а момент следующего обновления зависит от состояния.

Дополнительная проверка пикселей не устранила четыре оставшихся прямых
маршрута Combiner: обе diffuse-зависимые маски имеют ненулевые значения, а
для операции 7 встречаются ненулевые альфа и цвет. Это не позволяет исключить
вход `diffuse` или неизвестный `mFactor` как константный ноль. В .26 `VertexColor`
сообщал об отсутствии подтверждённых входов vertex diffuse/освещения; текущий
просмотр сохранённого цветового потока описан выше. Environment mapping и полная
семантика источников координат также остаются открытыми.

Для `TexEnvMap` профиля `123/35` открыто **структурное чтение параметров**, не
вычисление environment mapping. Все 665 записей из 16 пакетов Gracia полностью
совпали с независимым полевым разбором на Windows и Linux, включая границы,
теги и старую таблицу стадий; полные ответы двух платформ совпали по хешам.
Исходные хеши сохранены; другие legacy-профили этого класса остаются отклонены.
Реальный объект открылся в MainWindow только для просмотра, с доступными
параметрами и ссылками. Реконструкция этих объектов не заявляется.

Windows-набор из 178 тестов прошёл с одним пропуском directory-symlink из-за
прав; этот же тест прошёл в Linux. Отдельно прошли синтетический GPU smoke,
проверка публичного ресурсного API и прежний набор реальных MainWindow-сценариев.
CTest прошёл 14/14 на Windows и Linux. Синтетические тесты запуска проверяют
наличие `QAudioBufferOutput` и выбор Python.

### Preview .25: проверка следующих вариантов UV

TexOscillator stretch-repeat допускается только при нулевой амплитуде
соответствующей оси: масштаб этой оси неизменен. Обычные pan/stretch и pivot
другой оси сохраняются. Ненулевая амплитуда остаётся отклонённой как при
подготовке поверхности, так и при непосредственном вычислении времени.

Статический анализ одного native-пути показал для stretch-repeat множитель
π/2, а не π. В реальных данных найдены ненулевые амплитуды. Две гипотезы
округления совпали с сохранённым repeat-масштабом при выведенных временах,
но расходятся на других временах; одно совпадение полной матрицы различает
гипотезы только по другой оси. Pivot ещё одного образца отдельно не подтверждён.
Поэтому эти совпадения не считаются подтверждением движущейся траектории.

TexPanner теперь допускает Roll с нулевым табличным индексом, а также
ненулевой индекс, если две наблюдаемые угловые таблицы дают побитно
одинаковый XY и скорость по модулю является степенью двойки от 1 до 8192.
Последнее исключает промежуточное округление произведения скорости и времени
в пределах диагностического диапазона. Для трёх объектов из двух различных
пакетов совпали полные сохранённые матрицы при двух временах, каждое из
которых согласуется с семью panner-контролями, включая разные скорости.
Дубликаты пакетов между клиентами не считаются независимыми объектами.
Шесть экземпляров этих трёх объектов подготовлены из реальных ресурсов и
прошли возврат к абсолютному времени; хеши зависимостей не изменились.
Остальные варианты Roll, включая неоднозначную точность, отклоняются.

Для постоянного TexRotator дополнительно разрешена однозначно определённая
double-angle таблица, если каждая ненулевая компонента угловой скорости по
модулю — целая степень двойки. Умножение такой скорости на float32-время точно в
диагностическом диапазоне; в исследованном native-пути преобразование
произведения в целое использует усечение. Это действует и для planar, и для
пространственной матрицы; колебательный double-angle и остальные скорости
по-прежнему отклоняются.
Четыре реальных компонента из разных пакетов совпали целиком при разных
восстановленных временах, согласованных с 3–7 panner-контролями. Все четыре
поверхности подготовлены и прошли перемотку; зависимости не изменились.
Для других скоростей совпадение сохранённой матрицы не выбирает порядок
округления: найдены времена, на которых возможные траектории различаются.

Для пространственного Rotator выбор таблицы теперь проверяет все табличные
кандидаты Pitch/Yaw/Roll, а не окрестность результата обратной тригонометрии.
Полная матрица сравнивается точно; при неоднозначности, near-gimbal или более
256 комбинаций для одного Pitch результат отклоняется. На 104 различных
сохранённых матрицах наборы таблиц совпали с прежней проверкой. В итоговой
синтетической проверке 385 из 400 примеров нашли исходную таблицу и совпали
с прототипом, а 15 отклонены по бюджету; отказы не считаются совпадениями.
Это не проверка игрового runtime.

Read-only инвентаризация всех `.utx` в Textures/SysTextures четырёх
авторизованных клиентов охватила 2708 файлов и выявила 3179 записей целевых
классов, включая дубликаты между клиентами. Один пакет не прочитан из-за
неподдерживаемой версии; его нельзя засчитывать как проверенный. Хеши входов
и reader до и после совпали.
Это инвентаризация, а не проверка всех траекторий или равенства игровому runtime.
Она ограничена классами Panner, Oscillator, Rotator и их найденными triggered
вариантами; другие модификаторы, UV1 и environment mapping в этот подсчёт не входят.
Отдельная стратифицированная проверка подготовки взяла до пяти записей на
категорию в каждом клиенте: из 190 записей 89 подготовлены, 79 явно отклонены,
22 показаны только как отмеченный fallback. Это не случайная выборка и не
оценка общего покрытия; записи между клиентами могут дублироваться.
Хеши прочитанных пакетов и зависимостей сохранены.
Дополнительно классифицированы сохранённые компоненты Rotator, включая pivot
при разрешённом исходном размере Texture: подготовлены 153/177, 154/182,
12/28 и 5/19 соответственно для Кореи, Японии, High Five и Gracia. Всего 68
компонентов отклонены, в том числе из-за double-angle, неоднозначной или
нераспознанной таблицы; для 14 не удалось подтвердить прямую Texture и размер.
Это проверка компонентов, не подготовка полного материала; дубликаты между
клиентами сохранены в числах.
Инвентаризация содержит 10 записей jitter и 31 triggered с дубликатами.
Для jitter статически обнаружен вызов генератора случайных чисел;
OscillatorTriggered зависит от состояния и часов. В одном native-пути
PannerTriggered делегирует GetMatrix базовому Panner, но это не подтверждает
изменение параметров событиями. Эти эффекты не угадываются, а fallback явно
помечается и не используется как точный UV для композиции.

Windows-набор: 155 тестов, один тест создания directory symlink пропущен
из-за разрешений; этот же тест прошёл в Linux. GPU и реальные MainWindow
сценарии статической и скелетной модели прошли на итоговом коде, включая
Panner из четырёх клиентов, double-angle Rotator и межпакетную ссылку.
Повторные проверки 31/31 расширенных и 55/55 ранее обследованных цепочек

### Preview .13: planar TexPanner

TexPanner с прямой Texture теперь допускает ненулевой Yaw при нулевых

Перемотка, скорость, повтор и стоп применяются одновременно к позе и UV.
При повторе UV-время начинается заново вместе с клипом; это выбранный
диагностический режим, не утверждение о поведении игровых часов.

Отключение переключателя возвращает UV к t=0, сохраняя текущую позу.
Для клипов длиннее 3600 с связь явно отключена с сообщением о пределе,
а геометрическая анимация остаётся доступной. Каждый кадр вычисляется
от исходных UV, без накопления сдвига и изменения подготовленного материала.
Скрытие, загрузка, смена последовательности и очистка останавливают таймер.

102 Windows-теста прошли: совместная перемотка/повтор/стоп, скорость,
переключение UV без изменения позы, неизменность входов и ограничение времени.
GPU smoke проверяет реальный AnimationView с красным/зелёным mip: конец
клипа сдвигает UV, повтор и отключение связи возвращают исходный цвет.
Поддержка самих TexPanner остаётся ограниченной нулевым направлением
и прямой Texture; другие UV-модификаторы этим этапом не включены.
Реальный MainWindow-сценарий с session-only назначением TexPanner на
скелетную модель проверяет перемотку, отключение/включение связи, стоп,
проигрывание и остановку при переходе к ресурсу. Исходные хеши сохранены.

### Preview .11: диагностическое время TexPanner

Для TexPanner с нулевыми Pitch/Yaw/Roll и прямым Texture добавлен первый
анимированный UV-маршрут. В просмотре модели доступны время UV 0–3600 с
и пуск/пауза. Начальное время — 0; это отдельная диагностическая шкала,
не синхронизация с игровыми часами. В skinning-представлении пока используется
начальный UV-снимок t=0, без второго независимого проигрывателя материалов.

Read-only анализ native-пути установил: направление берётся из Rotator,
смещение проходит через float32-фазу `PanRate × time / 1024`, затем
`(phase - floor(phase)) × 1024`. Поэтому отрицательная скорость и переходы
через границу не заменяются обычным остатком по 1. DLL не загружаются
и не исполняются просмотрщиком для вычисления UV.

Два значения времени, выведенные из сохранённых опорных матриц, точно
предсказывают ещё семь матриц разных скоростей, включая отрицательные.
Это проверка согласованности кэша, **не измерение реального игрового времени**.
Все девять реальных TexPanner подготовлены с сохранением исходных texel;
хеши проверенных пакетов не изменились.
Ненулевые направления, Triggered/Oscillator/Rotator, вложенный TexPanner и
TexScaler поверх движущихся UV остаются неподдержанными. При композиции
непостоянных карт скорости должны совпадать.

99 Windows-тестов и GPU-переход красный → зелёный → красный по явному времени
прошли. Реальный MainWindow проверяет назначение TexPanner, изменение времени,
проигрывание и остановку при переходе к другому ресурсу. Исходные UV и texel
не переписываются: каждый момент вычисляется от исходных координат.
Таймер также останавливается при загрузке, скрытии и очистке просмотра.

Дополнительная выборка Japan/High Five/Gracia дала 27 Combiner операций 4–7
без ошибок чтения и с сохранением исходных хешей. Прямой поддерживаемый
маршрут найден только для уже известного masked add; расширение 4/5/7
по одной формуле без доказательства порядка входов не включено.

### Preview .10: подтверждённый masked add и общий сохранённый mip

Операция Combiner 6 теперь принимается для узкого подтверждённого случая:
два прямых Texture в установленном порядке, AlphaOperation=Add, без явного
Mask, InvertMask, Modulate2X/4X и UseDiffuseAlpha. Сохранённый shader должен
точно соответствовать распознанной последовательности. Формула RGB:
`Material2.rgb + Material2.a × Material1.rgb`, alpha — сумма alpha входов.
Результат округляется до 8 бит и ограничивается диапазоном канала.
Неизвестный порядок/выражение не заменяется общей формулой UE2.

Для Combiner с прямыми Texture разных preview-размеров выбирается самый
крупный общий **существующий** mip, не крупнее уже выбранных уровней.
Уровень 1×1 не используется как способ устранить несовместимость карт.
Заново декодируются исходные байты этого mip; пересэмплирования нет.
Выбранный размер явно указан в диагностике. Требования совпадения
адресации и UV сохраняются, вложенные модификаторы этим путём не обходятся.
Это намеренное снижение детализации диагностического просмотра, не
эквивалентность игровому выбору LOD или per-fragment арифметике.

В ограниченной выборке десяти пакетов найдены 20 объектов операций 4–7:
3 subtract, 4 masked blend, 12 masked add, 1 alpha modulation.
В production включён только описанный direct-texture masked-add маршрут.
На реальном межпакетном Combiner с mip 0 первого и mip 1 второго входа
совпали все **65 536 RGBA texel** отдельного расчёта; исходные хеши сохранены.
94 Windows-теста и GPU masked-add smoke прошли. Операции 4, 5, 7, остальные
маршруты 6 и анимированные UV остаются открытыми; `mFactor` не угадан.
Реальное назначение masked-add материала в слот модели через MainWindow
и GPU-отображение проверены вместе с навигацией и skinning; хеши сохранены.

### Preview .9: неявный alpha и смещения TexScaler

Для отсутствующего Combiner.Mask добавлен узкий распознаватель сохранённого
shader-текста: прямые Texture/ConstantColor, копирование alpha и известный
завершающий проход vertex lighting. Текст не исполняется. Неизвестные
выражения, преобразованное семплирование, неоднозначные пути и InvertMask
без явной маски отклоняются. Общего значения alpha по умолчанию нет.

TexScaler поддерживает смещения для прямого Texture:
`(u/UScale + UOffset/original_width, v/VScale + VOffset/original_height)`.
Используются размеры исходного mip 0, даже если просмотр выбрал меньший mip.
Коэффициенты округляются до float32. Ненулевое смещение без прямого Texture,
различные UV-смещения входов и вложенный неединичный масштаб поверх уже
сдвинутых UV остаются неподдержанными.

Проверены 90 Windows-тестов и GPU smoke с implicit_mask/uv_offset.
На 19 реальных TexScaler смещения и обратные масштабы точно совпали
с сохранёнными float32-матрицами, включая отрицательные смещения.
Три реальных Combiner с константным результатом совпали по RGBA; четвёртый
имеет подтверждённый alpha-маршрут, но отклоняется из-за разных mip-размеров.
Неизвестный маршрут FadeColor остаётся отказом. Это диагностическая
поддержка ограниченного набора материалов, не полный игровой рендер.
Назначение реальных implicit-alpha Combiner и TexScaler со смещением в слот
модели через MainWindow, GPU-отображение, навигация и skinning проверены;
хеши исходных пакетов сохранены.

### Combiner и статический TexScaler — preview .8

Combiner поддерживает RGB-операции выбора Material1/Material2, умножения и
сложения (enum 0–3). При умножении Modulate4X имеет приоритет над Modulate2X;
сумма и произведение ограничиваются диапазоном канала. Alpha поддерживает
Mask, Multiply, Add и выбор Material1/Material2; InvertMask инвертирует alpha
маски. Неиспользуемые входы не читаются, но обязательные пустые ссылки
отклоняются: отсутствующая маска не заменяется выдуманным значением.

Это **вычисление на сетке mip с округлением до 8 бит**, затем фильтрация
полученной текстуры. Умножение после bilinear-фильтрации в игровом shader
может дать другой результат между центрами texel. Точность арифметики
texel не объявляется точностью игрового рендера. Карты должны иметь
одинаковые размеры, адресацию и UV-масштаб; константа 1×1 распространяется
на вторую карту. Несовместимые входы не пересэмплируются скрыто.

Важное отличие L2: enum **7** обозначает `CO_Modulate_With_Mask_Alpha`,
тогда как общее описание UE2 называет его `CO_Use_Color_From_Mask`.
Операции 4–7 и UseDiffuseAlpha пока явно отклоняются. Описания математики
сопоставлены с [Legacy Combiner](https://beyondunrealwiki.github.io/pages/combiner.html);
противоречивые описания subtract/masked RGB не использованы как доказательство.

TexScaler применяет `(u/UScale, v/VScale)` для непроецированного UV0,
пока только при нулевых UOffset/VOffset. Смещения и другие источники
координат явно отклоняются. Масштабирование выполняется на углах граней
до raster/OpenGL, также для skinning; данные пакета не изменяются.
Произведение вложенных масштабов и итоговые UV ограничены для просмотра;
нулевые/нечисловые масштабы отклоняются. Сохранённые матрицы реальных
TexScaler использованы для проверки обратного масштаба, не как замена
неустановленной временной семантики TexPanner/TexOscillator.

Обход material-графа ограничен 32 уровнями, 64 посещениями и 64 МиБ
сериализованных данных; циклы и экспоненциально разветвляющиеся ссылки
завершаются явным отказом. Автопоиск дополнен SysTextures. Неоднозначные
совпадения между соседними ресурсными каталогами отклоняются; текущий
каталог и явно заданные зависимости сохраняют приоритет.

83 GUI/декодерных теста прошли. GPU smoke дополнен арифметикой Combiner
и полным путём TexScaler → mesh UV → пиксель framebuffer. Проверены реальные
MainWindow-переходы, подстановка материалов и skinning с сохранением
исходных хешей.
Дополнительно в сохранённом shader-тексте 20 реальных Combiner подтверждены
выражения RGB multiply/add и коэффициенты 1×/2×/4×; для семи из них совпала
формула alpha multiply. Это проверка отдельных выражений, не исполнение
полного shader с его преобразованиями, освещением и временем.
В ограниченной выборке 47 реальных Combiner/TexScaler подготовлены 11 объектов:
10 TexScaler с точным совпадением float32-коэффициентов сохранённых матриц
и один Combiner. Для Combiner все **32 768 RGBA texel** совпали с отдельным
расчётом по сохранённой формуле shader. Остальные 36 объектов остались
явно отклонёнными (пустой Mask, неподдержанные UV/операции/offset или разные
mip-размеры). Это выборочная проверка, не полное покрытие пакетов.

Если mesh хранит пустые слоты, а игра назначает материалы через actor, их можно
выбрать явно: открыть текстуру/материал, нажать **«Материал → слот модели…»**,
указать слот и заново открыть текстурный просмотр модели. **«Сброс материалов
модели»** удаляет эти назначения. Они действуют только в текущем процессе
просмотрщика; клиентские пакеты не записываются.

## Skinning

Для SkeletalMesh пункт **«Анимация модели (skinning)»** открывает связанный
MeshAnimation и проигрывает деформируемую геометрию. Есть выбор последовательности,
пауза/стоп, перемотка, скорость, повтор и каркас/грани/текстуры. Треки связываются
по уникальным именам костей, композиция использует иерархию mesh; дополнительные
animation-only кости не деформируют модель. Позиции линейно интерполируются,
вращения используют SLERP. Веса с суммой в пределах 0,98–1,02 нормализуются;
невалидные индексы, отсутствующие треки/веса и неоднозначные имена отклоняются.
Лимиты — 20 000 точек и 500 000 влияний. Применяются inverse bind pose и
линейное смешивание. Просмотр идёт в mesh-local координатах; размещение объекта,
игровые события, физика и дополнительные игровые модификаторы не исполняются.
Камера фиксируется по исходной геометрии и диапазону перемещения корня.

Независимая матричная проверка PSK/PSA: для первой модели 201 кадр /
363 810 отсчётов совпали с ошибкой не более 1,71e-13. Для второй проверены
830 733 отсчёта: максимум ошибки 0,063722 объясняется округлением внешних весов
(максимум изменения веса 0,001961); проверена соответствующая граница ошибки.
Шесть вершин с изменёнными внешним экспортом наборами влияний исключены
из этого сравнения, а не объявлены равными. Реальный Windows GUI проверен
на 7 958 вершинах / 98 костях, в том числе с явными подстановками текстур.

## Сравнение оригинала и реконструкции

В ресурсном режиме кнопка **«Сравнить ресурсы…»** предлагает выбрать второй
пакет. Проверяется весь набор ресурсных экспортов, независимо от текущего
фильтра объектов. Идентичность — точные путь объекта и класс; номера экспортов
могут различаться. Сопоставляются `flags`, `outer` и декодированные поля C++ API.
Перемещаемые native-offsets и числовые слоты разрешённых ссылок исключаются,
но пути/классы ссылок и точные битовые слова сохраняются в сравнении.

Отчёт показывает совпадения, отличия, отсутствующие объекты и непроверенные
ресурсы. Выбор строки показывает до 32 различий с путями полей; длинные
значения сокращаются только при отображении. Неизвестный профиль, отсутствие
reader или превышение лимита не считаются совпадением. Лимиты GUI-сравнения:
5 000 экспортов на пакет и 8 МиБ сериализованных данных на объект.
Отмена между операциями оставляет явно частичный отчёт.

Уровень доказательства — структурное совпадение ресурсов. Экспорты кода и
метаданных (классы, функции, свойства и т. д.) исключены, их суммарное число
указано отдельно; байтовое равенство файлов и поведение в игре
этот отчёт не устанавливает. Входные пакеты открываются только для чтения.
Кнопка **«К выбранному объекту»** возвращает просмотр ресурса.

Реальный GUI независимо сравнил оригинал с обычной реконструкцией и вариантом
с переставленными таблицами: по 50/50 объектов. Хеши обоих входов сохранены.

При закрытии uExplorer во время фоновой операции запрашивается отмена после
текущего класса/операции; окно закрывается автоматически после завершения
рабочего потока. Принудительного прерывания записи экспортируемого класса нет.
Это поведение GUI не является проверкой Graceful Exit игрового клиента.

## Остальные ресурсы

Пока показываются структурированные поля и ссылки. Большие массивы и двоичные
данные сокращаются **только в текстовом представлении**; сравнение и C++ API
этим ограничением не изменяются. Для неизвестных классов доступна запись
инвентаризации, для неподдерживаемых профилей — причина отказа reader.

Полная игровая семантика материалов, дополнительные варианты skinning
и расширение форматов VertMesh остаются отдельными этапами.
