# uExplorer

Просмотр пакетов Unreal Engine 2 / Lineage II, извлечение сохранённых исходников,
восстановление UnrealScript и структурное чтение ресурсов. Ядро и CLI — C++17,
интерфейс — Python/PySide6. Сборка Visual Studio 2022 x64 проверена.

Запуск и реализованные функции в Windows проверены; результаты работы с
целевыми игровыми пакетами подтверждены в исходном проекте. Scryde не входит
в подтверждённые интеграции.

## Возможности

- **Код:** просмотр классов `.u`, побайтовое извлечение сохранённого ScriptText
  либо восстановление по метаданным и байткоду; экспорт выбранных или всех
  классов пакета с JSON-отчётом `source/recovered/partial/failed`.
- **Ресурсы:** режимы для `.utx`, `.usx`, `.ukx`, `.uax`, `.unr` и ресурсных
  экспортов `.u`: свойства, ссылки, текстуры и mip, локальные грани Cubemap,
  материалы и их графы, звук и геометрия.
- **Просмотр и воспроизведение:** аудиоплеер с волной, FFT и спектрограммой;
  диагностический 3D, опорный скелет, скелетные и вершинные анимации,
  ограниченные текстурированный просмотр и skinning.
- **Сравнение и API:** сравнение доступных структурных полей двух пакетов;
  read-only C++/JSON API и CLI для инвентаризации и поддержанных ресурсных тел.

Ресурсный GUI предназначен **только для просмотра и сравнения**. Экспорт `.uc`
относится к режиму кода: общего экспорта текстур/звуков или готовых материалов
в этой реализации нет. Частичные материалы и UV-снимки помечены; полное игровое
освещение, анимация материалов, мировые коллизии и runtime-эквивалентность не
заявляются. Подробности и ограничения — [просмотр ресурсов](docs/RESOURCE_GUI.md).

## Структурный API и проверенный охват

Для инвентаризации ресурсных экспортов и импортов без загрузки зависимостей
доступна JSON-операция [`resource_inventory`](docs/RESOURCE_INVENTORY.md).

Для структурного чтения поддержанных форм доступны API-операции `static_mesh`, `material`,
`texture`, `palette`, `skeletal_mesh`, `vert_mesh`, `mesh_animation`, `animation_notify`,
`sound`, `model`, `polys`, `karma_props`, `resource_group` и ограниченный
`blocking_volume`. Для подтверждённых форм они возвращают доступные поля,
точные биты и разрешённые ссылки с проверкой границ; частичный разбор явно
помечается и не считается полной реконструкцией. Поддержанные профили и
контракты описаны в [ресурсном API](docs/RESOURCE_INVENTORY.md).
Текущий этап разработки uExplorer завершён в границах preview `.49`.
Полное игровое отображение, синхронизация UV и перенос готовых материалов
не подтверждены и не требуются для структурного чтения сохранённых данных.
Для `Model 133/40` полный read-only API сохраняет в ответе BSP-данные, render-
секции, световые записи и ссылки. Мировое размещение и игровая коллизия им не
устанавливаются; ресурсный writer находится отдельно в openUCC.
Для `127/39`, `128/39`, `130/40` и `132/40` подтверждён только наблюдаемый
вариант Model с пустыми дополнительными массивами и пятью нулевыми конечными
байтами. Другие формы просматриваются с предупреждением: при подходящих границах
показывается предположительный разбор, иначе — ограниченный фрагмент исходных
байтов. Ни тот ни другой не объявляется проверенной реконструкцией.

Отдельный ограниченный `blocking_volume` показывает сохранённые поля и связь с
Model для проверенного профиля 133/40. Это не полная реконструкция объёма и не
проверка мировых преобразований или игровой коллизии.

`resource_batch` читает 1–256 выбранных объектов за одну загрузку пакета,
сохраняет порядок и возвращает ошибку целиком при отказе любого селектора.
Windows/Linux-выборки совпали по 166 ответам анимаций/звуков/материалов и
38 ответам расширенных StaticMesh/Polys/KMeshProps. Структурные пересборки
openUCC независимо сравнены через API uExplorer для **1 183/1 184 контейнеров
и 234 612 экспортов**: StaticMeshes — 333/334 и 24 051 экспорт, текстуры —
683/683 и 35 663, анимации/звуки — 167/167 и 174 898. В том числе 62 и
последующие 11 контейнеров прошли обычную и переставленную реконструкцию на
Windows и Linux. Оставшийся контейнер имеет некорректные исходные wire-индексы.
Структурное сравнение не устанавливает игровую эквивалентность.

CLI принимает один JSON-запрос через stdin. Например, после сборки из каталога
`uExplorer` в PowerShell, с путём к собственному пакету:

```powershell
'{"operation":"resource_inventory","path":"C:/resources/Example.utx"}' | .\bin\uexplorer_cli.exe
```

Инвентаризация читает таблицы пакета и сама по себе не проверяет native-тела
ресурсов. Форматы запросов и границы конкретных операций —
в [описании API](docs/RESOURCE_INVENTORY.md).

## Быстрый запуск

Для автономной Windows x64-сборки со встроенными Python/Qt см.
[portable-сборку](docs/PORTABLE_BUILD.md). В готовом ZIP запускайте `Start.cmd`;
настройки хранятся рядом в `data/settings.ini`.

Из чистого клона сначала установите зависимости и соберите ядро по
[общей инструкции](../docs/BUILD.md#interface-editor-и-uexplorer-x64).
Затем запустите **`uExplorer\run.cmd`**. DLL и CLI создаются в `bin`;
готовые файлы не включены в Git. Скрипт также поддерживает portable runtime редактора.

`run.cmd` автоматически проверяет окружения в следующем порядке:
1. собственный `uExplorer/runtime`;
2. `uExplorer/.venv`;
3. `interface_editor/.venv`;
4. portable runtime `interface_editor/dist/windows/runtime` с его `packages`;
5. `python` из PATH.

Выбирается первый Python 3.10+ с PySide6 6.8+, в котором загружаются QtCore,
QtGui, QtWidgets и QtMultimedia с QAudioBufferOutput. Непригодные окружения пропускаются. Если подходящего нет,
показываются команды создания `.venv` и установки `requirements.txt`.
Зависимости автоматически не устанавливаются. Разрядность Python по-прежнему
должна совпадать с ядром DLL.

Проверить выбор без открытия окна:

```powershell
.\run.cmd -CheckRuntime
```

Явный параметр `-Python` тоже проверяется, но при ошибке не заменяется другим
интерпретатором. `run.cmd` передаёт параметры в `run.ps1` и возвращает код завершения.

Для отдельного Python (3.10+; разрядность должна совпадать с DLL):

```powershell
python -m pip install -r requirements.txt
.\run.ps1 -Python 'C:\Python312\python.exe'
```

Откройте каталог с пакетами → выберите пакет слева → тип объектов и объект
посередине → просмотрите результат справа. Для экспорта классов выберите режим
«Код», укажите каталог экспорта и нажмите «Экспорт выбранных» или
«Экспорт всего .u».

## Сборка

Нужны Visual Studio 2022 с компонентом **Desktop development with C++**,
Windows SDK, CMake 3.24+ и Python с установленным `nlohmann_json` в PATH.

```powershell
.\build.ps1
```

Создаёт `build-x64\uExplorer.sln`, собирает Release и устанавливает DLL/CLI
в `bin`. Solution можно открыть и собирать непосредственно в VS2022.

## Поддержка и ограничения

- Среди подтверждённых кодовых профилей пакетов: `123/0`, `123/37`, `126/0`,
  `133/40`; для ресурсов поддержаны дополнительные наблюдённые профили.
  Для исследованных Essence/Кореи/Японии добавлены INT64, сортировка массивов
  и метаданные делегатов; [проверки и ограничения](docs/PACKAGE_133_40.md).
- Оболочки: plain, `Lineage2Ver111`, `GamekitData111` (XOR `0xAC`), а также
  `Lineage2Ver121` с ключом из ASCII-имени файла; правила имён вне ASCII
  не подтверждены.
- ScriptText извлекается с сохранением исходных байтов.
- При отсутствии пригодного ScriptText работает декомпилятор; сложные функции
  могут содержать диспетчер `__RecoveredPC`.
- `partial` означает неполное восстановление; подробности и доступный AST/raw
  находятся в JSON-отчёте. В частности, неподтверждённые формы DelegateProperty, часть defaults, replication
  и state/latent-конструкций требуют доработки.
- Native-функции разрешаются по метаданным зависимостей; машинный код DLL
  не декомпилируется.

Проверено: Gracia — экспорт и повторная компиляция 239 классов, сравнение
3259 функций и 20009 CFG-блоков, метаданных свойств, enum и наследования.
Это проверка конкретного набора, а не гарантия компиляции любого `.u`.
