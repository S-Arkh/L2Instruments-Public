# L2Instruments

Набор инструментов для Lineage II / Unreal Engine 2: редактор интерфейса,
просмотр и восстановление UnrealScript и ресурсов, расширения компилятора и
клиентского native API, встроенный браузер и генератор тем. Компоненты можно
использовать отдельно; игровые файлы и SDK пользователь предоставляет сам.

## С чего начать

| Задача | Инструмент |
|---|---|
| Просмотреть пакет, исходники, текстуры, звуки, модели и анимации | [uExplorer](uExplorer/README.md) |
| Извлечь сохранённый ScriptText или восстановить классы из байткода | [uExplorer: экспорт кода](uExplorer/docs/USER_GUIDE.md#5-экспорт) |
| Сравнить сохранённые ресурсы оригинала и реконструкции | [uExplorer: просмотр ресурсов](uExplorer/docs/RESOURCE_GUI.md) |
| Редактировать XDAT, строки и проекты текстур | [Interface Editor](interface_editor/README.md) |
| Расширить внешний UCC поддержкой `INT64` и профильных конструкций | [ucc64](int64/README.md) |
| Добавить свои native-функции в клиентское расширение | [ExtensionL2](dll/README.md) |
| Встроить WebView2 или создать тему интерфейса | [Браузер](gameAddWebWithD3D9/README.md) · [pinkDream](pinkDream/README.md) |

Отдельный проект **openUCC** реализует
независимый компилятор UnrealScript и структурную пересборку ресурсов. Это не
`ucc64`: последний — launcher/bridge для **внешнего** UCC и SDK.

## Быстрый старт: готовые приложения

**Interface Editor** и **uExplorer** поддерживают автономные Windows x64-пакеты
со встроенными Python и Qt. Если подходящий архив опубликован в **Releases**,
скачайте и распакуйте его, затем запустите `Start.cmd`. Наличие конкретной
версии в Releases проверяйте отдельно; локальная preview-сборка не означает
автоматической публикации.

Для собственной сборки по необходимости откройте **Actions**, выберите
**Release Interface Editor** или **Release uExplorer**, нажмите **Run workflow**
и задайте версию и признак предварительного релиза. После успешных тестов
workflow публикует ZIP и `SHA256SUMS.txt`.

## Interface Editor: XDAT, схемы и текстуры

- **Редактирование:** две независимые панели дерева и поиска, свойства,
  добавление/копирование объектов, сравнение, общая история Undo/Redo и
  JSON roundtrip. Для свойств цвета доступны цветовой круг, ползунки RGB и
  числовой код; выбором через диалог старший байт сохраняется, отдельное поле
  alpha не меняется.
- **Схемы XDAT:** раздельные профили с ленивой загрузкой, включая High Five,
  Gracia и проверенные native-reader профили Essence/Japan и Korea. Подбор
  схемы, трассировка полей, HEX и проверка гипотез помогают исследовать
  неизвестные данные; гипотезы и сохранённый необработанный хвост не считаются
  доказанной структурой. Выбор схемы не конвертирует документ между клиентами.
- **Статический preview:** окна, кнопки, текстуры, TextBox и ScrollArea для
  поддержанных профилей, экспорт PNG, ограниченные повороты и масштаб UI,
  группы диагностических замечаний. Скрипты, динамические состояния и полный
  игровой вид не воспроизводятся.
- **Текстуры и строки:** проекты из PNG/TGA, сборка собственного UTX и
  назначение текстур, редактор SysString и DAT. Текущий writer проекта текстур
  создаёт UTX профиля HF 125/38 RGBA8 с одним mip; оригинальные RSA-профили DAT
  доступны только для чтения.

Проверка привязана к указанным профилям и образцам, а не ко всем клиентам.
Полное [руководство Interface Editor](interface_editor/USER_GUIDE.md) и
[исследование схем](interface_editor/docs/SCHEMA_RESEARCH.md).

## uExplorer: код и ресурсы

- Открывает каталоги с `.u`, `.utx`, `.usx`, `.ukx`, `.uax` и `.unr`.
  Извлекает сохранённый ScriptText либо восстанавливает классы по метаданным
  и байткоду; статусы `source`, `recovered`, `partial`, `failed` и JSON-отчёт
  помогают отличить исходник от неполной реконструкции.
- Показывает текстуры и mip-уровни, локальные грани Cubemap, свойства и графы
  материалов; проигрывает звуки с волной, FFT и спектрограммой.
- Предоставляет диагностический 3D-просмотр геометрии, скелетов, скелетных и
  вершинных анимаций, текстурированных моделей и ограниченного skinning.
  Shader/Combiner и UV поддерживаются только для распознанных вариантов;
  частичные показы и сохранённые снимки помечены.
- JSON API/CLI читает инвентарь, поддержанные текстуры, материалы, модели,
  анимации и звуки; `resource_batch` выполняет ограниченную пакетную выборку.
  GUI сравнивает доступные структурные поля оригинала и реконструкции.

Ресурсный GUI работает **только на просмотр и сравнение**: экспорт `.uc`
относится к режиму кода, не к универсальному экспорту текстур, звуков или
готовых материалов. Полное игровое освещение, анимация материалов, коллизии и
runtime-эквивалентность не заявляются. Подробности —
[ресурсный просмотр](uExplorer/docs/RESOURCE_GUI.md),
[ресурсный API](uExplorer/docs/RESOURCE_INVENTORY.md),
[руководство](uExplorer/docs/USER_GUIDE.md).

Совместно с openUCC структурно сравнены **1 183/1 184 контейнера Korea и
234 612 экспортов**. Один `.usx` отклонён из-за некорректных исходных
wire-индексов; этот результат не является проверкой всех карт или игровых
эффектов. Локально проверена portable preview **0.2.0-resource-preview.49**;
сохраняется только последняя preview-версия.

## Остальные инструменты и границы

- **ucc64 и ExtensionL2:** расширение внешнего UCC, `INT64`, client Sort,
  профильные enum/native PtrProperty, генерация UC-объявлений и подготовка
  native-расширения. Исходные UCC/SDK и клиентские зависимости в Git не входят.
  [Покрытие и поставка](docs/ROUNDTRIP_RELEASE.md).
- **Полный Interface:** в отчётах подтверждены адаптированные SDK-сборки
  Gracia, High Five, Японии и Кореи. Для первых двух использован сохранённый
  ScriptText, для последних двух — восстановление байткода. Успешная компиляция
  отделена от проверки в игре; различия метаданных modern-профилей сохранены
  в результатах. [Статус и границы проверки](docs/FULL_PACKAGE_REPAIR.md).
- **WebView2:** рабочие профили основной ветки — High Five и Gracia.
  Native-сборка без клиента и полный устанавливаемый UI-комплект — разные этапы.
  [Подготовка и сборка](gameAddWebWithD3D9/docs/PUBLICATION_BUILD.md).
- **Scryde:** подтверждён pinkDream; другие интеграции не подтверждены.

Workflow CI предназначен для сборки native-компонентов и автономных тестов;
фактический результат конкретной ревизии смотрите в GitHub Actions.
Release-workflows проверяют portable-пакеты обоих настольных приложений перед публикацией.
Проверки с игровыми клиентами и внешним SDK
выполняются отдельно. Исторические результаты привязаны к хешам проверенных
артефактов и не заменяют проверку новой сборки.

## Пути в документации

Корень репозитория — каталог с этим README и папками `dll`, `int64`,
`interface_editor` и другими проектами. Он может находиться в любом месте.
Пути внутри репозитория указаны относительно этого корня либо рабочего каталога,
явно названного в инструкции.

`<HF_CLIENT>`, `<GRACIA_CLIENT>` и `<SCRYDE_CLIENT>` обозначают корни установленных
клиентов соответствующих профилей; `system` и `SysTextures` — их подкаталоги.
Заменяйте обозначения своими путями, не вводите угловые скобки буквально.
В командах PowerShell пути задаются переменными, например:

```powershell
$ClientRoot = Read-Host 'Полный путь к корню нужного клиента'
$ClientSystem = Join-Path $ClientRoot 'system'
```

Для Scryde корень — каталог, содержащий `SysTextures` и `Scryde`, а не сама
подпапка `Scryde`. `<TEMP>` обозначает существующий временный каталог;
в PowerShell его можно получить через `[System.IO.Path]::GetTempPath()`.
Абсолютные пути вида `D:\YourClient` или `C:\Python312` — условные примеры:
подставьте расположение своей установки.

## Сборка приложений из исходников

Нужны Python 3.12, CMake 3.24+, для Windows — Visual Studio 2022 с C++ tools
и Windows SDK. Команды ниже выполняются из корня клонированного репозитория.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r interface_editor/requirements-release.txt -r pinkDream/requirements.txt
$Python = (Get-Command python).Source

# Редактор: Python x64 и C++ x64
cmake -S interface_editor -B interface_editor/build -G "Visual Studio 17 2022" -A x64 "-DPython_EXECUTABLE=$Python"
cmake --build interface_editor/build --config Release
python interface_editor/app/main.py

# uExplorer
cmake -S uExplorer -B uExplorer/build -G "Visual Studio 17 2022" -A x64 "-DPython_EXECUTABLE=$Python"
cmake --build uExplorer/build --config Release
cmake --install uExplorer/build --config Release --prefix uExplorer
python uExplorer/launch.py
```

## Что находится в репозитории

Исходники, схемы, рецепты тем, тесты, собственные примеры и документация.

команды выше собирают инструменты из исходников без готового релиза.
