# NWindow: rotationAngle и ScalableData

Дата: 2026-10-31. Назначение — воспроизводимая основа дальнейшей работы над
`interface_editor`, а не полный SDK или утверждение о совместимости всех сборок.

## Образцы и метод

| Образец | SHA256 файла NWindow.dll |
| --- | --- |
| Korea | `4ed1266cc4266d7612ac52f5cd12e587b8bd0a795e6c4972d31304e5aa7981a7` |
| Japan | `4edbe29c627ad839850f3319a46fa87c0e74a887e33b8fdb548b7ee59d846e26` |

Код исследован **только в корейском сохранённом загруженном образе** x86.
Исходный PE защищён; байты на диске и загруженные инструкции не взаимозаменяемы.
Использованы экспортные имена, guard-строки UTF-16, ссылки на них, таблицы
виртуальных методов и дизассемблирование Capstone. Японская DLL идентифицирована
хешем; отдельно проверены значения японских XDAT, не эквивалентность машинного кода.

Все адреса ниже — **RVA**, не файловые смещения и не адреса Gracia из основной
карточки. При работе с загруженным образом применять его фактическую базу.
DLL, дампы памяти, клиентские XDAT и снимки не публикуются. Оригиналы не изменялись.

## 1. Поворот: подтверждённые ветви

В процедуре применения общих свойств, начало `0x974770`, участок
`0x974D08..0x974DD3`:

1. Читается float угла из объекта определения, смещение `+0x68`.
2. Сравнение с константой **-9999.0** (RVA константы `0xE4728C`), затем с нулём.
   В обоих случаях установка поворота пропускается.
3. Начальная ось — `(0, 0, 1)`.
4. Если хотя бы один компонент оси задан (не -9999), каждый незаданный компонент
   заменяется на ноль. Если все три равны -9999, остаётся начальная ось Z.
5. Через vtable `+0x208` устанавливается ось, через `+0x20C` — угол.

Связанные точки:

| RVA | Назначение |
| --- | --- |
| `0xA4DF70` | `UWindowHandle::execSetRotationAngle`: float и необязательный vector, начальная ось Z |
| `0xB4B3A0` | `NCWnd::SetRotationAngle`: записывает угол в runtime-объект `+0x1C4` |
| `0xB4EFE0` | Чтение runtime-угла из `+0x1C4` |
| `0xA48D60` | `UWindowHandle::execGetRotationAngle` |

**Не смешивать** `+0x68` объекта определения с `+0x1C4` runtime NCWnd.

### Корпус XDAT

Считались UI-узлы каждого верхнеуровневого окна, включая вложенные контролы:

| Файл | Угол -9999 | Угол 180 | Оси для 180 |
| --- | ---: | ---: | --- |
| Japan normal | 20650 | 6 | Y |
| Japan Classic | 22616 | 6 | Y |
| Korea normal | 20062 | 6 | Y |
| Korea Classic | 22178 | 7 | 6 × Y, 1 × Z |

Для поворотов Y незаданные X/Z равны -9999. Примеры — текстуры
`tex_WeaponShapeBtn_Loop`, `tex_ArmourBtn_Loop`, `tex_HairAccessoryBtn_Loop`.
В корейском Classic дополнительный Z-поворот имеет `Bg07_tex`.

Таким образом, прежнее условие `rotationAngle != 0` ошибочно сообщало о повороте
почти каждого элемента. Исправление sentinel подтверждено нативной ветвью,
а не только частотой значений в файлах.

## 2. ScalableData: структура и применение

XDAT содержит 101 запись `scale0..scale100`, каждая — два int:
`widthRate`, `heightRate`, и 101 таблицу `fontScale0..fontScale100`.
Последние содержат `defaultFontName` и пары `name -> fontName`.

Во всех четырёх исследованных файлах запись i содержит `(100+i, 100+i)`.
Это свойство образцов, **не правило генерации таблицы**: редактор читает реальные
значения выбранной записи, поддерживает разные коэффициенты X и Y.

| RVA | Наблюдение |
| --- | --- |
| `0x928E10` | `XMLScalableGlobalData::Create`: цикл 101 записи, преобразование int в float и деление обеих компонент на 100.0 |
| `0xE471DC` | Константа float 100.0, используемая в этом преобразовании |
| `0x8B1550` | `NCScalableUIManager::SetScalableUIGlobalData`: запись пары float в таблицу по индексу |
| `0x8B17E0` | Получение пары коэффициентов: база + индекс × 8 |
| `0xA46F70` | `execChangeScalableSize`: unsigned-проверка индекса <=100, обращение к таблице, виртуальный вызов `+0x148`, уведомление скрипта |
| `0xB4E5B0` | Изменение масштаба NCWnd; без runtime `NCScalableUI` в поле `+0x1EC` возвращает отказ |
| `0xB3BFB0` | Пересчёт положения/anchor-offset |
| `0x929C80` | Исходные смещения `+0x14/+0x18` NCScalableUI умножаются на коэффициенты X/Y |
| `0xB427A0` | Сохраняет текущие коэффициенты в NCWnd `+0x1F0/+0x1F4`, пересчитывает размеры |
| `0x929BE0` | Исходная ширина NCScalableUI `+0x0C` умножается на коэффициент |
| `0xB3BE10` | Передаёт выбранный уровень/пару коэффициентов дочерним NCWnd |
| `0xB3BEE0` | Подмена font ID с учётом выбранного уровня |
| `0x8B1880` | `ScalingFontID`: индекс уровня и исходный font ID выбирают запись таблицы |
| `0x8B13B0` | `ResizeFontMappingData`: создаёт массив записей для font ID; затем явные mappings заполняют соответствия |
| `0xB42AE0` | Чтение текущих коэффициентов NCWnd |

Размер шрифта не следует повторно умножать на процент: выбранная таблица меняет
идентификатор шрифта. В образцах `GameDefault` при уровнях 0/50/100 переходит
в `GameDefault` / `GameDefaultType2` / `GameDefaultType3`; определения содержат
размеры 10/12/14. `FrameTitle` и edit-font имеют собственные соответствия.
В `0xB3BEE0` установка выполняется только для действительной записи соответствия;
именованный шрифт без mapping не следует безусловно заменять defaultFontName.

### Включение масштабирования

`XMLWindowData::GetScalable`, RVA `0x97C950`, проверяет поле `+0x23C`.
При -1 обращается к связанному определению; если значение осталось -1 или
связанное определение отсутствует, возвращает **0**, а не 1.

`NCWnd::SetUpScalableUIDefaultSetting`, `0xB4E660`, может создать runtime-объект
по состоянию родительского окна. `NCWnd::AddScalableUI`, `0xB43930`, также
выделяет его явно. Поэтому наличие таблицы в XDAT не означает, что каждое окно
масштабируемо. Включение/уровень могут дополнительно задаваться игровым кодом.

В корпусе явно `scalable=1`: Japan normal — нет; Japan Classic — InventoryWnd;
Korea normal — CharacterCreate; Korea Classic — CharacterCreate и InventoryWnd.
Это не перечень окон, которые игра может сделать масштабируемыми во время работы.

## 3. Что реализует предпросмотр, а что ещё приблизительно

- -9999/0 не создают предупреждений о повороте; sentinel-компоненты оси
  нормализуются по наблюдённому правилу.
- Используется статическое преобразование вокруг центра прямоугольника:
  Z-повороты и 180° вокруг X/Y (отражение). Пиксельные тесты проверяют результат.
  **Точная точка вращения игрового renderer, перспектива и смешанные 3D-оси
  в этом разборе не установлены.** Это обозначенное приближение редактора.
- Уровень UI выбирается пользователем отдельно от zoom изображения.
  Умножаются абсолютные размеры и anchor-offset; доли процентных размеров
  применяются к уже рассчитанному reference без повторного умножения.
- Статическая модель наследует включение масштабирования по дереву; явные
  `scalable=0/1` переключают его, для корня без заданного значения используется 0.
  Полная цепочка наследования определений и runtime-скрипты не эмулируются.
- FontMapping выбирает имя/размер из fontDefinition; системная гарнитура остаётся
  приблизительной. Файлы шрифтов клиента не загружаются, тени/stroke не эмулируются.
- Округление дробных координат и специализированные виртуальные методы разных
  контролов могут отличаться от native. Скриптовые уведомления не исполняются.

Снимок для фонового рендера включает таблицы, определения шрифтов и стили под
той же блокировкой и revision, что и поддерево UI. Preview не редактирует XDAT.

## 4. Как продолжить исследование

1. Проверить хеш DLL. Для другой сборки заново найти экспортные/guard-имена;
   не переносить RVA механически.
2. В рабочей копии получить загруженный образ с известной базой. Сопоставить
   экспорт `execChangeScalableSize`, guard-строки `XMLScalableGlobalData::Create`,
   `NCScalableUIManager::ScalingFontID`, `XMLWindowData::GetScalable`.
3. Проверить ветвление sentinel, начальную ось, делитель 100 и границы индекса.
   Не делать вывод о runtime-семантике только из сериализатора.
4. Для pivot/направления вращения проследить передачу NCWnd axis/angle до
   графического backend и сверить асимметричную тестовую текстуру в рабочей копии.
5. Для полного масштабирования сверить окна с `scalable=-1/0/1`, вложенные окна,
   процентные размеры, fontMapping и динамическое переключение на уровнях 0/50/100.
6. Публиковать только обезличенные выводы, хеши и RVA; клиентские файлы/дампы
   и пользовательские настройки оставлять вне отслеживаемого содержимого.
