# WebView2 → GPU-кадры → интерфейс HF

> Историческое описание до разделения на профили. Пути browserTexture и gracia
> соответствуют теперь profiles/high-five и profiles/gracia от корня проекта.
> Актуальные комплекты и команды: [README](../README.md).

Независимая экспериментальная ветка в `gameAddWebWithD3D9`.
Исходная PNG-сборка остаётся в `../gameAddWeb/browserTexture`.
При подготовке этой версии клиент не изменялся.

**Подробное руководство:** [GUIDE.md](GUIDE.md) — назначение инструмента,
путь кадра, потоки, ввод, жизненный цикл, сборка, установка и откат, диагностика
и правила подготовки клиентских профилей.

**Пошаговый перенос на другие клиенты:** [PORTING.md](PORTING.md) —
от проверки DLL/ABI и восстановления Interface до сборки, установки и игрового теста.

**Статус профилей:** HF проверен в игре. Interface Gracia восстановлен,
скомпилирован и проверен по байткоду; UI загружается в игре. Для Gracia подготовлен
семифайловый комплект с отдельным `GraciaBrowserHost.exe`: IPC-тесты прошли,
подтверждены изображение, ввод и lifecycle в игре. Текущий статус и команды:
[профиль Gracia](../profiles/gracia/README.md).

## Два проверенных пути

### 1. GPU sharing: самостоятельный эксперимент

`native/gpu_probe.cpp`: WebView2 CompositionController → DirectComposition →
Windows Graphics Capture (WGC) → D3D11 texture → общая D3D9Ex texture.
В конце кадр читается **через D3D9**, чтобы проверить фактическую передачу пикселей.
Источник — служебное HWND за пределами виртуального рабочего стола.

На RTX 3080, x86, 512×512, непрерывная canvas-анимация, 10 секунд:

- 59.6 полученных кадров/с, 54.5 изменяющихся кадров/с;
- GPU-копирование с ожиданием завершения: 0.88 мс;
- контрольное чтение через D3D9: 2.59 мс;
- 117 различных цветов прочитано из D3D9, проверена ожидаемая цветовая область.

Отчёт: `reports/d3d9ex-shared-probe.json`. Это самостоятельное D3D9Ex-устройство,
а не устройство игры. Импорт HF D3DDrv.dll содержит `d3d9.dll!Direct3DCreate9`,
поэтому открытие shared texture на игровом устройстве этим тестом не доказано.

Сборка и запуск эксперимента:

```powershell
.\build.ps1
```

### 2. Готовый к проверке в HF совместимый путь без PNG

`browserTexture/`: WebView2 HWND → WGC/D3D11 → staging/readback BGRA →
проверенный адаптер динамической UTexture → штатный Canvas/D3D9 HF.
GPU sharing в самой игре не используется. Сохраняется штатное перекрытие
браузера другими игровыми окнами. Заменять D3DDrv.dll/Engine.dll не требуется.

На непрерывной requestAnimationFrame-анимации, 512×512, 8 секунд:

- 55.9 полученных кадров/с, 52.6 копирований/с потребителю;
- GPU-захват/readback: среднее 2.36 мс, максимум 5.96 мс;
- копирование потребителю: среднее 0.124 мс;
- PNG и WIC-декодирование исключены.

Отчёт: `reports/hf-wgc-motion-benchmark.json`. FPS игры, YouTube и D3D-upload
в HF пока не измерены. Сравнение с прежними ~18 FPS не является строгим A/B:
этот тест использует непрерывную анимацию. WGC выдаёт новые кадры при изменении
изображения: на исходной странице с изменением раз в 400 мс получилось 2.5 FPS,
что соответствует частоте изменения содержимого, а не ограничению производительности.

Прошли MSVC x86, UCC (0 ошибок / 35 прежних предупреждений), Core VM, XDAT,
JSON-конфиг, кадры, русский ввод, мышь/drag/колесо, mute, popup, hide/resume/close.
Проверка профиля установленного HF (`install.py --check`) также прошла.

## Установка тестовой сборки

При закрытом клиенте сохранить текущие три файла и заменить из
`browserTexture/result/system`:

- `ExtensionL2.dll`
- `Interface.u`
- `Interface.xdat`

`WebView2Loader.dll` уже есть в рабочем комплекте; при необходимости он лежит
здесь же. Существующий `options.config` сохранить. Иконка E встроена в Interface.u.
Браузерный профиль WebView2 остаётся прежним (`L2TextureWeb`, ключ — путь DLL).

Проверить YouTube, перекрытие настройками, русский ввод, колесо, сворачивание,
звук после закрытия и переход между экранами. Новый `system/browser-performance.json`
содержит `pipeline: WGC D3D11 readback -> HF CPU mip (no PNG)`.
Для отката вернуть сохранённые три файла.

Установщик с резервным копированием, из папки browserTexture:

```powershell
$ClientSystem = Read-Host 'Полный путь к system целевого клиента HF'
py -3 install.py --system $ClientSystem --check
py -3 install.py --system $ClientSystem
```

## Сборка комплекта HF

```powershell
.\browserTexture\build.ps1
```

Исходники скопированы в эту ветку; её staging/workspace/result не используют
выходные каталоги исходной PNG-сборки. Общими остаются компилятор/SDK/editor
в `../addWeb`, runtime Python в `../interface_editor`.

Требуются работающий WebView2 Runtime, D3D11 и Windows Graphics Capture
(проверено на Windows 11). При недоступности WGC выводится ошибка; скрытого
возврата на PNG нет. Автоматическое восстановление после потери D3D11-устройства
ещё не реализовано. Подключение shared GPU-текстуры непосредственно к устройству
HF — отдельный следующий этап; текущая сборка сохраняет CPU-readback ради
совместимости с уже проверенным текстурным адаптером.

## Исправление завершения процесса

После успешного игрового теста обнаружен оставшийся l2.exe.
У PID 44960 после закрытия оставался один ожидающий поток. Найден опасный путь:
глобальные COM/WinRT-объекты могли вызывать Release из CRT-деструкторов DLL при
ExitProcess, когда остальные потоки уже остановлены и удерживается loader lock.

При DLL_PROCESS_DETACH с ненулевым reserved теперь только отсоединяются указатели
COM/WinRT без Release/Close/ожиданий/блокировок. При завершении процесса ресурсы
освобождает ОС. Обычное закрытие WebView/WGC по-прежнему выполняется на STA;
источник WGC закрывается перед контроллером. STA также отслеживает уничтожение
окна-владельца клиента и завершает свой цикл сообщений.

Регрессия `browserTexture/tests/test_exit.ps1`: отдельный процесс загружает DLL,
запускает WebView2/WGC до получения кадра и вызывает ExitProcess без Shutdown.
Старый путь дал 0xC0000005, исправленный — 0. Полная копия сценария зависания HF
этим тестом не воспроизведена; после исправления выполнена повторная проверка
клиента, проблема не наблюдалась.
Отчёт: `reports/shutdown-regression.json`. Тест не завершает игровые процессы;
при таймауте он завершает только созданный им дочерний fixture.
