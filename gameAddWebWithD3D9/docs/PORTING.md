# Внедрение браузера в другой клиент: порядок работ

Пути относительно `gameAddWebWithD3D9`, если не указано иначе. Эта инструкция
описывает инженерный перенос внутри текущего дерева инструментов. Автоматического
универсального конвертера для любой сборки Lineage II нет: ABI и UI проверяются
для конкретных файлов. Для уже поддержанных HF и Gracia используйте их build/install.

## 1. Сохранить оригиналы и идентифицировать клиент

Создать отдельную папку профиля с неизменяемыми `inputs`. Скопировать Core.dll,
Engine.dll, NWindow.dll, D3DDrv.dll, Core.u, Engine.u, NWindow.u, Interface.u,
Interface.xdat. Записать SHA256, версии PE/пакетов и схему XDAT. Рабочие HF/Gracia
не использовать как место экспериментов для нового клиента.

Проверить `../dll/core_profiles.json` и `client_profiles.json`: одинаковое название
хроник не означает одинаковый профиль. Хеши в профиле должны относиться к исходным
файлам, а не к случайно уже заменённым DLL.

## 2. Подготовить Core и native API

Следовать `../dll/CORE_PROFILES.md`: проверить таблицу native-функций, соглашения
вызова, строковые экспорты, загрузку ExtensionL2. Gracia использует в том числе
вариант строкового ABI PBG, HF — PB_W. Проверить загрузку Engine с выбранным Core
и реальные VM-вызовы до интеграции браузера.

Проверить свободные native-индексы. Текущий браузер использует 4000–4030;
существующие клиентские native-функции не переназначать. В Gracia 4086–4095 сохранены.

## 3. Проверить текстурный ABI

Найти и подтвердить Engine::Init, vtable UTexture/render interface, offsets mip,
размеров, формата, пикселей и dirty/revision. Сравнить с профилями
`client_profiles.json`. `tools/client_profiles.py` проверяет входы и генерирует
адаптер; точные CLI-аргументы доступны через `--help`.

Пример теста — `profiles/gracia/tests/texture_layout_probe.cpp`: настоящий Engine::Init,
цвета каналов, обновление revision, отказ чужому layout. Успех fixture не доказывает
работу игрового UObject/GC/Canvas — это проверяется после запуска клиента.

## 4. Получить и восстановить исходники Interface

Сначала проверить наличие настоящего ScriptText. Парсер пакетов —
`tools/ue2/ue2package.py`, извлечение — `tools/ue2/extract_sources.py`.
В Gracia ScriptText пуст; использована WOTgreal-выгрузка и исходный байткод.

Цепочка Gracia как образец:

| Скрипт | Что делает |
|---|---|
| `profiles/gracia/audit_exported_sources.py` | Сверяет классы, анализирует повреждения и неизвестные natives |
| `profiles/gracia/restore_sources.py` | Восстанавливает native-имена, простые циклы и литералы |
| `profiles/gracia/property_types.py` | Читает типы, enum, свойства и сигнатуры |
| `profiles/gracia/bytecode_sources.py --all` | Генерирует тела по basic blocks с диспетчером исходных адресов |
| `profiles/gracia/verify_recovery.py` | Сравнивает скомпилированные выражения/переходы и метаданные с оригиналом |

Эти скрипты привязаны к входам Gracia. Для нового клиента адаптировать пути,
декларации и обнаруженные особенности, а не запускать их вслепую. Сохранять
промежуточные отчёты и исходную выгрузку. Исправление только синтаксиса не доказывает
сохранение поведения.

Исходники хранить вне каталога игры: Gracia при наличии `interface/Classes`
проверяет uclist.int и может удалить Interface.u для встроенной перекомпиляции.

## 5. Встроить окно и API

Основа — `profiles/high-five/Classes/BrowserWnd.uc` и API-классы. Добавить браузерные
native-декларации, иконку и обработчик кнопки логина. Для восстановленного
диспетчера ветку Browser вставлять перед его исполнением, после local declarations.

Добавить BrowserWnd в соответствующую схему XDAT: texture surface, прозрачную
кнопку ввода, EditBox клавиатуры и адреса, навигационные кнопки, состояния,
иконку сворачивания. В Gracia это ct24, в HF ct26; перенос по номерам полей без
сопоставления семантики неверен. Проверить round-trip сериализации и сохранение
прежних UI-узлов. Порядок окон проверять на логине и в игре.

`prepare.py` каждого варианта готовит staging, SDK, Classes, ресурсы и XDAT.
Изменения вносить в исходники/генераторы: stage и workspace перезаписываются.

## 6. Выбрать размещение браузера

- HF: WebView2, WGC и BGRA работают внутри процесса на отдельном STA.
- Gracia: `GraciaBrowserHost.exe` обслуживает WebView2/WGC, DLL обменивается с ним
  кадрами и вводом через IPC. Этот вариант введён после воспроизводимого
  `Create controller 0x80010108`; первопричина внутрипроцессного сбоя не установлена.

Общий путь: WebView2 → WGC/D3D11 → CPU BGRA → UTexture → штатный Canvas/D3D9.
Это не прямое D3D11/D3D9Ex sharing. UObject изменяет только игровой UI-поток.
Для прежнего IPC см. `profiles/gracia/browser_host.cpp`, `browser_transport.cpp`, `browser_ipc.h`.

## 7. Собрать и проверить вне игры

Нужны VS2022 C++/Windows SDK, CMake, Win32/x86, WebView2 Runtime и Python с
XDAT-модулем; используются SDK и компилятор из текущего дерева проекта.

HF: `profiles/high-five/build.ps1`. Gracia (команды из profiles/gracia):

```powershell
cd gracia
.\build.ps1 -ExportedClasses 'D:\sources-outside-client\Classes'
```

`compile_ui.ps1` вызывает UCC через `tools/ue2/run_compile.py`;
`build_native.ps1` собирает native-часть и запускает тесты с таймаутами.
`tools/ue2/package_client.py` упаковывает Interface с envelope клиента,
не подменяя версию пакета и не изменяя скомпилированный payload.

Проверки: Core loader/VM, JSON options, текстурный layout, кадры/ввод/lifecycle,
выход процесса, а для отдельного host — та же функциональность через IPC.
Не считать отдельный host-тест доказательством работы внутри игры.

## 8. Сформировать комплект и установить с откатом

`manifest.py` проверяет выходные файлы, отчёты и XDAT и записывает хеши.
`install.py --check` выполняет read-only проверку клиента и комплекта.
Обычная установка создаёт backup, сохраняет options.config; `--restore` откатывает
установку после проверки хешей. Команды для Gracia приведены в её README.

В комплекте Gracia семь файлов, включая Core.dll и GraciaBrowserHost.exe.
Компиляторские Core.u/Engine.u/NWindow.u не копировать в игру как runtime-замену.
Для нового профиля перечень выходных файлов и разрешённых входов формируется явно.

## 9. Подтвердить в игре и зафиксировать результат

Проверить изображение, логин/игровые состояния, RU/EN, клики, колесо, drag,
потерю фокуса, сворачивание, иконку, закрытие, прекращение звука, popup,
порядок окон и завершение процесса. Для Gracia `diagnose_browser.ps1` даёт чистый
профиль и Chromium log; обычный статус также виден в заголовке и web-texture.log.

Привязать подтверждение к хешам реально установленных файлов, как в
`profiles/gracia/game-validation.json`. Новая сборка с другими хешами требует новой проверки;
manifest Gracia автоматически не переносит старое подтверждение на новые бинарники.
