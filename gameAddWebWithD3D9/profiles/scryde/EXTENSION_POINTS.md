# Проверка точек расширения Scryde

Статус: исследование остановлено. [Сводка и состояние файлов](README.md).
Ниже — результаты разных методов; отказ одного метода не отменяет успех другого.

## Успешная трассировка Process Monitor

Запись `tests/startup-trace-20261029-113919` завершена успешно:
`startup.pml`, полный экспорт `startup.csv`, выборка `scryde.csv`, `result.json`.
В выборке 232821 событий: 212366 от ScrydeGame.bin и 20455 от загрузчика.
Зафиксирован 231 Load Image (включая повторные события и оба процесса).

Подтверждена загрузка clmods.dll и ScrydeRadio.dll из тестового каталога,
а также Core/Engine/NWindow/D3DDrv и других штатных библиотек.
В этой записи нет обращений к путям с ExtensionL2, WebView или plugin.
Это ограниченный интервал запуска до экрана входа, а не доказательство отсутствия
всех механизмов расширения во всех игровых сценариях.

Из тестового system читались Option.ini, Scryde.ini, ScrydeGame.ini, User.ini,
localization.ini и s_info.ini. Конфигурации загрузчика сторонних UI-плагинов
в этих наблюдениях не выявлено. Наличие и загрузка clmods/ScrydeRadio сами по себе
не означают открытого интерфейса регистрации стороннего кода.

Дополнительная деталь: msxml4.dll загружена из исходного каталога
`<SCRYDE_CLIENT>\Scryde` (основная установка), несмотря на запуск копии на другом диске.
Причина выбора пути не установлена (возможна системная COM-регистрация).
Следовательно, копия не полностью независима от исходного каталога.
Это наблюдение не объясняет автоматически прежний отказ копий с junction.

Итог: наблюдать загрузку удалось без перечисления модулей через Toolhelp/PSAPI,
но подтверждённой пользовательской точки подключения браузера не найдено.

## Результат динамической диагностики

`module_probe.ps1` завершился с кодом 2: ни один метод не перечислил модули
клиента. Отчёт перенесён в `tests/retained-fixture-reports/module-probe.json`.
64-битный сборщик запущен с повышением прав. Контроль на собственном процессе
успешен: Toolhelp и PSAPI перечислили по 89 модулей.

Для ScrydeGame.bin (PID 58844) все три замера, включая два с заголовком
`Scryde Game`, дали одинаковый результат:

- CreateToolhelp32Snapshot: ошибка 5 (ERROR_ACCESS_DENIED).
- OpenProcess с PROCESS_QUERY_INFORMATION | PROCESS_VM_READ: успешно.
- EnumProcessModulesEx: ошибка 5 (ERROR_ACCESS_DENIED).

Это подтверждает отказ перечисления модулей этими API, но не устанавливает,
какой компонент его вызывает. Наличие/отсутствие ExtensionL2, clmods или
ScrydeRadio в памяти из этого отчёта определить нельзя.
Код 2 намеренно обозначает отсутствие успешного результата для игры;
он не является свидетельством падения сборщика или клиента.

## Проверка публичной документации

- https://active-ac.com/manual/en/lineage2/settingup/ прямо указывает, что
  настройки находятся в config сервера AA. files.xml формируется FileHasher.
- https://active-ac.com/manual/en/lineage2/plugins/ описывает BrowserBypass
  (открытие браузера игрока), Overlay (текст) и UiEvents (события существующего
  интерфейса). Они включаются серверной конфигурацией и вызываются серверными
  пакетами; это не описанный SDK произвольных пользовательских DLL/WebView.
- На форуме Scryde есть пользовательские текстурные патчи, например
  https://board.scryde.net/threads/patch-by-chaser-v3-0-scryde-fix-the-icon-above-the-head-flame-archon-14-04-26.67060/page-35
  с обсуждением переноса текстур в новые файлы после обновления. Это не доказывает
  разрешённость замены Interface.u/XDAT или наличие программного API.

Публичной инструкции подключения собственного браузера в рассмотренных источниках
не найдено. Это результат ограниченного поиска, не доказательство отсутствия API.
Первый сборщик `observe_modules.ps1` (32-bit PowerShell с повышением прав)
завершился с кодом 0, но записал пустые имена/пути модулей. Отчёт
`tests/retained-fixture-reports/module-observation.json` не подтверждает успешное перечисление.
Последующие Toolhelp/PSAPI и Process Monitor дали результаты, описанные выше.

Проверены бинарники и текстовые настройки установленного каталога
`<SCRYDE_CLIENT>\Scryde`, где `<SCRYDE_CLIENT>` — корень основной установки. Клиентские файлы не изменялись.

## ExtensionL2

На момент исходного аудита ExtensionL2.dll экспортировала ExtensionL2Attach, ExtensionL2Count,
ExtensionL2GetBinding, ExtensionL2Index, ExtensionL2LastStatus. В строках есть
WebView2, L2AddWeb, options.config, L2 browser frame source.
Это наш адаптер, а не штатный SDK Scryde; его экспортный интерфейс соответствует
`addWeb/native/base/extension_runtime.cpp`. Точная исходная сборка не определена.
Затем DLL удалена из основного клиента. В полной тестовой копии она
оставалась до удаления копии; её загрузки в записанном интервале Process Monitor не обнаружено.

ExtensionL2.u читается парсером: классы ExtensionL2API и ExtensionL2Tests,
корневой импорт Core. Само наличие пакета не означает его загрузку.

Статические таблицы импортов Core/Engine/NWindow/ScrydeGame.exe/ScrydeRadio
не содержат ExtensionL2.dll. Поиск ASCII/UTF-16 имён ExtensionL2 и
ExtensionL2Attach в DLL/EXE/BIN/текстовых настройках нашёл их только в самой
ExtensionL2.dll. Статическая цепочка загрузки адаптера не обнаружена.
ScrydeGame.bin не показывает обычных DLL-импортов: это ограничивает выводы.
Динамическая загрузка вне записанного интервала не исключена.

### Незавершённый анализ цепочки загрузки

Статический поиск обнаружил имя clmods.dll в ScrydeGame.exe, а ScrydeRadio.dll
и ZyXELAnchor — в ScrydeGame.bin. Это не устанавливает точную цепочку вызовов
или наличие настраиваемого загрузчика.
Экспорт PML со стеками был остановлен после роста XML до нескольких гигабайт.
Экспорт stacks.xml был неполон; попытки извлечения событий завершились таймаутами.
Неполный XML удалён при закрытии исследования.
Файл extension-load-stacks.json не создан. Проверенных выводов по стекам нет.

## Настройки и другие модули

- ScrydeGame.ini содержит стандартные Paths и EditPackages. Это пути поиска
  ресурсов и список пакетов редактора, а не подтверждённый загрузчик плагинов.
- SecureModule=False не отменяет проверку Active Anticheat: оба опыта замены UI
  были отклонены при существующих настройках.
- Строки Plugins/PluginPath найдены в fmodex.dll; это не свидетельство API
  расширения игрового UI (FMOD — звуковая библиотека).
- ScrydeRadio.dll экспортирует ZyXELAnchor; интерфейс регистрации UI-плагинов
  в рассмотренных экспортах не обнаружен. У clmods.dll именованных экспортов нет.

## HTML

NWindow экспортирует UHtmlHandle: LoadHtml, LoadHtmlFromString,
SetHtmlBuffData, ControllerExecution и стандартные NPC/tutorial/BBS viewers.
Это признаки штатного игрового HTML, а не доказательство поддержки современного
браузера, JavaScript или видео. Экспортируемого WebView/browser/plugin API
в рассмотренных Core/Engine/NWindow путях не установлено.

## Вывод

Подтверждённая штатная точка подключения собственного браузера не найдена.
Статический анализ не доказывает отсутствие всех возможных точек расширения:
родные Interface/Engine/NWindow пакеты защищены, точная цепочка вызовов неизвестна.
Загрузка отдельных модулей подтверждена Process Monitor, но это не доказывает
существование доступного пользователю механизма регистрации новых UI-пакетов.
