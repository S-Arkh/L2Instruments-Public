# Scryde: проверка замены интерфейса

Обозначения путей: `<SCRYDE_CLIENT>` — корень основной установки Scryde,
`<HF_CLIENT>` — корень исходного клиента HF. `<TRIAL_OTHER_DISK>` — тестовая
копия на другом диске, `<TRIAL_SAME_DISK>` — на диске основной установки.
Это условные обозначения расположений из эксперимента, а не буквальные пути.

## Итог: исследование остановлено

После завершения удалены все три тестовые копии:
`<TRIAL_OTHER_DISK>`, `<TRIAL_SAME_DISK>`, `tests/ui-trial-20261029-104801`
и неполный `stacks.xml`. Junction удалялись без обхода целевых ресурсов.
Документация, аудит и готовые трассировки сохранены. Малые отчёты из копии C:
перенесены в локальный `tests/retained-fixture-reports` рабочего дерева разработки;
эти артефакты не входят в публикационную копию.
Пути к удалённым копиям ниже описывают исторические условия опытов.

Браузер и пользовательский интерфейс в Scryde **не внедрены**.

Из проектов этого набора на Scryde работает только [pinkDream](../../../pinkDream/README.md).
Успешные запуски с исходным UI ниже относятся к базовому клиенту, а не к интеграции браузера.
Проверка завершена следующими результатами:

| Опыт | Результат |
|---|---|
| Копии с junction на диске основной установки | Окно не появилось; причина не установлена |
| Полная копия на другом диске с родным UI | Запуск подтверждён |
| HF Interface.u + HF Interface.xdat | Active Anticheat отверг Interface.xdat |
| HF Interface.u + родной XDAT | Active Anticheat отверг Interface.u |
| Наблюдение DLL через Toolhelp/PSAPI | Ошибка 5; контроль сборщика успешен |
| Наблюдение через Process Monitor | Загрузка clmods/ScrydeRadio подтверждена; API расширений не найден |
| Команда `///ui` | UI исчез, управление пропало; после перезапуска оба восстановились |
| Трассировка `///ui` | Поиска XML/XSD/дополнительных .u не зафиксировано |

HF-донор уже содержал BrowserWnd/AddWebAPI/TextureProbeAPI; это **не pristine HF**.
Совместимость его интерфейса с Scryde не установлена: проверка файлов остановила запуск.
Обход проверки целостности не реализован; исполняемые файлы в ходе исследования не патчились.

## Отдельная проверка Interface.u: замена отклонена

После восстановления родной пары в полной копии
`<TRIAL_OTHER_DISK>\Scryde` заменён только Interface.u на ранее проверенный
донорский файл (SHA-256 `b27d86db04ebd73d565e64a8d59ad69d04d91dae09c901fb03d0c240fda3a308`).
Interface.xdat остался исходным (SHA-256
`a1bf7b8bedc24df1a7ea8051f56dea62e97218883627cc350b5365bc7923c87a`).
Перед заменой проверено отсутствие процессов Scryde; после замены проверены хеши.
На время опыта в fixture.json устанавливалось `current_ui: donor-u-original-xdat`.
Запуск завершился окном Active Anticheat (ScrydeGame.bin, PID 30160).
Зафиксировано сообщение: «Файл не соответвует scryde\interface.u Пожалуйста,
проверьте файлы игры». Следовательно, отдельная замена донорским Interface.u
при родном XDAT также отклоняется проверкой файлов. Совместимость UI и native API
не проверена. После подтверждения закрытия клиента и проверки отсутствия
процессов Scryde родной Interface.u восстановлен. SHA-256 обоих установленных
файлов совпадают с исходными; fixture.json возвращён в состояние `original`.

## История: замена пары интерфейса

Полная копия ресурсов без junction создана в `<TRIAL_OTHER_DISK>`.
Подтверждён успешный запуск с исходным интерфейсом, затем закрыт
клиент. Причина отказа предыдущих копий не установлена: в новом опыте изменены
и способ копирования ресурсов, и диск размещения.

После проверки отсутствия игровых процессов в полной копии заменены только
`Interface.u` и `Interface.xdat` из `replacement-ui`. SHA-256 после установки:

- Interface.u: `b27d86db04ebd73d565e64a8d59ad69d04d91dae09c901fb03d0c240fda3a308`
- Interface.xdat: `8e0542f099f9a258afc77438715befe886b61a9524f64cfbc28e1813560da24d`

Пробный запуск с донорской парой заблокирован Active Anticheat.
Зафиксирован точный текст: «Файл не соответствует scryde\interface.xdat
Пожалуйста, проверьте файлы игры». Процесс ScrydeGame.bin (PID 41856)
показывал окно с заголовком Active Anticheat.

Вывод: простая замена этой пары не допускается проверкой целостности XDAT.
Совместимость HF-классов и native API не проверена: до загрузки UI опыт не дошёл.
Это сообщение само по себе не проверяло отдельную замену Interface.u;
её отказ подтверждён последующим опытом, описанным выше.
Оригинальная пара сохранена в `<TRIAL_OTHER_DISK>\original-ui`.
После закрытия клиентских процессов родная пара восстановлена в
`<TRIAL_OTHER_DISK>\Scryde`; SHA-256 обоих файлов проверены по исходным значениям
из аудита. В fixture.json установлено `current_ui: original`.

## История: подготовка первой копии

- Статический отчёт сохранён в `interface-audit.json`.
- Создана копия `tests/ui-trial-20261029-104801/Scryde` с исходным UI.
- Пары интерфейса сохранены в `original-ui` и `replacement-ui` рядом с копией.
- Донор содержит прежние браузерные изменения, включая BrowserWnd/AddWebAPI.
- Защищённые пакеты Scryde не декодированы; совпадение экспортов DLL не доказывает совместимость.

Первый baseline-запуск `ScrydeGame.exe` запросил повышение прав Windows:
manifest содержит `requestedExecutionLevel level='requireAdministrator'`.
Команда ожидания запуска превысила таймаут; последующая проверка обнаружила
процесс `consent`, но не игровой процесс Scryde. На этом этапе загрузка исходного
интерфейса ещё не была подтверждена и замена UI не выполнялась.

## Повторный baseline-запуск

После повторного запуска загрузчик (PID 20832) завершился, появился
`ScrydeGame.bin` (PID 14424) без заголовка окна. Подтверждено отсутствие
окна игры и сообщения об ошибке. При следующей проверке процесс уже отсутствовал.
Новые игровые журналы не появились: ScrydeGame.log и CheckGrp.log сохранили
время исходной копии (28 октября). В копии появился пустой Running.ini.
Причина завершения пока не установлена; несовместимость донорского интерфейса
этим опытом не проверялась, поскольку использована исходная пара Scryde.
