# Комплект компилятора ucc64

В `bin` находятся Windows x86 launcher `ucc64.exe` и его `Ucc64Bridge.dll`.
Держите их рядом. Комплект работает на Windows x64 через поддержку Win32.
SDK и игровые пакеты в архив не входят.

## Использование

Подготовьте отдельную копию совместимого SDK System и исходники в соседних
каталогах `<Package>/Classes`. Настройте `EditPackages` в `UE2Runtime.ini`.

```text
bin/ucc64.exe --system <isolated-System> make -NoBind
```

Launcher проверяет точный SDK по хешам. Ошибка совместимости означает, что нужен
поддерживаемый SDK, а не отключение проверки. Рабочий клиент не используйте как
каталог компиляции. Результат `.u` появляется в изолированном System.

Необязательные режимы задаются переменными окружения:

- `UCC64_CLIENT_ARRAY_SORT=1` — клиентский Sort, opcode `0x47`.
- `UCC64_CLIENT_ENUM_PROFILE=korea290` — проверенный профиль enum-зависимостей.
- `UCC64_SCOPED_ENUM_CASTS=1` — лексическое разрешение явных enum-преобразований.

Без этих переменных действует стандартный режим. Пакет с клиентским Sort нельзя
считать совместимым с обычным SDK runtime. Заголовок пакета не подменяется.

## Границы

Совместимый SDK: Core.dll SHA-256
`5bff274734cae994353a8c60f4bfe1087dbdd9aa3883c7b2a7eff6ea2f51dc7e`,
Editor.dll
`d64995c1282956c6e9d67dd70715a69b5101331aa727a2d44b03e25fd7f2cd2e`,
UCC.exe
`c68ba1ce0eab03af23b04dc1c991c3f1cc047a8a2076c6850e3071892806fb65`.

Указатели сохраняют native PtrProperty. Поддержка указателей legacy Gracia/HF
исключена из требований; репликация отложена и запрещена компилятором.
SDK автоматически меняет часть метаданных при сохранении. Успешная компиляция
не доказывает точность исходных метаданных или эквивалентность поведения клиента.

`BUILDINFO.json` содержит ревизию исходников и хеши файлов, `SHA256SUMS.txt` — хеш
ZIP. Проверка упаковки запускает извлечённый launcher из каталога с кириллицей
и пробелами. Полная регрессия, инструкции подготовки SDK, добавления профилей
и исследования находятся в исходном репозитории: `docs/SCRIPT_TOOLS.md`,
`test_interfaces/PROFILE_PIPELINE.md`, `int64/docs/METADATA_WORKFLOW.md`.

Поставляются варианты MSVC и MinGW. Выбирайте одну согласованную пару EXE/DLL;
наличие второго варианта не означает побайтовое равенство их бинарников.

## Шаблон локального переносного workspace

`int64/portable/Compile.ps1` и `Compile.cmd` предназначены для отдельного
workspace с уже подготовленным SDK. Они создают рабочую копию для каждой
попытки, перекодируют исходники в UTF-16 и сохраняют успешные результаты отдельно
от ошибок. `README_RU.txt` содержит краткую пользовательскую инструкцию.
Внешние SDK, клиентские пакеты и исходники профилей в Git не включаются.

Проверены обычная сборка, код отказа с сохранением предыдущего результата и
перенос в путь с кириллицей/пробелами при ограниченном PATH. Все поставленные DLL
необходимы по цепочке PE-импортов, включая IFC23, VorbisFile/Vorbis/Ogg и обе CRT
(MSVCR70/MSVCR71). Без User.ini возникает отказ appInit; без Editor.int не
находится make. Core.int, Engine.int и шаблонный UE2Runtime.ini не нужны
проверенной сборке; рабочий INI генерирует скрипт.

Профили именуются по подтверждённым протоколам: Gracia 152, High Five 268,
Japan 591, Korea 606. Историческое имя настройки korea290 обозначает проверенный
enum-профиль компилятора: оба предоставленных современных Engine содержат
совпадающую последовательность семи значений EL2ObjectType.
Для поставки предпочтителен сохранённый валидный ScriptText; при его отсутствии
используется восстановление из байткода. Происхождение исходников и результаты
проверок фиксируются отдельно, а исследовательские материалы не входят в
минимальный пользовательский комплект.
