# Указатели: проверенный поднабор

Текущий клиентский результат Korean/Japan: **25 PASS / 0 FAIL / 0 SKIP**.
Подтверждены ненулевые разные `GFxValue.pValue`, копирование через
local/value/out/return, поля, массив и структуру, а также обнуление копий
с сохранением native-значений 73/91. Отчёты сверены с Build и хешами комплекта.
Этап указателей закрыт в согласованных границах. Legacy-поддержка Gracia/HF
не требуется из-за отсутствия native-экспортов PtrProperty в проверенных Core.
Реализация репликации отложена; её явный запрет сохраняется. Оба пункта
исключены из условий завершения текущего этапа.
Ниже сохранена история предыдущих проверок и исправления native getter.

Компилятор создаёт настоящий `Core.PtrProperty`. Поддерживаются поля классов
и структур с модификатором `native` либо `transient`:

```unrealscript
const HandleCount = 3;
var native pointer Handle, Handles[HandleCount];
var transient pointer AnimationData;

defaultproperties
{
    Handle=0
    Handles(0)=0
    AnimationData=0
}
```

Размер фиксированного массива — целая константа от 2 до 2048. Поле без скобок
скалярное. Явный `[1]` отвергается, как и в штатном SDK.

В defaults принимается только литерал `0`. Ненулевые адреса, `None`, `0x0`,
`0.0` и выражения вызывают ошибку. Поддерживаются и вложенные defaults структуры:
`Data=(InnerHandle=0,Count=7,InnerHandles[1]=0)`. При текстовом экспорте нулевые
поля могут опускаться; ненулевой указатель вызывает ошибку экспорта.
Поддерживается копирование указателей в функциях, включая элементы массива
и поля структуры: `OtherHandle=Handle; Handles[1]=Handle;`.
Тип указателя не смешивается с `int`, `Object` или `string`. В выражениях разрешена
целая константа со значением ноль, но не переменная `int` даже с нулевым значением.
Для сравнения используйте `PointerEqual(A, B)` или `PointerEqual(A, 0)`.
Обычный `==`, арифметика и репликация указателей запрещены.
Запрет репликации распространяется на вложенные и унаследованные структуры,
элементы массивов и параметры RPC с pointer-полями. Локальный указатель внутри
RPC не передаётся по сети и разрешён. Репликация ссылки на объект не означает
передачу его pointer-хранилища.

Поддерживаются `local pointer Value`, параметры `pointer Value`, `out pointer
Destination` и возвращаемый тип `function pointer`. Модификаторы native/transient
предназначены для полей, а не для локальных переменных и параметров. Массивы
в функциях и optional/coerce-параметры в проверенный синтаксис не входят.

```unrealscript
function pointer Identity(pointer Value)
{
    local pointer Saved;
    Saved = Value;
    return Saved;
}

function Clear(out pointer Destination)
{
    Destination = 0;
}
```

## Проверка

Используйте подготовленную копию совместимого SDK. Выход каждого запуска должен
быть новым каталогом под `uExplorer/local`; оригиналы клиента не изменяются.

- `uExplorer/tests/compile_generation.py`: `--compiler` — каталог System SDK,
  `--launcher` — собранный ucc64.exe, `--sources uExplorer/tests/pointers`,
  `--out` — новый каталог, `--library` — собранный uexplorer_core.dll.
- `int64/tests/pointer_compiler.py`: те же `--compiler`, `--launcher`, `--out`;
  проверяет ошибочные объявления и значения, диагностику и отсутствие пакета.
- `int64/tests/ptr_lifecycle.py`: дополнительно `--probe` — ptr_lifecycle_probe.dll,
  `--metadata-probe` — uexplorer_metadata_probe.exe, `--compiled-package` —
  Generation.u из положительного прогона. Проверяет регистрацию, сохранение,
  загрузку в новом процессе, копирование, независимость экземпляров и выполнение
  скомпилированной функции копирования через `ProcessEvent`.

Логи остаются в выходных каталогах. Успех требует ожидаемого кода завершения,
а не только строки PASS внутри вывода. При несовпадении хеша SDK используйте
соответствующий проверенный SDK; не отключайте проверку.

Расширенный Test прошёл в обоих современных клиентах: 19 PASS, 0 FAIL, 1 SKIP.
Проверены Build и хеши установленных файлов. Проверка ненулевых клиентских адресов
остаётся SKIP. Legacy-профили прошли 12 PASS, 0 FAIL, 2 SKIP и сохраняют общий
пропуск указателей. Подтверждены два нажатия; сохранён итоговый отчёт после них.
Исследование ABI и ограничений: `PTRPROPERTY_RESEARCH.md`.

## Проверка оставшихся ограничений

Исправлено вычисление размера pointer-выражений через объектный контекст.
SDK-прогон подтверждает копирование ненулевого маркера через `Source.Handle`
и нулевой результат `Missing.Handle` при `Missing == None`; roundtrip сохраняет
AST и метаданные. Отрицательный набор расширен до 45 случаев, все PASS.

Доступность native-класса проверяется в отдельном процессе с копией DLL:

```powershell
python -B int64/tests/client_pointer_contract.py --system <client-System> --probe <tools>/ptrproperty_probe.exe --expect-exports present --out uExplorer/local/pointer-contract-modern
python -B int64/tests/client_pointer_contract.py --system <legacy-System> --probe <tools>/ptrproperty_probe.exe --expect-exports absent --out uExplorer/local/pointer-contract-legacy
```

`--system` используется только для копирования DLL. `--probe` — собранный x86
инструмент. `--out` должен быть новым каталогом. В отчёте сохраняются хеши DLL,
инструмента, ожидаемая доступность и фактические экспорты. UIntProperty служит
контролем успешной загрузки. Отсутствие PtrProperty подтверждено для проверенных
Gracia/HF, наличие — для Korean/Japan. Поддержка указателей в текущих legacy
адаптерах отсутствует; для её добавления потребуется отдельная реализация
native-класса и проверка ABI. Замена на int/Object не допускается.

Новый modern-тест получает ненулевые значения из `GFxValue.pValue`, сохраняя
владельцев до завершения проверки. Проверяются разные адреса, копирование через
local/value/out/return, поля, массив и структуру, затем обнуление копий с
сохранностью native-владельцев. Ожидаемый итог нового комплекта: 25 PASS,
0 FAIL, 0 SKIP. Первый прогон дал 23 PASS, 2 FAIL, 0 SKIP: GetInt возвращал
нули. Тест переведён с bare `new GFxValue` на native-пару
`GFxUIScript.AllocGFxValue` / `DeallocGFxValue`; повторная клиентская проверка
ещё требуется. Ошибки первого прогона сохранены в исследовательском отчёте.

Вторая версия с native-выделением дала 22 PASS / 1 FAIL: адреса подтвердились
как ненулевые и разные, но GetInt снова вернул нули. Разбор native-кода обоих
клиентов установил причину: SetInt сохраняет GFx Number (тип 5, double),
GetInt читает только тип 3. Текущая версия использует соответствующий GetFloat
и по-прежнему требует ровно 73/91. Клиентская проверка этой версии ожидается.
