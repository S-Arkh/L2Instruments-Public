# Исправление сохранения при существующем .bak

Ошибка сохранения воспроизведена на прежнем переносимом Windows-модуле:

```text
filesystem error: cannot copy file: File exists [...Interface.xdat] [...Interface.xdat.bak]
```

Проблемный вызов — `std::filesystem::copy_file(..., overwrite_existing)`
в Windows-сборке MinGW. Несмотря на флаг перезаписи, он возвращал ошибку при
существующем файле назначения. На Linux прежний код эту ошибку не воспроизводил.

## Исправление

1. Новый XDAT формируется и проверяется, как прежде.
2. Существующий XDAT копируется в отдельный временный файл бэкапа.
3. В Windows для копирования используется `CopyFileW`, а для замены `.bak` —
   `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`.
4. Только после успешного обновления бэкапа заменяется основной XDAT.
5. При ошибке временные файлы убираются, документ остаётся несохранённым.

Ошибка Win32 теперь содержит числовой код и путь назначения.
Воспроизведённый сбой происходил до замены основного XDAT.

## Проверки

`tests/test_save_regression.py` запускается как через pytest, так и отдельным
unittest в переносимом Windows Python:

- уже существующий `.bak` и три последовательных сохранения;
- путь с кириллицей и пробелами;
- содержимое `.bak` совпадает с предыдущей версией основного файла;
- каталог вместо `.bak`: отказ, исходный файл и каталог сохранены,
  несохранённое состояние документа не потеряно, временные файлы удалены;
- сохранение в новый файл.

До исправления первый тест падал с той же ошибкой. После исправления все три
теста прошли на Windows x64-модуле под Wine 9. Общий Linux/Qt-набор: 37 passed.

Исправление включено в текущий `dist/windows/app/_interface_core.pyd`.
