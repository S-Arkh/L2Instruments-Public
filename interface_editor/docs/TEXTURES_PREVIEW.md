# Предпросмотр и собственные текстуры

## Статический макет

Выберите объект в дереве и вкладку «Предпросмотр». Области независимы.
Режим «Только элемент» показывает выбранный контрол с его children;
«В контексте родителя» — ближайший контейнер с рамкой вокруг выбранного объекта.
Положение рассчитывается в контексте верхнего окна, с учётом относительных
якорей и процентных размеров плюс абсолютные добавки.

Рендерер использует QImage в фоновом потоке. QPixmap и виджеты остаются в GUI.
Старый результат отбрасывается, если изменились выбор, документ, свойства или
каталог ресурсов. Изменения и Undo/Redo обновляют видимый предпросмотр.

Настройки:
- «Вписать», 50/100/200/400%;
- normal/pressed/hover для выбранной кнопки;
- «Обновить» — сбросить кэш ресурсов;
- «Сохранить PNG» — записать готовый макет атомарно через QSaveFile.

Макеты ограничены 2048 пикселями по большей стороне. Шрифты приблизительные.
SysString подключается через меню «Строки»; без таблицы или отсутствующего ID
показывается номер. Динамические контролы показываются заглушками.
HTML/3D/анимация не исполняются. Отдельные alphaMask/colorModify
текстур пока выводятся с замечанием. Список замечаний виден под картинкой.

## Чтение ресурсов

Выберите «Опции → Каталог ресурсов клиента…». Можно указать корень полного
клиента, его System или непосредственно SysTextures. Читаются UTX из выбранной
папки и стандартных SysTextures/Textures.

C++-загрузчик поддерживает plain, Lineage2Ver111/121; RGBA8, P8, G16,
DXT1/DXT3/DXT5. Реальные Button_DF и Windows_DF_Drawer_Bg проверены на HF.
Учитывается Split9: границы не растягиваются как середина текстуры.
Неизвестные оболочки и классы материалов дают замечание/заглушку.

Кэш пакетов ограничен 128 МиБ (один большой пакет допускается отдельно),
кэш QImage — 32 МиБ. Каталог не сканируется и текстуры не декодируются заново
при каждом выборе. После изменения внешних файлов нажмите «Обновить».

## Проект собственных картинок

1. «Текстуры → Менеджер текстур… → Новый проект».
2. Выберите родительский каталог и новое имя пакета, например `L2UI_Custom`.
3. «Добавить изображение»: выберите PNG/TGA, имя и группу.
4. Для размеров не степени двойки предлагается прозрачное дополнение. Растягивание
   исходника не выполняется; логическая область сохраняется в Split9.
5. «Собрать UTX» — собрать все изображения проекта и проверить результат.

```text
L2UI_Custom/
├─ project.json
├─ images/              исходники и нормализованные PNG
└─ output/
   ├─ L2UI_Custom.utx
   └─ build.json
```

Первая версия создаёт HF 125/38, RGBA8 без потерь, один mip, с альфа-каналом.
Размер после дополнения — до 4096×4096; общий бюджет пикселей пакета — 192 МиБ.
Имя пакета/группы/текстуры: латинские буквы, цифры, подчёркивания, без пробелов.
Группа может быть пустой. Имена существующих текстур сохраняются при замене картинки.

Файл UTX — результат сборки, а не исходный проект. Для доработок открывайте
project.json, используйте «Заменить изображение» или добавляйте новые, затем
собирайте пакет заново. GUID проекта стабилен; имена ссылок не меняются.
Исходники прошлых замен и резервные копии сохраняются. Не переименовывайте UTX
вручную: имя участвует в ссылках и оболочке Ver121.

## Назначение и мастер кнопки

Сначала выберите целевой объект в левой или правой области. Используется последняя
выбранная область. Затем в менеджере выберите текстуру и нажмите:

- «Назначить выбранному элементу»: для Button — normalTex/pushedTex/highlightTex,
  для Texture — file, для Window/TextBox — backTex. Пункт «Не менять» сохраняет поле.
- «Создать кнопку с текстурами»: задайте имя, подпись, координаты, размеры и
  текстуры состояний. Кнопка добавляется в children выбранного окна или рядом
  с выбранным контролом. Одна отмена удаляет всю созданную кнопку.

Пакет должен быть собран. Его output подключается к предпросмотру автоматически,
поэтому картинку можно увидеть до установки в игру.
Обработчик нажатия в UnrealScript создаётся отдельно.
Для подписи мастер предлагает прямой текст либо ID из загруженной SysString.

## Установка

Закройте игровой клиент. В менеджере нажмите «Установить в клиент» и выберите
реально используемый игрой SysTextures (или корень полного клиента).
Копируется только собственный пакет. Если файл с таким именем уже существует,
обновление разрешено только при совпадении GUID проекта; чужой/штатный пакет
не заменяется. Предыдущая собственная версия сохраняется как `.utx.bak`.

Результат сборки проверяется независимым чтением через загрузчик пакетов и
сравнением RGBA-пикселей всех текстур. Это не заменяет первое испытание пакета
в игровом клиенте: в build.json явно записано `game_tested: false`.

## Проверки и пример

`examples/L2UI_Custom` содержит три оригинальные PNG-картинки и готовый UTX:
NativeTest_Normal, NativeTest_Pressed, NativeTest_Hover в группе Buttons.

```powershell
.venv\Scripts\python.exe -m pytest tests/test_preview_textures.py -q
.venv\Scripts\python.exe tests/test_native_textures_portable.py
```

Для теста реальных ресурсов задайте `INTERFACE_CLIENT_RESOURCES` путём к полному
клиенту. Для проверки отдельного модуля — `INTERFACE_MODULE_DIR`.
`tools/create_texture_demo.py --out <новая папка>` создаёт демонстрационный проект.
