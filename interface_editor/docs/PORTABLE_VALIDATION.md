# Проверка portable и браузерных профилей

Основа: `05c42c5` с исправлением межпрофильной
подготовки Gracia и инструментами проверки из этого изменения.
Сборки, дистрибутивы и полные копии клиентов размещались отдельно от исходников
и оригинальных клиентов. Сырые журналы, снимки экрана и игровые данные
остались локальными; здесь приведены обезличенные результаты.

## Найденная регрессия

`profiles/gracia/prepare.py` открывал шаблон High Five (`ct26.XDAT`)
документом с каталогом только Gracia (`ct24.XDAT`). После разделения схем
это воспроизводимо приводило к `RuntimeError: Unknown schema`.
Теперь второй документ получает `profile_text('ct26.XDAT')`.
Синтетический тест `gameAddWebWithD3D9/tests/test_browser_schemas.py` проверяет оба профиля,
тождественность результата полному каталогу и сохранение существующего Core.

Тест принадлежит браузерному проекту и использует редактор как зависимость.
Для запуска нужны pytest и собранный `_interface_core` в `interface_editor/app`,
совместимый с выбранным Python и платформой. Клиентские файлы не требуются:
входные XDAT создаются синтетически во временном каталоге.

Из корня репозитория:

```powershell
python -m pytest gameAddWebWithD3D9/tests/test_browser_schemas.py -q
```

Из каталога `gameAddWebWithD3D9`:

```powershell
python -m pytest tests/test_browser_schemas.py -q
```

Путь к модулям редактора тест определяет относительно своего файла;
настройка `PYTHONPATH` для него не требуется.

## Portable Interface Editor

Проверены новая сборка из официальных архивов Python/Qt и обновление копии
исторического дистрибутива с предварительно проверенным манифестом.
Использован уже собранный и протестированный Windows x64 модуль редактора;
кросс-компиляция MinGW в этой проверке не выполнялась.

- Обе сборки: импорты из собственного bundle, совпадение хешей манифеста,
  редактирование, undo/redo, сохранение, JSON, определение схемы и отмена,
  импорт/экспорт пользовательского пакета, сохранение текущего документа
  при неудачном открытии.
- Реальные ct24, ct26, Essence native и Korea native: побайтовый binary
  roundtrip и восстановление исходных байтов через JSON под встроенным Python.
- Оба `Start.cmd` запущены из пути с пробелами и кириллицей: 26 пунктов
  версий, пустой кеш схем при старте, ноль ошибок схем. Временная
  инструментация изолировала настройки и закрывала GUI; затем удалена.
- Обновление удалило старый `schemas.json`, сохранив идентичную резервную
  копию. Повторное `--ui-only` успешно; внешний пользовательский пакет
  сохранился побайтово.
- Финальная проверка манифестов после удаления инструментации успешна.
- Windows pytest: **230 passed, 29 skipped, 20 subtests passed**.

Пример упаковки из корня репозитория (переменные обозначают локальные пути):

```powershell
python interface_editor/tools/package_windows.py --cache $Cache --module $TestedModule --out $Bundle
python interface_editor/tools/finalize_distribution.py $Bundle
& "$Bundle/runtime/python.exe" interface_editor/tools/validate_distribution.py --output $Report --sample "ct26.XDAT=$Sample"
```

`--module` принимает готовый Windows x64 PE; совместимость Python ABI и
зависимостей подтверждается запуском в bundle. Альтернативный существующий
режим `--cxx` требует `--dlltool`. `--sample` можно повторять для разных
профилей. Драйвер запускается под встроенным Python, использует временные
настройки/файлы и по умолчанию Qt offscreen; проверка `Start.cmd` — отдельная.

## Сборки и host-тесты браузера

Предоставленные клиенты уже содержали модифицированные UI/Core-файлы.
Для воспроизводимой сборки использованы совместимые исторические входы
и compiler workspace; результат установлен только в полные тестовые копии.

- `archive/addWeb`, `prototype`, High Five и Gracia: подготовка XDAT
  успешна; все четыре результата побайтово совпали с запуском тех же
  сценариев на полном каталоге. `manifest.verify_xdat()` Gracia прошёл.
- High Five: полная сборка native/UC, упаковка, options и Core VM probes,
  кадры WebView2, навигация, мышь, латиница/кириллица, прокрутка,
  minimize/resume/close и завершение процесса прошли.
- Gracia: сборка UC и упаковка; проверка восстановления — **3259 функций,
  21326 блоков, 0 ошибок**. Native in-process сборка, pipe compatibility,
  полный host frame/input suite и active-browser process exit прошли.
- `build_browser_options.ps1` успешно сформировал оба конечных комплекта.
  В сборках были предупреждения компилятора; ошибок в завершённых сборках нет.

## Проверка внутри настоящих клиентов

Проверены копии Gracia (протокол **152**) и High Five (протокол **268**).
Оба клиента дошли до экрана входа с пересобранными комплектами.
В каждом через игровую кнопку Browser проверены:

1. Отрисовка детерминированной страницы с локального HTTP-сервера.
2. Увеличение счётчика по клику внутри страницы.
3. Ввод цифр и кириллицы при активной русской раскладке.
4. Прокрутка до видимого `Bottom reached`.
5. Сворачивание браузера и восстановление с сохранением позиции прокрутки.
6. Закрытие и новое открытие со сбросом счётчика, ввода и прокрутки.
7. Штатное завершение клиента с открытым браузером.

Оба тестовых клиента закрыты, локальный HTTP-сервер остановлен.
Хеши исходных файлов, заменявшихся в копиях, совпали с резервными копиями
до установки: 6 файлов Gracia и 5 High Five. Оригинальные клиенты не были
целями установки или запуска.

**Граница проверки:** это реальная интеграция на экране входа, без авторизации
и входа персонажем в мир. Навигация, расширенные клавиатурные сценарии,
аудио и popup-поведение подтверждены host-тестами, а не новой игровой сессией.
Исторические отметки «проверено в игре» в документации профилей не означают,
что такой сценарий повторён для этой сборки.
