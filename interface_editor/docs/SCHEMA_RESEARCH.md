# Исследование неизвестных XDAT

**Файл → Исследование схем XDAT** открывает мастер для выбранной в верхней панели
схемы. Он также доступен из результатов неудачного открытия. Работа ведётся над
изолированной копией схемы; текущий редактируемый документ не заменяется.

## Порядок работы

1. Добавьте один или несколько XDAT одной предполагаемой версии. Кнопка
   «Загрузить схему…» позволяет продолжить работу с прежним JSON-черновиком.
2. Нажмите **«Разобрать»**. Справа появятся поля, пути объектов с индексами списков,
   типы, смещения, размеры и результаты условных веток. Выбор поля показывает HEX
   вокруг его начала. Для крупных файлов показаны последние 2000 событий.
3. **«Подобрать изменения»** проверяет вставку 1–8 числовых полей, строк/compact,
   удаление соседних скалярных полей и замену типа около места расхождения.
   Сначала рассматриваются подозрительные значения bool, строк и float. Это
   эвристики, а не ошибки формата: обычное чтение продолжает сохранять такие значения.
4. Гипотеза должна улучшать оценку хотя бы одного образца и не ухудшать остальных.
   Для каждого образца показана тройка: полное чтение без хвоста,
   смещение первой аномалии/ошибки, смещение ошибки. Это **не проценты достоверности**.
5. Выберите гипотезу и нажмите **«Принять гипотезу»**. Схема изменится, после чего
   разбор повторится. Есть отдельная отмена изменений схемы. JSON слева также можно
   править вручную; при правке прежние результаты сбрасываются.
6. Экспортируйте JSON или установите его отдельной пользовательской схемой.
   После установки выберите её при открытии XDAT обычным способом.

Поиск ограничен числом проверок и временем (1–120 секунд). Отмена и лимит времени
проверяются между гипотезами; уже начатый нативный разбор завершается. Общий размер
образцов ограничен 512 МиБ, одного файла — 256 МиБ.

Возможные теги типов около ошибки помогают сопоставлять повторяющиеся структуры.
Они не устанавливают границы объектов: совпадение может встретиться внутри строки.
Необработанный хвост отмечен как `opaque`. Он сохраняется, но не считается
восстановленной структурой. Мастер не пропускает произвольные байты ради успешного чтения.

Автоподбор пока ограничен локальными изменениями скалярных полей. Новые классы
контролов, структуры списков, условия присутствия полей и их смысл требуют ручного
уточнения JSON. Он не восстанавливает произвольную бинарную грамматику с нуля.

## Импорт и экспорт

**Файл → Импорт схемы… / Экспорт схемы…** работают со схемами, а не с JSON-документами
XDAT. Экспорт включает пространство имён выбранной версии и зависимости, в том числе
полиморфные типы. Импорт проверяет язык операций, ссылки, циклы и конфликты полей;
совпадающие с установленными идентификаторы отклоняются без перезаписи.
Для отдельной доработки существующей схемы используйте мастер и установку черновика:
он создаёт независимые идентификаторы.

Пакет сохраняет `format: 1`, `revision`, `status` и, при наличии проверки,
`validation`: размеры и SHA256 образцов, результаты побайтного сравнения, размеры хвостов.
`sample-tested` означает только успешную проверку данных образцов без хвоста;
это не подтверждение семантики полей или работы в игре. Остальные пакеты имеют статус
`draft`. При изменении схемы старые результаты нужно получить заново.

Отчёты для обмена не содержат путей, имён файлов, значений полей, HEX и текстов
исключений. Эти сведения доступны локально в окне исследования. Произвольные
метаданные исходного пакета при переносимом экспорте не копируются.

## Командная строка

После сборки, из каталога `interface_editor`:

```text
python tools/research_schema.py --schema etoa5.XDAT --sample <sample-a.xdat> --sample <sample-b.xdat> --suggest --seconds 20
python tools/research_schema.py --package <draft.json> --sample <sample-a.xdat>
```

`--suggest --apply 0 --output <new-draft.json>` явно принимает гипотезу с индексом 0,
повторно проверяет её и сохраняет новый пакет. Существующий выходной файл не
перезаписывается. Стандартный вывод содержит только переносимый отчёт.

## Essence и контрольные образцы

Прежние поздние схемы расходятся с Essence уже в первом окне. Новые встроенные
профили `essence_native.XDAT` и `korea_native.XDAT`, восстановленные по native-reader,
теперь читают все шесть файлов
Essence/Кореи/Японии до EOF без хвоста. Пройдены roundtrip и проверки изменённых
имён и размеров через собственные native-сериализаторы клиентов. Семантический
аудит всех runtime-значений и визуальная проверка полного клиента ещё не завершены; см.
`ESSENCE_XDAT_RESEARCH.md`. Переименование старой схемы поддержку не добавляет.

Дополнительные реальные образцы High Five и Gracia Epilogue прошли побайтную проверку
по `ct26.XDAT` и `ct24.XDAT` соответственно; у каждого сохранён 20-байтовый хвост.
Native-сериализаторы также приняли изменённые файлы с исходным, заменённым и
удалённым хвостом, останавливаясь на границе полезных данных. На восьми независимых
старых XDAT подтверждена CRC32 по смещению +12 хвоста; смысл остальных слов
ещё уточняется. Схемы HF/Gracia показывают слова распознанного хвоста только для
чтения и сохраняют их без пересчёта: см. `XDAT_LEGACY_TAILS.md`.
Клиентские файлы в репозиторий не включены. Новые автоматические проверки используют
синтетические структуры, включая неизвестное поле, несколько образцов, редактирование,
повторную сериализацию, отмену, импорт/экспорт и работу мастера.

Проверка этой доработки: Windows x64/MSVC — полный прогон 149 passed, 29 skipped,
20 subtests passed; после уточнения валидации и интерфейса — 19 профильных тестов.
Linux — 49 профильных тестов. Новый диагностический путь дополнительно прошёл
побайтную проверку на 27 внешних эталонах прежних хроник.
