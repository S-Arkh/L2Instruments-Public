# Подбор схемы XDAT

При ошибке открытия XDAT редактор в фоне проверяет каждую уникальную установленную
схему. Есть прогресс и отмена (текущая проверка завершается перед отменой).
Проверка включает чтение и побайтное сравнение обратной сериализации с исходником.
Результат не определяет хроники однозначно: совместимых схем может быть несколько.
Схемы с меньшим необработанным хвостом показываются первыми; хвост сохраняется
как байты, а не считается разобранной структурой.

Выберите результат и нажмите **«Переключиться и открыть»**. Текущий документ
заменяется только после успешного открытия. Traceback доступен в **«Подробностях»**.

Если совпадений нет, можно сохранить JSON-отчёт со смещениями ошибок
и SHA256 файла либо создать черновик на основе выбранной схемы.
Порядок кандидатов по смещению ошибки — лишь подсказка для исследования.

Черновик получает собственные идентификаторы типов, включая полиморфные структуры
и зависимости. В Windows он сохраняется в
`%LOCALAPPDATA%/L2Tools/InterfaceEditor/schemas/`; точный путь показывается в диалоге.
Пользовательские схемы загружаются при запуске и перед открытием файла.
Ошибка в пользовательском JSON показывается отдельно; встроенные схемы остаются доступны.

Черновик — редактируемый JSON, а не автоматически восстановленная спецификация.
Измените порядок/типы полей в `records`, затем нажмите
**«Повторить анализ после правки схем»**. Для неизвестного формата могут понадобиться
другие образцы XDAT и сведения о версии клиента. Отчёт можно сохранить отдельно.

Расширенный мастер: **Файл → Исследование схем XDAT**, а также кнопка в результатах
подбора. Трассировка, HEX, гипотезы и импорт/экспорт описаны в
[SCHEMA_RESEARCH.md](SCHEMA_RESEARCH.md). Отчёты для обмена больше не включают пути,
имена файлов, HEX, значения и тексты исключений.

## Проверка Windows-сборки 0.6.0-schema-detection

- Финальный модуль: 39 тестов прошли (34 проверки схем, 3 сохранения, 2 DAT;
  дополнительно 20 DAT-подпроверок).
- Проверены все 27 эталонов, неправильная/неизвестная схема, повреждённые данные,
  несколько совпадений, хвост, отмена, сохранение открытого документа,
  создание изолированного черновика и чтение после ручного изменения его структуры.
- В опубликованном `dist/windows` проверен путь GUI: неверный Interlude для
  High Five → перебор установленных схем → переключение на единственное совпадение ct26.XDAT
  → успешное открытие.
- Общий запуск до финальной статической линковки: 144 passed, 2 skipped,
  1 failed. Ошибка `test_strings_edit_assign_preview_and_independent_languages`
  (сравнение пикселей предпросмотра в Windows/offscreen) воспроизведена также
  на прежней, неизменённой поставке.
- Причина этого сбоя впоследствии установлена: Qt/offscreen в Windows не находил
  системные шрифты, поэтому разные подписи давали одинаковое изображение.
  `tests/conftest.py` задаёт `QT_QPA_FONTDIR` из `%WINDIR%/Fonts` до создания
  QApplication. Обе проверки SysString проходят и с обычным Windows-плагином,
  и в offscreen с доступными шрифтами.
- Модуль собран MSVC x64 с `CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded`;
  зависимости DLL: `python312.dll` и `KERNEL32.dll`.
- Предыдущая поставка сохранена обновляющим инструментом в `dist/updates/`.
