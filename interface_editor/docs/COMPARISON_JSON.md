# Две панели: сравнение, прокрутка и JSON

## Прокрутка и выравнивание

В режиме «Опции → Синхронная прокрутка свойств» используется один вертикальный ползунок
справа от обеих областей. Прокрутка колёсиком в таблице синхронизируется с ним.
Выравнивание строк строится по объединению имён активных свойств: сначала порядок
левой стороны, затем поля, имеющиеся только справа. Пустые строки не редактируются.

Если синхронизация отключена, таблицы прокручиваются отдельно. При включённом
сравнении выравнивание сохраняется. Без сравнения и синхронизации каждая таблица
показывает только собственные активные поля.

## Переходы ← / →

Кнопки открывают уже существующий выбранный объект на другой стороне. Это не
копирование его значений в другой объект и не дублирование в XDAT. При переходе
раскрываются родители и дерево прокручивается к объекту. Совместимый завершённый
поисковый фильтр сохраняется; скрывающий объект или ещё выполняющийся — сбрасывается.

## Цвета сравнения

Сравниваются свойства двух выбранных объектов, не их поддеревья:

- оранжевый — разные значения или типы, включая разные enum-типы;
- красный — нет активного поля на одной из сторон;
- обычный фон — совпадение.

Окрашиваются названия, значения и выпадающие списки. Обновление выполняется после
выбора другого объекта, правки и Undo/Redo. Неактивное условное поле помечается
как отсутствующее в текущем представлении, с пояснением в подсказке.

## Поиск с соседями

Пункт «Опции окна → Показывать соседей и их ветки» показывает содержимое родителя совпавшего
элемента вместе со всеми раскрываемыми подветками. Например, поиск btnCredit
позволяет увидеть остальные кнопки в children LoginMenuWnd.
Совпадения выделены жирным. Левая и правая галочки независимы.

Если совпало само окно верхнего уровня, его соседями являются остальные окна
списка windows — в этом случае видимой может стать большая часть документа.
Это не заставляет Qt создавать все узлы: представление остаётся ленивым.

## Формат JSON версии 1

```json
{
  "format": "interface-editor-document",
  "version": 1,
  "schema": "ct26.XDAT",
  "tree": {
    "type": "ct26.XDAT",
    "tag": "",
    "fields": {}
  }
}
```

Это иллюстрация заголовка, не полный документ для импорта. Экспорт записывает
все поля, списки и вложенные объекты выбранной схемы, включая неактивные поля.

У обычного значения:

```json
"size_absolute_width": { "value": 120, "raw": "62000000" }
```

Редактируйте **value**. В примере raw ещё содержит прежнюю ширину 98, но при
импорте будет записана новая ширина 120. Исходные байты используются только если
их декодированное значение совпадает с value. Это позволяет сохранять старое
бинарное представление без потерь и одновременно применять ручные изменения.

У списка — `items` с объектами и `prefix` с исходным счётчиком. Добавление или
удаление элементов items автоматически приводит к пересчёту счётчика при записи.
Типы элементов должны соответствовать списку. `object` хранит вложенный объект.
`_tail.raw` хранит неизвестный хвост в hex; не меняйте его без понимания формата.

Поле `tag` сохраняет исходную кодировку имени полиморфного типа. Поля `raw`,
`prefix`, `tag` можно не указывать для канонической записи; `_tail.raw` нужен
для сохранения самого хвоста. Некорректный hex отклоняется.

Числа и строки должны иметь правильный JSON-тип. `bool` в исходном XDAT хранится
как целое: 1/0/-1; другие исходные значения также сохраняются. Неизвестные enum
не заменяются автоматически. Для нечисловых float используются строки `NaN`,
`Infinity`, `-Infinity`, исходный битовый шаблон сохраняется через raw.

Формат не содержит runtime-ID узлов: они формируются заново при импорте.
Имена полей должны точно соответствовать схеме. Копирование объекта в items
не обновляет автоматически ссылки на него в других полях или UnrealScript.

## Проверка импорта и сохранение

Импорт создаёт отдельный документ и проверяет типы, диапазоны, структуру, затем
выполняет бинарную сериализацию и повторное чтение. Открытый документ заменяется
только при успехе. При ошибке текущие данные остаются доступны.

После JSON-импорта документ считается несохранённым и не имеет пути назначения
XDAT. «Сохранить» открывает диалог выбора нового файла, а не перезаписывает JSON.
Экспорт JSON не сбрасывает признак несохранённых изменений. При перезаписи
существующего JSON создаётся его `.bak`, используя исправленный механизм сохранения.

Проверки: `tests/test_json.py`, расширенный `tests/test_gui.py`,
`tools/validate.py --json-roundtrip`. Для проверки только пользовательского XDAT:

```powershell
$ClientXdat = Read-Host 'Полный путь к Interface.xdat целевого клиента'
.venv\Scripts\python.exe tools/validate.py --client $ClientXdat --client-only --json-roundtrip --report docs/json-client-check.json
```
