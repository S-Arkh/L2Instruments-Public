# Разработка и проверка

## Схемы

Все определения находятся в schemas/schemas.json, эталоны — в tests/fixtures.
После изменения схем выполняйте весь roundtrip-набор, а не только High Five.
Внешний редактор и его исходники для сборки и запуска не требуются.

## Ядро

`Document` владеет данными и выдаёт стабильные ID. Qt-модель получает только
строки непосредственных потомков, а панель — свойства одного узла. Оба дерева
используют общую модель с независимыми proxy-фильтрами и selection model.
Фильтр получает совпадения и пути к их предкам из C++.

Бинарный код сохраняет сырые байты неизменённых значений. Отредактированная строка
записывается ASCII либо UTF-16LE; длина — compact integer. Цвета отображаются
сырыми 32-битными числами: `color` = AARRGGBB, `rgba` = AABBGGRR.
Строки не допускают встроенного NUL. Поля, влияющие на условную структуру,
переключают активные свойства; прежние значения сохраняются в истории/документе.

Длительные вызовы освобождают GIL. C++-документ защищён mutex, команды выполняются
в фоне; UI блокирует редактирование на время записи/команды. Результаты старого
поиска не применяются после нового запроса или замены документа.

Отдельные объекты нельзя пропустить в незнакомой схеме: формат не содержит
универсальной длины каждого контрола. Ошибка содержит путь поля и byte offset.

## Проверки

```powershell
.venv\Scripts\python.exe -m pytest tests -q
$ClientXdat = Read-Host 'Полный путь к Interface.xdat целевого клиента'
.venv\Scripts\python.exe tools/validate.py --client $ClientXdat --report docs/validation-local.json
.venv\Scripts\python.exe tools/capture_ui.py $ClientXdat --output docs/editor-local.png
```

`validate.py` читает эталоны/клиент, сравнивает roundtrip в памяти, измеряет
открытие и поиск, записывает JSON-отчёт. Входные XDAT не изменяет.
`capture_ui.py` запускает Qt offscreen, открывает клиент и делает снимок двух
панелей. Это не проверка фактического Windows desktop или игрового UI.
Параметры `--compare --right-query TextBox` показывают режим сравнения разных типов.
`--language ru` / `--language en` выбирает язык снимка интерфейса.

`validate.py --json-roundtrip` дополнительно проверяет побайтное равенство после
экспорта/импорта JSON. `--client-only` ограничивает проверку указанным клиентом.
Переменная `INTERFACE_MODULE_DIR` позволяет тестировать отдельный собранный модуль,
включая Windows .pyd в переносимом Python. Схемы и эталоны берутся из проекта.

## Переносимая Windows-сборка

`tools/package_windows.py` — кросс-сборка из Linux:

```text
python tools/package_windows.py --cache <каталог архивов> --cxx <x86_64-w64-mingw32-g++> --dlltool <x86_64-w64-mingw32-dlltool> --out dist/windows-new
```

В cache нужны официальные python-3.12.10-embed-amd64.zip, Python-3.12.10.tgz,
pyside6_essentials-6.12.0-cp310-abi3-win_amd64.whl,
shiboken6-6.12.0-cp310-abi3-win_amd64.whl.
В Python сборщика — pybind11 и nlohmann_json. Загрузки скрипт не выполняет.
`--resume` разрешает повторить только незавершённую упаковку без BUILDINFO.json.

Хеши исходных архивов и модуля записываются в BUILDINFO.json.
Для обновления уже проверенным .pyd используется `tools/update_distribution.py
--module <файл.pyd> --revision <имя-версии>`. Он сверяет прежний комплект с
manifest, сохраняет старые файлы приложения в dist/updates и обновляет ядро,
Python-файлы, схемы и manifest. Редактор необходимо перезапустить после обновления.
Для изменений только Python-интерфейса используется `--ui-only` вместо `--module`:
проверяется неизменность исходников ядра, сам .pyd не заменяется.
`tools/finalize_distribution.py` добавляет README, лицензии header-only библиотек
и фиксирует хеши Python-файлов/схем. Он проверяет совпадение упакованного UI с
исходниками, но сам не объявляет сборку протестированной.

## Границы текущей версии

- Статический предпросмотр поддерживает базовые контролы High Five и UTX-текстуры;
  интерактивного редактирования на холсте пока нет. SysString подключается отдельно.
- Нет автоматического определения или конвертации версии XDAT.
- Нет автоматического переименования ссылок в других полях и UnrealScript.
- Поиск не строит весь Qt-граф: автоматически раскрывает до 200 совпадений.
- Структурные команды могут сбросить Qt-модель с восстановлением выбора/веток;
  ввод поисковой строки этого не делает.
- Бэкап `.bak` содержит предыдущую версию файла и обновляется при следующем сохранении.

Проекты текстур и предпросмотр: [TEXTURES_PREVIEW.md](TEXTURES_PREVIEW.md).
Новый модуль называется `_interface_core`; CMake-проект — InterfaceEditor.

DAT-слой: `core/dat.cpp`, публичный API в `core/dat.hpp`. OpenSSL/zlib загружаются
по стабильному C ABI; Lineage-фрейминг и таблицы реализованы собственным кодом.
`test_dat_portable.py` запускается во встроенном Windows Python с
`INTERFACE_MODULE_DIR`, без pytest/Qt. `tools/verify_dat_reference.py` — необязательная
проверка совместимости с отдельно предоставленным консольным кодеком.
`tools/create_sysstring_test.py <исходник> --out <новая папка>` создаёт тестовые
DAT-копии без изменения источника. [Подробности SysString](SYSSTRING.md).
