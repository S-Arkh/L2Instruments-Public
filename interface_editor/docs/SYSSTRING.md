# SysString: чтение, редактирование и сохранение

`<HF_CLIENT>` в примерах — корень установленного клиента High Five;
замените это обозначение своим путём.

## Независимые параметры

1. Схема XDAT описывает дерево интерфейса.
2. Схема SysString описывает таблицу записей.
3. Заголовок DAT выбирает оболочку и алгоритм шифрования.
4. Профиль ключей выбирается отдельно для RSA.
5. Язык текста — подпись загруженной таблицы; он независим от языка меню редактора.

Оболочка определяется по самому файлу, не по хроникам открытого XDAT.
Сейчас реализована общая схема `id-ascf-v1`: uint32 количества записей, затем
пары uint32 ID + ASCF. Такая структура подтверждена описаниями C3, Interlude,
Freya, High Five, Lindvior, Helios и Grand Crusade. Это не универсальный редактор
всех DAT: неизвестная структура требует отдельного обработчика схемы.

## Использование

1. Меню **Строки → Редактор строк… → Открыть DAT…**.
2. Для проверенного файла выберите:

```text
<HF_CLIENT>\system\sysstring-e.dat
```

3. Схема — SysString uint32 ID + ASCF; язык — English;
   ANSI — cp1252; профиль чтения — «Авто (по заголовку)».
4. Программа покажет `Lineage2Ver413 / l2encdec`, 2328 записей.
   В этой версии файла есть 6000 → Test Button.
5. В предпросмотре появятся Credit, Options, Replay и остальные найденные подписи.

Можно открыть несколько языковых файлов. Активная таблица выбирается в редакторе
строк или **Строки → Язык текста**. Загруженные файлы и активный язык запоминаются
и восстанавливаются при следующем запуске.

Если ID действительно отсутствует в выбранном языке, остаётся `#номер` и
замечание `ID not found`. Если таблица не подключена — `localized string is not loaded`.
При смене языка/редактировании строки предпросмотр обновляется без повторного
чтения текстур и без изменения XDAT.

## Добавление и назначение

- «Добавить строку»: предлагается свободный ID с учётом всех загруженных таблиц.
- Текст вводится обычной строкой, **без** служебного `a,` и завершающего `\0`.
- «Все загруженные языки» позволяет сразу ввести отдельные переводы одного ID.
- «Переводы строки» редактирует/добавляет переводы уже существующего ID.
- Undo/Redo в редакторе строк относятся к текущей языковой таблице.
- «Назначить выбранному элементу» устанавливает ID в выбранное поле объекта XDAT.
  Для buttonName очищается buttonNameText, для sysstring — прямое поле text.
- В таблице свойств у известных ID-полей есть контекстная команда выбора SysString.
- Мастер новой кнопки поддерживает «Прямой текст» и «SysString».

Изменения XDAT и DAT учитываются отдельно. Экспорт/сохранение XDAT **не сохраняет
SysString автоматически**. Несохранённые таблицы отмечаются звёздочкой; закрытие
программы проверяет оба вида изменений. Закрытие окна строк не уничтожает таблицы.

## Кодеки

| Оболочка | Чтение | Запись |
|---|---|---|
| plain | Явный режим «Без оболочки» | Да |
| 111 | XOR 0xAC | Да |
| 120 | Позиционный XOR | Да |
| 121 | XOR по имени файла | Да; штатное ASCII-имя, каталоги могут быть Unicode |
| 211/212 | Blowfish, два ключа | Да |
| 411–414, l2encdec | RSA + zlib | Да |
| 411–414, original-* | Оригинальные профили ключей | Только неизменённая копия; обратных ключей нет |
| custom-* для 41x | По явно импортированному профилю | Если указан encode_exponent |

У 211/212 учтены два варианта: дополнение до восьми байт и старый режим
`blowfish-partial`, оставляющий неполный конечный блок незашифрованным.
В стандартной схеме отделяются известный SafePackage-хвост и padding. Если
невозможно уверенно разделить неизвестный хвост и padding, запись блокируется.

Режим по умолчанию — **исходная оболочка и исходный профиль**. Смена формата или
RSA-профиля выполняется явно. Программа не меняет ключи клиента и не заменяет
неизвестную оболочку на 413. Заголовки вне реестра отклоняются с диагностикой.

Для оригинальных RSA-профилей реализовано чтение, но в текущем наборе нет
реальных оригинально зашифрованных 411–414 эталонов. Их нельзя считать проверенными
на всех клиентах лишь по наличию реализации. Проверенный пользовательский DAT
использует **l2encdec**, а не оригинальный профиль 413.

Схема, оболочка и язык интерфейса не привязаны друг к другу. Доступные ANSI-кодировки:
cp1252, cp1251, cp949, cp932, cp936, cp950, UTF-8 и Latin-1.
Неизменённые ASCF сохраняют исходные байты; новые не-ASCII строки пишутся UTF-16LE.

## Сохранение и дополнительные данные

Сначала DAT строится в памяти, затем расшифровывается и разбирается для проверки.
Только после совпадения payload выполняется запись временного файла, обновление
`.bak` и замена назначения. Ошибка не сбрасывает несохранённое состояние.

В проверенном файле внутренний хвост — 13 байт ASCF-маркера SafePackage.
Он сохраняется. Внешний 20-байтовый footer содержит CRC32 от заголовка и шифротекста;
CRC проверяется при чтении распознанного footer и пересчитывается при записи.
Поддерживаются файлы без footer. Сам шифротекст после пересборки может отличаться
из-за сжатия; записи, порядок, исходные строки и дополнительные данные сохраняются.

## Пользовательский RSA-профиль

«Импорт профиля ключей…» читает JSON с полями name (начинается с custom-), version
(411..414), modulus (256 hex-цифр), decode_exponent и необязательным encode_exponent.
Без encode_exponent профиль предназначен только для чтения. Это профиль ключей
для известной структуры 41x, не загрузчик произвольных криптоалгоритмов.

## Реализация и проверки

DAT-оболочки, блоки, схема SysString и сохранение реализованы в `core/dat.cpp`.
Приложение не запускает L2FileEdit/l2encdec. Для математических примитивов используется
OpenSSL 3 из CPython, для сжатия и CRC — zlib. Windows-зависимости находятся в
runtime; для сборки из исходников zlib1.dll приложена в third_party/windows.
В Linux используются системные libcrypto.so.3, libz.so.1 и iconv.

Выполнена взаимная проверка с отдельным консольным кодеком для всех девяти
заголовков: native → reference и reference → native. Это тест разработчика,
не зависимость программы. Исторический отчёт `dat-reference.json` остаётся
в рабочем дереве разработки; проверку можно повторить через `tools/verify_dat_reference.py`.

Тесты: `test_dat.py`, `test_sysstring_gui.py`, `test_dat_portable.py`.
Windows-модуль дополнительно проверяется переносимым Python без pytest/Qt.

## Тест в клиенте

В `examples/sysstring_test` находятся две отдельно созданные копии:
- sysstring-e-roundtrip.dat — те же записи после сохранения нашим кодером;
- sysstring-e.dat — добавлен 6001 → Interface Editor Test, остальные записи сохранены.

Они прошли повторное чтение и проверки. **Сохранение нашим кодером ещё требуется
подтвердить в игре.** Для теста сохраните прежний DAT, установите тестовый
sysstring-e.dat при закрытом клиенте и назначьте кнопке ID 6001.
