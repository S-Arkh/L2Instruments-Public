# Ручной выпуск Interface Editor для Windows x64

Workflow: `.github/workflows/release-interface-editor.yml` — **Release Interface Editor**.
Сборка запускается только через `workflow_dispatch`. Обычные push/PR по-прежнему
проверяет отдельный CI `Build and test`.

## Запуск из интерфейса GitHub

Файл workflow должен сначала попасть в основную ветку репозитория.
Пользователь с правом записи открывает **Actions → Release Interface Editor →
Run workflow** и выбирает:

- **Branch** — ветку, исходники которой нужно выпустить;
- **version** — `X.Y.Z`, например `0.6.0`, либо `0.6.0-rc.1`;
- **prerelease** — предварительный выпуск (включено по умолчанию).

Версии с суффиксом требуют `prerelease=true`. Номер относится к выпуску
portable; workflow не изменяет версию в исходниках приложения.
Для первого запуска рекомендуется `0.6.0-rc.1`.

После успешных проверок появится выпуск **Interface Editor <version>** с тегом
`interface-editor-v<version>` и файлами:

```text
InterfaceEditor-<version>-windows-x64.zip
SHA256SUMS.txt
```

Выпуски доступны в **Releases** справа на странице репозитория, если раздел
включён в настройках отображения. Предварительный выпуск не помечается Latest.
В приватном репозитории скачивание доступно только пользователям с доступом.

Распакуйте архив целиком и запустите `Start.cmd`. Установленные Python, Qt и
средства разработки не нужны. Целевая система — Windows 10/11 x64.
Проверить архив можно в PowerShell:

```powershell
Get-FileHash ./InterfaceEditor-0.6.0-rc.1-windows-x64.zip -Algorithm SHA256
```

Сравните хеш с `SHA256SUMS.txt` из того же выпуска.

## Что проверяется перед публикацией

1. Формат версии, полный SHA исходного коммита, отсутствие существующего тега/выпуска.
2. Чистый checkout, проверка публикационных файлов, MSVC x64 сборка и pytest редактора.
3. Загрузка embedded Python 3.12.10 и Qt Essentials/shiboken 6.12.0 из официальных
   источников; SHA256 сверяются с `tools/portable_inputs.json`, включая кешированные файлы.
4. Упаковка через `package_windows.py --module`, проверка лицензий/хешей через
   `finalize_distribution.py`. MSVC runtime из Qt wheel размещается рядом с Python.
5. Создание ZIP, распаковка в каталог с пробелами и кириллицей, запуск
   `validate_distribution.py` именно встроенным Python, с очищенными PATH/Python/Qt
   настройками. Проверяются импорты, редактирование, история, JSON, определение
   схемы, отмена и пользовательские пакеты.
6. Запуск настоящего `Start.cmd` с Qt offscreen, временной инструментацией и
   изолированными настройками; проверка меню, ленивого кеша и ошибок схем.
7. Удаление инструментации и сравнение всех файлов распакованного архива с манифестом.
8. Повторная проверка SHA256 ZIP в отдельной задаче публикации.

`BUILDINFO.json` содержит версию, исходный SHA, хеши входных архивов и файлов
комплекта. Сам `BUILDINFO.json` покрывается хешем ZIP. Клиентские данные, рабочие
каталоги разработчика, сырые журналы и локальные настройки в ZIP не включаются.
Проверки на реальных игровых файлах в Actions не выполняются.

## Ошибки и повторный запуск

При ошибке сборки или проверки выпуск не публикуется. Сначала создаётся черновик,
затем загружаются файлы, и только после успеха выпуск становится опубликованным.
Существующие теги и выпуски не перезаписываются; параллельные запуски одной версии
сериализованы. Если публикация оборвалась, проверьте черновик и тег вручную;
для нового запуска можно выбрать новую версию. Повторный запуск задания
публикации не использует `--clobber`.

Права `contents: write` есть только у задачи публикации. Используется штатный
`GITHUB_TOKEN`, личный токен не нужен. Сборочные артефакты Actions хранятся один
день; опубликованные файлы Releases от этого срока не зависят.

## Обновление зависимостей

Согласованно обновляйте `requirements-release.txt`, `tools/portable_inputs.json`,
версии в `tools/package_windows.py` и Python в workflow. Контрольные суммы должны
быть проверены при обновлении lock-файла, а не автоматически заменены при ошибке
скачивания. После обновления нужен новый предварительный выпуск и его проверка.
