# Interface Editor — C++ + Python

Сборка и запуск в Windows, все реализованные функции редактора и результаты
редактирования в игре проверены. Scryde не входит в подтверждённые игровые
интеграции: запуск доработок не удался либо исследования прекращены.

Настольный редактор с C++-ядром и Python/PySide6-интерфейсом.
Две независимые области показывают один документ: отдельные поиск, выбор,
раскрытие веток, свойства и статический предпросмотр.

## Запуск в Windows

Пути программы указаны относительно каталога `interface_editor` в репозитории.
`<HF_CLIENT>` — корень установленного клиента High Five;
подставьте его фактическое расположение.

Сначала выполните сборку по [README](README.md), затем запустите **`run.cmd`**.
Готовый `dist/windows` не включён в Git. Локально подготовленный переносной
комплект запускается через `dist/windows/Start.cmd` и переносится целиком.
Целевая ОС — Windows 10/11 x64 с системными API ICU, используемыми Qt.

1. Выберите хроники в верхней панели (для текущего клиента — **High Five**).
2. Выберите **Файл → Открыть** и откройте `<HF_CLIENT>\system\Interface.xdat`.
3. Слева найдите `btnCredit`, справа — другой элемент для сравнения.
4. Выберите объект: рядом появятся его свойства.

Список версий задаёт схему **следующего открытия**. Уже открытый документ
сохраняется в той схеме, в которой прочитан; это не конвертер между хрониками.


## Меню и язык (0.3.0)

- **Файл** на месте прежней кнопки «Открыть»: Открыть, Сохранить,
  Сохранить как, Открыть JSON, Экспорт JSON. Горячие клавиши сохранены.
- **Опции**: синхронная прокрутка, изменение значений свойств колёсиком,
  **Язык → Русский / English**.
- **Опции окна** под поиском каждой панели: «Показывать соседей и их ветки».
  Левая и правая настройки независимы.

Изменение значений колёсиком **по умолчанию выключено**. Колесо над выпадающим
списком или числовым редактором прокручивает таблицу, а не редактирует XDAT.
При включении соответствующей опции возвращается стандартная реакция редактора
значения на колесо. Клавиатура и выбор мышью продолжают работать в обоих режимах.

Язык переключается сразу, с сохранением выбранных объектов, фильтров, прокрутки
и несохранённых изменений. Настройки запоминаются. Имена полей, типов, enum и
содержимое XDAT остаются исходными.
Подробности настроек и защиты колёсика: [docs/MENUS_LANGUAGE.md](docs/MENUS_LANGUAGE.md).

## Предпросмотр и пользовательские текстуры (0.4.0)

В каждой области есть независимые вкладки **«Свойства» / «Предпросмотр»**.
Для High Five отображаются Button, Texture, TextBox, Window и ScrollArea.
Есть режим родительского окна, масштабирование, состояния кнопки и экспорт PNG.
Пока открыт предпросмотр, общая прокрутка свойств скрывается.

Через **Опции → Каталог ресурсов клиента…** укажите каталог с SysTextures/Textures.
Выберите `<HF_CLIENT>`; ресурсы подключаются отдельно.

Если ресурсы отсутствуют, рисуются подписанные заглушки. Для настоящих подписей
откройте SysString через меню «Строки». Для отсутствующих ID остаются `#номер`.
Это статический макет,
а не исполнение игрового UI: шрифты и динамические элементы могут отличаться.


## SysString и DAT (0.5.0)

**Строки → Редактор строк…**: открыть DAT, выбрать язык текста, искать по ID/тексту,
добавить/изменить строку и сохранить DAT. Поддерживаются стандартные оболочки
111/120/121, 211/212 и 411–414; схема таблицы выбирается отдельно от XDAT.
Для RSA отдельно указываются профили ключей с разными возможностями чтения/записи.

Пример входного файла: `<HF_CLIENT>\system\sysstring-e.dat`.
Профиль чтения — «Авто», кодировка — cp1252. Язык подписей независим от языка меню.

Предпросмотр использует текущую таблицу, включая несохранённые изменения.
Мастер кнопки поддерживает выбор между прямой подписью и SysString ID.
Сохраняйте изменения DAT отдельно от XDAT. Инструкция: [docs/SYSSTRING.md](docs/SYSSTRING.md).


Меню **Текстуры → Менеджер текстур…** позволяет создать отдельный проект,
добавлять/заменять PNG и TGA, собирать собственный UTX и устанавливать его в
SysTextures. Назначение текстур выбранному объекту и создание кнопки выполняются
как одна команда Undo/Redo. Исходные клиентские пакеты не используются как выход.

Создайте собственный проект и выходной UTX локально. Чтение, сравнение пикселей
и применение результатов в игре проверены в исходном проекте.
Инструкция: [docs/TEXTURES_PREVIEW.md](docs/TEXTURES_PREVIEW.md).

## Переименование

Текущий каталог — **interface_editor**, приложение — **Interface Editor**,
нативный модуль — **_interface_core**. Настройки предыдущего имени автоматически
переносятся; ранее экспортированные JSON-документы остаются читаемыми.
Если использовался старый ярлык, направьте его на новый `run.cmd`.

## Сопоставление двух областей и JSON

- **Опции → Синхронная прокрутка свойств** — общий вертикальный ползунок справа.
  Колёсико над любой таблицей перемещает обе. Поля выравниваются по имени,
  строки имеют одинаковую высоту. Прокрутка деревьев остаётся независимой.
- **Слева → направо / Справа → налево** — открыть тот же выбранный объект
  на другой стороне. XDAT не изменяется. Фильтр принимающей стороны сбрасывается,
  если он мешает показать объект или его поиск ещё не завершён.
- **Сравнить** — оранжевые строки означают разные значения/типы, красные —
  отсутствие активного поля на одной стороне. В пустой ячейке показано «Нет поля»,
  а подсказка различает отсутствие свойства и неактивность при текущих флагах.
- **Файл → Экспорт JSON** — сохранить весь текущий документ, включая несохранённые
  изменения. Фильтр дерева не ограничивает выгрузку.
- **Файл → Открыть JSON** — загрузить документ обратно; версия XDAT берётся из JSON.
  После импорта обычное сохранение предложит новое имя XDAT.
- **Опции окна → Показывать соседей и их ветки** — независимая галочка каждой
  области. Найденные элементы выделены жирным; соседние элементы и их дочерние ветки
  остаются доступны для раскрытия. Счётчик показывает только совпадения.

Настройки синхронной прокрутки, сравнения и соседей запоминаются между запусками.
Подробности и редактирование JSON: [docs/COMPARISON_JSON.md](docs/COMPARISON_JSON.md).

## Возможности

- Ленивое дерево: объекты представления создаются по мере раскрытия веток.
- Поиск по имени/типу в C++ без пересоздания всего дерева, задержка ввода 180 мс.
  Регистр ASCII не учитывается; Unicode-текст ищется как задан. Автораскрытие
  ограничено первыми 200 совпадениями, остальные доступны через ветки дерева.
- Строки, целые, float, enum, nullable bool и сырые значения цветов.
- Неизвестные enum/bool отображаются и сохраняются без автоматической нормализации.
- Изменения выбранного объекта видны с обеих сторон.
- Добавление, дублирование, удаление и копирование в другую совместимую ветку.
- Общая история Undo/Redo, индикатор несохранённых изменений.
- Фоновые открытие, поиск, команды и сохранение; индикатор выполняемой операции.
- Сохранение через временный файл: сериализация, проверка повторным чтением,
  резервная копия `<имя>.xdat.bak`, затем замена целевого файла.

Чтобы добавить кнопку, раскройте нужное окно и выберите его список **children**,
затем «Добавить» → `ct26.Button`. Для копирования между областями выделите объект,
нажмите «Копировать», на другой стороне выберите список children и нажмите
«Вставить копию». Дублированная кнопка получает уникальное имя с `_copy`.

Имена элементов должны соответствовать обработчикам UnrealScript. Редактор
изменяет XDAT; обработчики кнопок в Interface.u создаются отдельно.

## Схемы

При ошибке открытия автоматически запускается **подбор совместимой схемы** с
предложением переключиться. Если совпадений нет, доступны отчёт анализа и создание
пользовательского JSON-черновика на основе существующей схемы.
Подробности: [docs/SCHEMA_DETECTION.md](docs/SCHEMA_DETECTION.md).

Доступны **24 позиции меню / 23 схемы** — от Interlude до Salvation.
Они включены в `schemas/schemas.json` (1218 записей, включая вложенные структуры).
Runtime полностью C++; для запуска и сборки достаточно содержимого этого проекта.

**Все 27 внешних эталонных файлов** прошли побайтный roundtrip в исходном проекте;
игровые фикстуры не включены в Git, автономные тесты используют синтетические данные.
Отдельных эталонов для `etoa2_2_ru` и `etoa2_3_ru` нет: эти схемы
перенесены, но их проверка на реальных файлах ещё нужна.
Модифицированные XDAT частных клиентов могут требовать отдельной схемы.

## Структура

```text
core/          C++: XDAT, UTX, декодирование текстур, команды и Undo/Redo
bindings/      pybind11 — Python API ядра
app/           Python/PySide6: свойства, предпросмотр, менеджер текстур
schemas/       переносимые декларативные схемы
tests/         тесты; игровые эталоны подключаются отдельно
tools/         проверки и упаковка
docs/          инструкции
dist/windows/  локально создаваемый переносимый комплект (не в Git)
```

## Сборка из исходников

Windows: Python 3.12 **x64**, VS2022 с C++ workload. Из этого каталога:

```powershell
.\build.ps1
.\run.cmd
```

`build.ps1` создаёт `.venv`, устанавливает зависимости, собирает C++ через CMake
и запускает тесты. После локальной сборки `run.cmd` предпочитает её переносимому
комплекту. `dist/windows/Start.cmd` всегда запускает именно переносимую версию.

Linux (нужны компилятор C++17 и заголовки установленного Python):

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
.venv/bin/python -m cmake --build build
.venv/bin/python -m pytest tests -q
.venv/bin/python app/main.py
```

Команды инструментов и ограничения: [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
