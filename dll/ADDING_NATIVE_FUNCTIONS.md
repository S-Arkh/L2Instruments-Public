# Добавление функций через extensionL2.cpp

Подготовка теперь включает обязательные loader/VM-пробы и manifest комплекта.
После изменения инструментов сначала пересоберите DLL и EXE через `build.ps1`.
Профили других Core и проверка установки: [CORE_PROFILES.md](CORE_PROFILES.md).

Рабочий файл относительно каталога `dll` (все команды ниже выполняются из него):

```text
src\extensionL2.cpp
```

Теперь реализации, имена UnrealScript и native-индексы задаются **в одном файле**.
Сигнатуры UC выводятся из C++ типов автоматически. Проверка native-индексов
остальных клиентских DLL/пакетов не входит в обязательный сценарий.

## Как это работает

```text
extensionL2.cpp: C++ функции/методы + L2_NATIVE(...)
    ↓ сборка
ExtensionL2.dll
    ├─ extension_bindings.exe читает описания → ExtensionL2API.uc
    └─ при старте клиента ExtensionL2Attach регистрирует весь список в Core

ExtensionL2API.uc → ucc64 → ExtensionL2.u → вызовы из Interface.uc
```

DLL называется `ExtensionL2.dll`, экспорт подключения — `ExtensionL2Attach`.
**При переходе со старого имени требуется один раз установить обновлённую
патченную Core.dll из dist/profiles, соответствующую вашему клиенту.**
Для Clear HF используется dist/profiles/Clear_hf. Затем этот патч подходит для всего списка функций.
Он подключает модуль один раз; код
регистрации внутри DLL сам обходит список. Скрипт не переписывает Core под каждую
новую функцию и не встраивает C++-исходник в Core.dll.

## Пример добавления функции

В extensionL2.cpp, перед функцией `l2ext::bindings`, напишите:

```cpp
static std::int32_t GetExtensionVersion()
{
    return 1;
}
```

В массив `items[]` того же файла добавьте:

```cpp
L2_NATIVE(4007, GetExtensionVersion, &GetExtensionVersion),
```

После сборки генератор создаст в ExtensionL2API.uc:

```uc
native(4007) static final function int GetExtensionVersion();
```

Вызов из UC:

```uc
local int Version;
Version = class'ExtensionL2API'.static.GetExtensionVersion();
```

Имена параметров в сгенерированной декларации — Arg0, Arg1 и т.д. На порядок
аргументов и их значения это не влияет. `ExtensionL2API.uc` редактировать вручную
не нужно: он обновляется из описаний в собранной DLL.

## Классы

В extensionL2.cpp можно размещать обычные C++-классы. В примере есть `L2Math`
и `L2Counter`; их статические методы зарегистрированы так:

```cpp
L2_NATIVE(4001, ClampInt,   &L2Math::ClampInt),
L2_NATIVE(4004, SetCounter, &L2Counter::Set),
L2_NATIVE(4005, GetCounter, &L2Counter::Get),
```

Состояние L2Counter принадлежит C++ модулю и доступно через функции:

```uc
class'ExtensionL2API'.static.SetCounter(123);
Log(string(class'ExtensionL2API'.static.GetCounter()));
```

Полноценный новый тип движка, например `UMyActor`/`UObject` с полями, наследованием
и сборкой мусора, требует отдельной регистрации UClass. Шаблон автоматически
регистрирует **функции**, а C++-классы здесь служат их реализацией. Нестатические
методы вызывайте из обычной функции/статической обёртки, управляющей вашим объектом.

## Поддерживаемые сигнатуры

| C++ | UnrealScript | Представление VM |
|---|---|---|
| `std::int32_t` / `int` в Windows x86 | `int` | 4 байта |
| `std::int64_t` | `int64` | high32, low32; преобразует адаптер |
| `std::uint8_t` | `byte` | 1 байт |
| `bool` | `bool` | BOOL 4 байта; преобразует адаптер |
| `float` | `float` | 4 байта |
| `std::wstring` | `string` | FString, память выделяет/освобождает Core |
| `void` как результат | функция без возвращаемого типа | результат не записывается |

До восьми обязательных аргументов по значению. Аргументы вычисляются через
FFrame::Step слева направо, затем потребляется конец списка параметров.
Поддерживаются выражения и вложенные native-вызовы, а не только константы.

Для UObject-параметров, массивов, `out`, ссылок и optional
нужны отдельные ABI-адаптеры; текущие шаблоны такие сигнатуры отклоняют при сборке.
`std::string` нельзя напрямую объявить вместо UnrealScript `string`.
Для строк используйте `std::wstring` по значению. Готовый файловый пример:
[FILE_IO.md](FILE_IO.md).

Обычные C++ исключения пользовательской функции перехватываются адаптером и
переводятся в ошибку движка. Обращение к памяти движка и его API требует отдельно
проверенных типов/адресов. Глобальные и статические инициализаторы DLL не должны
требовать запущенного клиента: генератор UC тоже загружает DLL, но без Core.

## Сборка под VS 2022

Из каталога `rebuild/dll`, в Developer PowerShell for VS 2022:

```powershell
.\build.ps1
```

Скрипт собирает Win32 DLL и инструменты, затем автоматически генерирует UC.
Результаты:

```text
build/Release/ExtensionL2.dll
build/Release/extension_bindings.exe
build/Release/extension_probe.exe
ExtensionL2/Classes/ExtensionL2API.uc
build/bindings.json
```

Вручную:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A Win32
cmake --build build --config Release
cmake --build build --config Release --target generate_native_uc
```

Генератор — x86 EXE, поэтому работает и с 64-битным Python/Windows без попыток
загрузить 32-битную DLL через 64-битный ctypes. Он также выдаёт bindings.json
для проверки индексов и сигнатур в скомпилированном `.u`.

## Подготовка полного примера

```powershell
$ClientSystem = Read-Host 'Полный путь к system целевого клиента HF'
.\prepare_extension.ps1 -ClientCore ..\..\Clear_hf\Core.dll -ClientSystem $ClientSystem
```

Действия скрипта:

1. Генерирует UC из **выбранной ExtensionL2.dll**.
2. Собирает ExtensionL2.u в новом рабочем каталоге.
3. Проверяет все сгенерированные native-декларации по bindings.json.
4. Создаёт копию выбранной оригинальной Core.dll с загрузочным патчем.
5. Кладёт рядом ExtensionL2.dll и упакованный ExtensionL2.u.

Проверки индексов других модулей здесь нет. Перед патчем проверяются обычные
PE-импорты к Core, чтобы не смешать DLL разных клиентов. При регистрации остаются проверки
диапазона, дубликатов в своём списке и текущих слотов Core; их стоимость мала,
и они не требуют чтения защищённых Engine.u/NWindow.u.

Для готовой сборки из dist:

```powershell
$ClientSystem = Read-Host 'Полный путь к system целевого клиента HF'
.\prepare_extension.ps1 -NativeDll .\build\Release\ExtensionL2.dll -ClientCore ..\..\Clear_hf\Core.dll -ClientSystem $ClientSystem
```

Индексы задаются вами в диапазоне 256..4095. В примере заняты 4000..4009.
Сохраняйте номера уже используемых функций: в скомпилированном UC вызов содержит
именно индекс. При добавлении функции достаточно новой строки L2_NATIVE с новым
номером; при изменении сигнатуры пересоберите все вызывающие её пакеты.

## Обновление установленного расширения

- Изменение только тела функции с прежней сигнатурой/индексом: пересобрать DLL
  и заменить ExtensionL2.dll при закрытом клиенте.
- Добавление функции: пересобрать DLL, сгенерировать UC, собрать ExtensionL2.u
  и пакеты с новыми вызовами; заменить эти файлы в клиенте.
- После перехода на новое имя патч Core.dll повторять не требуется, пока имя ExtensionL2.dll
  и экспорт ExtensionL2Attach остаются прежними и версия Core не меняется.

ExtensionL2.u должен быть доступен компилятору вызывающего пакета и клиенту.
Например, добавьте `EditPackages=ExtensionL2` перед `EditPackages=Interface`
и разместите исходники ExtensionL2 рядом с остальными пакетами рабочего каталога.
После переименования пакета пересоберите вызывающие его UC-пакеты.

`ExtensionL2Tests.uc` содержит тестовые вызовы примера. Если удалите или переименуете
примерные функции, обновите/удалите соответствующие тестовые вызовы. Автоматическая
регистрация и генератор от тестового класса не зависят.

## Что проверено

Собраны ExtensionL2.dll, генератор и ExtensionL2.u. Для исходных семи деклараций проверены
вызовы через реальную клиентскую VM, bool/int/float/int64, void и методы без
аргументов, состояние C++ класса, порядок аргументов и вложенные вызовы.
Обновлённый патч Core.dll автоматически регистрирует весь список; отдельные
изменения Core под каждую функцию не требуются.

Готовые файлы проверены MinGW-w64 + Wine x86; сборка в Windows и все реализованные
функции в игре также проверены. Для Scryde рабочая интеграция не получена,
исследования прекращены. Модуль поддерживает два проверенных профиля Core;
патч создаётся из оригинала конкретного клиента. Подробности Clear HF —
[CLEAR_HF_FIX.md](CLEAR_HF_FIX.md).
