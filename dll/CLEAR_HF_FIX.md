# Исправление Core для Clear HF / HF5-REVISION-268-EN

`<HF_CLIENT>` — корень целевого клиента HF. В командах PowerShell
`$ClientSystem` задаёт полный путь к его папке `system`.

## Причина ошибки точки входа

В установленном клиенте Engine.dll и l2.exe совпадают с оригиналами Clear_hf.
Но установленная патченная Core.dll была построена на ДРУГОЙ версии Core.

Engine.dll импортирует из Core.dll:

```text
?GetCPUCacheLineSize@L2UserHardWareInformation@@QBEHXZ
```

В прежнем Core экспорт имел суффикс `QAEHXZ`. Дополнительно D3DDrv.dll ожидает
другую сигнатуру SetVGAInfo. Некоторые аппаратные функции этих версий имеют
разные возвращаемые типы. Поэтому исправление состоит в использовании родной
Core, а не в добавлении алиаса к одной отсутствующей функции.

Предыдущий пример был проверен на отдельно предоставленной Core и не подтверждал
совместимость с этим полным комплектом клиента.

## Готовые файлы

Используйте **пару** из:

```text
dll/dist/profiles/Clear_hf/Core.dll
dll/dist/profiles/Clear_hf/ExtensionL2.dll
```

При закрытом клиенте замените ими Core.dll и ExtensionL2.dll в:

```text
<HF_CLIENT>\system
```

Engine.dll, l2.exe и остальные файлы должны оставаться из оригинального Clear_hf.
Имеющийся ExtensionL2.u совместим с этой же таблицей функций 4000..4006.
Копия пакета также приложена в папке профиля.

Для восстановления исходного запуска без расширения верните
`int64_UCC/Clear_hf/Core.dll` в System. Исходники Clear_hf не изменялись.

## Профиль

Оригинальная Core.dll Clear HF:

```text
0677e909b10ec398543dbd04cf4d8714ed97befd23d5f928aef17b1a5d844471
```

Новая патченная копия:

```text
03ed7faa0dfe0853071f6defda191b2eae76961e835c9624be25396a69dbb455
```

Сохраняются все исходные экспорты и байты оригинальных секций. Новый загрузочный
код находится в дополнительных секциях, а собственная реализация функций —
в ExtensionL2.dll. Новый модуль поддерживает и Clear HF, и предыдущий Core-профиль.
Это не делает сами Core.dll взаимозаменяемыми между клиентами.

## Повторное создание патча

Из каталога rebuild/dll:

```powershell
.\build.ps1
$ClientSystem = Read-Host 'Полный путь к system целевого клиента HF'
.\prepare_extension.ps1 -ClientCore ..\..\Clear_hf\Core.dll -ClientSystem $ClientSystem
```

Теперь -ClientCore задаётся явно. Перед подготовкой проверяется соответствие
Core-экспортов PE-импортам клиентского комплекта. Это проверка зависимостей DLL,
а не сканирование native-индексов.

Отдельная проверка:

```powershell
py -3 tools/check_core_dependencies.py $ClientSystem --core dist/profiles/Clear_hf/Core.dll
```

## Выполненные проверки

- С оригинальным и новым патченным Core все Core-импорты 11 клиентских модулей
  разрешаются. Со старой установленной Core обнаружены отсутствующие экспорты
   Engine.dll и D3DDrv.dll, включая процедуру из сообщения об ошибке.
- В тестовом хосте действительно загружены новая Core и оригинальный Engine.dll
  Clear_hf; LoadLibrary завершился успешно.
- Ручная и автоматическая регистрация ExtensionL2 прошли на новом Core-профиле.
- Все проверки VM выполнены, включая аргументы/результаты, INT64, вложенные
  вызовы и фактический bytecode от UCC.
- Исходные файлы Clear_hf и установленного System при исследовании не изменялись.

Исполнение VM и загрузка DLL проверены в Wine x86.
Дополнительно подтверждены сборка в Windows, успешный запуск клиента с парой DLL
в `<HF_CLIENT>\system` и работа всех реализованных
native-функций непосредственно в игре.

При запуске отдельной папки `system` неполной тестовой копии HF лог показывал
отсутствующие текстуры `Aden_broken_Castle_T.Aden_BC_ach` и `Default.Disable`
перед сбоем `UOrcMove::CalculateCRC32`. Ресурсы полного клиента лежали в другом
каталоге. После перехода к полному клиенту подтверждён успешный запуск.
